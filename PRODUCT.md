# Продукт

## Назначение

Приложение для параллельного учёта зарплаты и продаж магазина. Часть учёта — собственную логику смен, расчёт зарплаты и продаж — невозможно вести в 1С. Приложение предназначено для этой части.

Приложение намеренно простое. Оно не повторяет поля и логику 1С и хранит только то, что нужно для точного и воспроизводимого расчёта.

Архитектура описана в каталоге [docs](docs), её оглавление — в [ARCHITECTURE.md](ARCHITECTURE.md). Формулы и запреты учёта описаны в разделе [«Правила учёта»](docs/accounting-rules.md).

## Принципы продукта

- **Данные первичны, расчёт вторичен.** В базе хранятся исходные факты: справочники и документы. Любой расчёт (зарплата, продажи) можно в любой момент повторить по этим фактам и получить тот же результат.
- **Правила расчёта меняются.** Схема расчёта зарплаты сложная и будет меняться, поэтому она не закладывается в структуру данных, а описывается в конфигурации и собственных действиях.
- **Объекты добавляются по ходу работы.** Конкретные справочники, документы и регистры появляются постепенно. Добавить объект — значит описать его в одном файле конфигурации.
- **Быстрый ввод с клавиатуры.** Формы заполняются без мыши: Enter и Tab для перехода между полями, сочетания клавиш для записи и проведения.
- **Прозрачность.** По каждому объекту видно, кто, когда и что в нём изменил, а также какое исходное действие пользователя к этому привело.

## Пользователи

Одновременно работают не больше двух человек, один из них только читает данные. Пользователь входит в приложение по PIN: у каждого пользователя свой PIN, по нему приложение определяет, кто вошёл. Доступ определяется ролями (RBAC). Роли и их права описываются в конфигурации; конкретный набор ролей появится вместе с прикладными объектами.

## Возможности первой версии

### Платформа учёта

- Справочники: создание, изменение, пометка удаления, списки с отбором и сортировкой. Запись определяется GUID и показывается по наименованию; стандартного поля «Код» нет.
- Документы: то же, плюс проведение и отмена проведения.
- Регистры: движения, которые документы записывают при проведении. Используются там, где нужны остатки или обороты.
- Ссылки на записи: в таблицах и полях показывается представление объекта, из него можно открыть карточку. Поле может ссылаться на заданный справочник или документ либо принимать ссылку на любой объект этих видов. Внешние связи используют тот же механизм. Справочник может показываться представлением связанной записи: сотрудник называется ФИО физического лица, и ФИО хранится в одном месте.
- Регистры сведений: текущие значения по уникальному набору измерений без привязки к документу. Например, связь записи приложения с объектом внешней системы. Сведения читаются, заменяются и удаляются через единый API, с проверкой прав и записью в журнал.
- Собственные действия объектов для операций, которые не сводятся к записи, например расчётов.
- Пометка удаления справочников и документов; физическое удаление независимых сведений по ключу.
- Единый API для внесения и чтения данных. Им пользуется интерфейс приложения; через него же данные можно вносить из других программ.
- Собственные экраны конфигурации, например рабочие места: экран открывается во вкладке и стоит в меню подсистемы рядом со справочниками и документами. Доступ к экрану задаётся ролью.
- Собственные блоки конфигурации на главном экране и над стандартными списками: блоки располагаются в группах по горизонтали или вертикали и показываются с учётом доступа к данным. Блок над списком может скрыть кнопку создания и действия меню строки.

### Импорт, физические лица, сотрудники и номенклатура

Справочник «Физические лица» хранит ФИО, пол, дату рождения и номер телефона. Пол выбирается из значений «Мужской» и «Женский»; незаполненное значение допускается.

Справочник «Сотрудники» хранит тех, кого можно указать в составе смены. Сотрудник ссылается на физическое лицо и показывается его ФИО; своё у сотрудника только короткое обозначение — код, который вводит пользователь. На одно физическое лицо заводится один сотрудник: вторую запись приложение отклоняет, даже если первая помечена на удаление. Сотрудник отделён от физического лица, потому что повторный импорт из 1С записывает физическое лицо целиком, а ставка, должность и дата приёма позже будут храниться у сотрудника.

Справочник «Номенклатура» хранит названия позиций и заполняется импортом из 1С. Штрихкодов в нём нет: в выгрузке справочников 1С они отсутствуют.

Отдельный инструмент для Windows импортирует выбранный справочник из универсальной XML-выгрузки 1С. Соответствие полей задаётся файлом JSON. Повторная загрузка обновляет те же записи по внешним связям, ошибка отменяет текущую порцию. Инструмент использует обычный вход по PIN и права приложения.

### Смены

Документ «Смена» хранит дату открытия, дату закрытия и состав сотрудников. У смены два состояния: открыта и закрыта.

- Смену открывают записью нового документа: дата открытия подставляется текущая, состав набирается нажатием на ФИО сотрудников. Пока смена открыта, дату и состав можно менять. Смена без сотрудников и смена с повтором сотрудника не записываются.
- Смену закрывают действием «Закрыть смену» с датой закрытия, по умолчанию текущей. Закрытие проводит смену. Закрытую смену нельзя изменить и открыть заново.
- Открытой может быть только одна смена. Интервалы смен не пересекаются; следующая смена может начаться в момент закрытия предыдущей.
- Смену задним числом вводят теми же двумя шагами с прошлыми датами, когда открытой смены нет.
- Пометки удаления у смен нет: ошибочно открытую смену закрывают.

На главном экране и над списком смен стоит блок «Текущая смена». Он показывает открытую смену: ссылку на её форму, дату открытия и число сотрудников. Если открытой смены нет, блок сообщает об этом. В блоке две кнопки, из которых доступна одна: «Открыть» показывает форму новой смены в окне, когда открытой смены нет, а «Закрыть» выполняет закрытие открытой смены с окном даты. Недоступная кнопка остаётся на месте неактивной. Кнопки, на действие которой у пользователя нет права, в блоке нет, а без права чтения смен нет и самого блока. Кнопки «Создать» в списке смен нет: смену открывают кнопкой блока.

### Продажи, рассрочки, отвесы и возвраты

Продавец отражает в приложении четыре документа. Каждый относится к смене; в новом документе смена заполнена открытой сменой. Смена в поле выбора названа номером, датой открытия и ФИО сотрудников состава. Формулы и запреты записаны в разделе [«Правила учёта»](docs/accounting-rules.md).

- Товары во всех четырёх документах вводятся одинаково: название текстом, стоимость, скидка в процентах и вычисляемый итог. Скидку вводят числом или выбирают из справочника «Скидки»; в строку попадает число, а не ссылка на скидку. Списки документов показывают товары раскрытием строки.
- «Продажа» хранит товары и их сумму.
- «Рассрочка» хранит тип («Банковская» или «Собственная»), физическое лицо, товары, взносы, сумму и остаток. Взнос добавляет кнопка «Внести» с датой, суммой и получателем; строки взносов на форме не редактируются. Кнопка «Закрыть» закрывает рассрочку с нулевым остатком. Закрытая рассрочка открывается только для просмотра.
- «Отвес» хранит физическое лицо, товары и остаток. У каждого товара есть состояние: «В отвесе», «Продано» или «Вывешено». «Вывешено» продавец выбирает в строке сам. Кнопка «Продажа» показывает товары в отвесе; по выбранным она создаёт непроведённую продажу с копиями товаров, отмечает строки проданными со ссылкой на неё и открывает форму продажи. Такая продажа показывает отвес, из которого оформлена. Отвес закрыт, когда товаров в отвесе не осталось.
- «Возврат» хранит продажи-основания и возвращаемые товары. Под основаниями показаны товары каждой выбранной продажи; нажатие на товар добавляет его копию в возврат. При проведении приложение проверяет предел суммы по каждой продаже и в отказе называет продажу и сумму, которую ещё можно вернуть.

Страница «Рабочее место продавца» в подсистеме «Продажи» собирает работу с документами на одном экране. В шапке четыре столбца: «Продажа», «Отвес», «Возврат», «Рассрочка». В каждом кнопка создания документа и кнопка перехода к его списку; кнопки создания нет у пользователя без права записи документа. Под шапкой стоят блоки «Рассрочки» и «Отвесы». Это первая редакция экрана: по ней уточняются требования.

Блоки «Рассрочки» и «Отвесы» стоят также на главном экране. Блок перечисляет незакрытые документы: ФИО физического лица и остаток. Нажатие на строку открывает документ. Без права чтения документа блока нет.

### Права

- Роли с правами на чтение и запись каждого объекта, на проведение документов и на собственные действия.
- Интерфейс показывает только доступные пользователю объекты и действия.

### Ограничения записи

- Закрытие периода: после расчёта зарплаты пользователь создаёт и проводит документ «Закрытие периода» с датой «Закрыто по». Эта дата входит в закрытый период и может предшествовать дате оформления документа. Подключённые к правилу документы за закрытый период после этого изменить нельзя.
- Для документов с правилом запрета удаления проведённый документ сначала нужно снять с проведения; напрямую пометить его на удаление нельзя.
- Другие запреты описываются в конфигурации тем же механизмом.

### Журнал действий

- Каждое изменяющее действие фиксируется одной записью: кто, когда, над каким объектом, какие поля изменились (было → стало).
- Действия, запущенные другими действиями, связаны в цепочку с исходным действием и пользователем.
- Можно посмотреть историю объекта, действия пользователя и цепочку одного запроса.

### Интерфейс

- Веб-интерфейс строится по описаниям с сервера, поэтому список и форма нового объекта конфигурации появляются без отдельной разработки.
- Внешний вид форм можно настроить в описании объекта. На форму можно поставить собственный блок, например итог по строкам, или заменить поле ввода собственным.
- Слева показаны подсистемы, как в 1С. Подсистема открывает окно с группами объектов; у каждого объекта стоит иконка его вида. Состав подсистем и групп задаётся в конфигурации, один объект можно показать в нескольких группах.
- Открытые списки и формы остаются вкладками, как окна в 1С. Вкладка сохраняет своё состояние, пока открыта: несохранённые значения формы, отбор, сортировку и страницу списка. Повторное открытие того же списка или той же записи возвращает к её вкладке. Форма с несохранёнными изменениями перед закрытием спрашивает подтверждение.
- Запись простого справочника создаётся в окне поверх списка, без отдельной вкладки: так настроены «Номенклатура», «Физические лица» и «Сотрудники». Режим создания задаётся в конфигурации объекта.
- После входа открыт главный экран с блоками конфигурации: текущей сменой, незакрытыми рассрочками и отвесами. Его вкладка стоит первой и не закрывается.
- В списках можно искать по части строки, числа, суммы или даты в том виде, который показан на экране. Например, сумма 1 234,50 находится по «34,5» или «1 234», а дата 29.09.2026 по «09.2026».
- У регистров сведений есть список с отбором и сортировкой; формы редактирования для них нет.
- Формы и табличные части заполняются с клавиатуры: Enter переводит фокус вперёд, Shift+Enter назад. В конце таблицы Enter добавляет строку. Ctrl+S записывает форму, Ctrl+Enter проводит документ и закрывает форму после успеха, Esc закрывает её вкладку с подтверждением несохранённых изменений.

Над каждым списком есть отдельное поле «Поиск»: фрагмент ищется во всех видимых колонках, включая названия связанных записей и документов-регистраторов. Поиск действует вместе с отбором; его очистка сохраняет условия отбора. Ввод применяется с небольшой задержкой и возвращает список на первую страницу. Недоступные пользователю названия связанных записей не участвуют в поиске.

## Не входит в первую версию

- Отчёты, печатные формы, экспорт.
- Конкретные правила расчёта зарплаты: они будут описаны в разделе [«Правила учёта»](docs/accounting-rules.md), где уже записаны правила продаж, рассрочек, отвесов и возвратов.
- Автоматическое резервное копирование. Пока резервная копия — это копия файла базы.

## Поставка

Приложение поставляется одним исполняемым файлом. Рядом с ним лежат файл базы данных и файл настроек. Интерфейс открывается в браузере.

## Термины

| Термин | Значение |
|---|---|
| Справочник | Список условно-постоянных объектов: сотрудники, номенклатура, точки |
| Документ | Запись о событии с датой и номером: смена, выплата, закрытие периода |
| Табличная часть | Список строк внутри документа или справочника, например состав смены |
| Проведение | Отражение документа в учёте: запись движений в регистры |
| Регистр | Таблица движений для расчёта остатков и оборотов |
| Регистр сведений | Текущие значения, в которых набор измерений однозначно определяет запись |
| Пометка удаления | Признак того, что объект больше не используется; сам объект остаётся в базе |
| Подсистема | Раздел интерфейса: группы ссылок на объекты, собранные по смыслу |
| Конфигурация | Набор прикладных объектов, ролей и подсистем конкретного магазина |
| Платформа | Общие механизмы: хранение, API, права, журнал, интерфейс |
