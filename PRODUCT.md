# Продукт

## Назначение

Приложение для параллельного учёта зарплаты и продаж магазина. Часть учёта — собственную логику смен, расчёт зарплаты и продаж — невозможно вести в 1С. Приложение предназначено для этой части.

Приложение намеренно простое. Оно не повторяет поля и логику 1С и хранит только то, что нужно для точного и воспроизводимого расчёта.

Архитектура описана в [ARCHITECTURE.md](ARCHITECTURE.md).

## Принципы продукта

- **Данные первичны, расчёт вторичен.** В базе хранятся исходные факты: справочники и документы. Любой расчёт (зарплата, продажи) можно в любой момент повторить по этим фактам и получить тот же результат.
- **Правила расчёта меняются.** Схема расчёта зарплаты сложная и будет меняться, поэтому она не закладывается в структуру данных, а описывается в конфигурации и собственных действиях.
- **Объекты добавляются по ходу работы.** Конкретные справочники, документы и регистры появляются постепенно. Добавить объект — значит описать его в одном файле конфигурации.
- **Быстрый ввод с клавиатуры.** Формы заполняются без мыши: Enter и Tab для перехода между полями, сочетания клавиш для записи и проведения.
- **Прозрачность.** По каждому объекту видно, кто, когда и что в нём изменил, а также какое исходное действие пользователя к этому привело.

## Пользователи

Одновременно работают не больше двух человек, один из них только читает данные. Пользователь входит в приложение по PIN: у каждого пользователя свой PIN, по нему приложение определяет, кто вошёл. Доступ определяется ролями (RBAC). Роли и их права описываются в конфигурации; конкретный набор ролей появится вместе с прикладными объектами.

## Возможности первой версии

### Платформа учёта

- Справочники: создание, изменение, пометка удаления, списки с отбором и сортировкой. Запись определяется GUID и показывается по наименованию; стандартного поля «Код» нет.
- Документы: то же, плюс проведение и отмена проведения.
- Регистры: движения, которые документы записывают при проведении. Используются там, где нужны остатки или обороты.
- Ссылки на записи: в таблицах и полях показывается представление объекта, из него можно открыть карточку. Поле может ссылаться на заданный справочник или документ либо принимать ссылку на любой объект этих видов. Внешние связи используют тот же механизм.
- Регистры сведений: текущие значения по уникальному набору измерений без привязки к документу. Например, связь записи приложения с объектом внешней системы. Сведения читаются, заменяются и удаляются через единый API, с проверкой прав и записью в журнал.
- Собственные действия объектов для операций, которые не сводятся к записи, например расчётов.
- Пометка удаления справочников и документов; физическое удаление независимых сведений по ключу.
- Единый API для внесения и чтения данных. Им пользуется интерфейс приложения; через него же данные можно вносить из других программ.

### Импорт и физические лица

Справочник «Физические лица» хранит ФИО, пол, дату рождения и номер телефона. Пол выбирается из значений «Мужской» и «Женский»; незаполненное значение допускается.

Отдельный инструмент для Windows импортирует выбранный справочник из универсальной XML-выгрузки 1С. Соответствие полей задаётся файлом JSON. Повторная загрузка обновляет те же записи по внешним связям, ошибка отменяет текущую порцию. Инструмент использует обычный вход по PIN и права приложения.

### Права

- Роли с правами на чтение и запись каждого объекта, на проведение документов и на собственные действия.
- Интерфейс показывает только доступные пользователю объекты и действия.

### Ограничения записи

- Закрытие периода: после расчёта зарплаты пользователь создаёт и проводит документ «Закрытие периода» с датой «Закрыто по». Эта дата входит в закрытый период и может предшествовать дате оформления документа. Подключённые к правилу документы за закрытый период после этого изменить нельзя.
- Для документов с правилом запрета удаления проведённый документ сначала нужно снять с проведения; напрямую пометить его на удаление нельзя.
- Другие запреты описываются в конфигурации тем же механизмом.

### Журнал действий

- Каждое изменяющее действие фиксируется одной записью: кто, когда, над каким объектом, какие поля изменились (было → стало).
- Действия, запущенные другими действиями, связаны в цепочку с исходным действием и пользователем.
- Можно посмотреть историю объекта, действия пользователя и цепочку одного запроса.

### Интерфейс

- Веб-интерфейс строится по описаниям с сервера, поэтому список и форма нового объекта конфигурации появляются без отдельной разработки.
- Внешний вид форм можно настроить в описании объекта.
- В списках можно искать по части строки, числа, суммы или даты в том виде, который показан на экране. Например, сумма 1 234,50 находится по «34,5» или «1 234», а дата 29.09.2026 по «09.2026».
- Регистры сведений появляются в меню со списком, отбором и сортировкой; формы редактирования для них нет.
- Формы и табличные части заполняются с клавиатуры: Enter переводит фокус вперёд, Shift+Enter назад. В конце таблицы Enter добавляет строку. Ctrl+S записывает форму, Ctrl+Enter проводит документ и закрывает форму после успеха, Esc закрывает её с подтверждением несохранённых изменений.

Над каждым списком есть отдельное поле «Поиск»: фрагмент ищется во всех видимых колонках, включая названия связанных записей и документов-регистраторов. Поиск действует вместе с отбором; его очистка сохраняет условия отбора. Ввод применяется с небольшой задержкой и возвращает список на первую страницу. Недоступные пользователю названия связанных записей не участвуют в поиске.

## Не входит в первую версию

- Отчёты, печатные формы, экспорт.
- Конкретные правила расчёта зарплаты: они будут описаны отдельно.
- Автоматическое резервное копирование. Пока резервная копия — это копия файла базы.

## Поставка

Приложение поставляется одним исполняемым файлом. Рядом с ним лежат файл базы данных и файл настроек. Интерфейс открывается в браузере.

## Термины

| Термин | Значение |
|---|---|
| Справочник | Список условно-постоянных объектов: сотрудники, номенклатура, точки |
| Документ | Запись о событии с датой и номером: смена, выплата, закрытие периода |
| Табличная часть | Список строк внутри документа или справочника, например состав смены |
| Проведение | Отражение документа в учёте: запись движений в регистры |
| Регистр | Таблица движений для расчёта остатков и оборотов |
| Регистр сведений | Текущие значения, в которых набор измерений однозначно определяет запись |
| Пометка удаления | Признак того, что объект больше не используется; сам объект остаётся в базе |
| Конфигурация | Набор прикладных объектов и ролей конкретного магазина |
| Платформа | Общие механизмы: хранение, API, права, журнал, интерфейс |
