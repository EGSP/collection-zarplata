# Импорт из 1С

Руководство предназначено для оператора, который переносит справочник из универсальной XML-выгрузки 1С в приложение. Инструмент читает выбранный вид объектов и отправляет записи через API от имени пользователя. Один запуск загружает один справочник; для другого справочника нужен отдельный запуск с другим файлом сопоставления.

Для загрузки используйте раздел [«Сборка и запуск»](#сборка-и-запуск), для подготовки собственного сопоставления: [«Сопоставление полей»](#сопоставление-полей). Параметры собраны в [справочнике CLI](#справочник-cli).

## Сборка и запуск

### Что подготовить

Нужны запущенный сервер приложения, универсальная XML-выгрузка 1С в UTF-8 и файл сопоставления для целевого справочника. Пользователь, чей PIN будет введён, должен иметь право записи целевого справочника и права чтения и записи регистра «Внешние связи». Сервер применяет обычные ограничения полей и политики записи. Успешного входа самого по себе недостаточно для импорта.

Перед загрузкой в рабочую базу сохраните её резервную копию и проверьте выбранное сопоставление на отдельной базе. Повторный импорт заменяет пользовательские поля записи: пропущенные необязательные поля очищаются. Он может перезаписать изменения, сделанные в приложении после предыдущей загрузки.

XML содержит персональные данные. Храните его вне репозитория; не добавляйте в git выгрузки и PIN. Файлы сопоставления и JSON Schema не содержат самих записей выгрузки.

### Как собрать инструмент

Для сборки нужен Go версии, указанной в [go.mod](https://github.com/EGSP/collection-zarplata/blob/main/tools/1c-xml-import/go.mod) (сейчас `1.27.0`), и доступ к зависимостям Go. Команды ниже выполняются в PowerShell из корня репозитория:

```powershell
$env:CGO_ENABLED = '0'
go build -C tools/1c-xml-import -trimpath -o collection-xml-import.exe .
```

При успешной сборке команда завершается с кодом `0`. Параметр `-C` меняет рабочий каталог Go, поэтому результат находится в `tools/1c-xml-import/collection-xml-import.exe`, а не в корне репозитория. Этот файл не добавляется в git.

Сборка без cgo даёт исполняемый файл без зависимости от системных библиотек. Для запуска готового файла Go не нужен; для сборки основного приложения Go тоже не требуется. Инструмент использует стандартную библиотеку и `golang.org/x/term` для скрытого ввода PIN. Для сборки Windows-версии на другой платформе задайте `GOOS=windows` и `GOARCH=amd64` в окружении команды сборки.

Для проверки исходников инструмента можно отдельно выполнить:

```powershell
go vet -C tools/1c-xml-import ./...
gofmt -l tools/1c-xml-import
```

Пустой вывод `gofmt -l` означает, что файлы соответствуют стандартному форматированию Go. Эти команды не загружают данные в приложение.

### Как загрузить справочник

1. Выберите [готовое сопоставление](#готовые-сопоставления) или подготовьте своё. Проверьте `sourceObject`, `targetCatalog` и `externalSystem`. Имя внешней системы должно обозначать конкретную базу 1С, а не все базы сразу.
2. Укажите путь к XML и адрес нужного сервера. В примере замените `C:\import\catalogs.xml` своим путём. Порт `3101` подходит, только если приложение действительно запущено на нём.

   ```powershell
   & .\tools\1c-xml-import\collection-xml-import.exe `
     --xml 'C:\import\catalogs.xml' `
     --server http://127.0.0.1:3101 `
     --mapping tools/1c-xml-import/mappings/physical-persons.mapping.json
   ```

3. После приглашения `PIN:` введите PIN пользователя. Символы на экране не отображаются. Для удалённого сервера укажите HTTPS; HTTP разрешён только для `127.0.0.1`, `localhost` и `::1`.
4. Дождитесь завершения. При успехе инструмент выводит строку со счётчиками в формате `Создано: N, обновлено: M` и завершается с кодом `0`; `N` и `M` обозначают фактические числа записей. В PowerShell код доступен в `$LASTEXITCODE`. При ошибке сообщение выводится в поток ошибок, итоговая строка не печатается.
5. Откройте целевой справочник в приложении. Проверьте несколько записей по выгрузке: название и дополнительные поля. Для физических лиц проверьте пол, дату рождения и первый телефон. В регистре «Внешние связи» проверьте выбранное имя системы, вид источника и переход по ссылке к загруженной записи.

Сумма итоговых счётчиков равна числу обработанных записей выбранного вида, без групп справочника. Запись считается обновлённой, если найдена её внешняя связь, даже когда значения полей не изменились. Счётчики не заменяют проверку содержания. Если все найденные объекты оказались группами, загрузка завершится с нулевыми счётчиками; отсутствие выбранного вида объектов вообще считается ошибкой.

Для проверки повторной загрузки на отдельной базе запустите ту же команду ещё раз с тем же `externalSystem` и XML. Уже связанные записи должны попасть в счётчик обновлений; новые записи и внешние связи для них не должны появиться. Такой повтор снова заменяет пользовательские поля.

### Что делать при ошибке

Импорт идёт порциями, по умолчанию по 100 записей. Сервер сохраняет каждую порцию одной транзакцией. Ошибка проверки данных, прав или политики записи отменяет текущую порцию целиком; ранее подтверждённые порции остаются в базе. Ошибка чтения XML или преобразования поля останавливает чтение, и ещё не отправленная порция не сохраняется.

При обрыве соединения или неверном ответе сервера инструмент не может подтвердить, сохранилась ли отправленная порция. У него нет автоматического повтора сетевых ошибок. После проверки причины повторите запуск с начала, сохранив исходные `externalSystem` и `sourceObject`: сервер найдёт внешние связи сохранённых записей и обновит их вместо создания дубликатов.

| Сообщение или ситуация | Действие оператора |
|---|---|
| `Неверный файл сопоставления` или ошибка правила поля | Исправьте JSON и правило по справочнику ниже. Файл проверяется до входа на сервер |
| `Для удалённого сервера требуется HTTPS` | Укажите прямой HTTPS-адрес сервера. Инструмент не следует HTTP-переадресациям |
| `Вход не выполнен` | Проверьте адрес и PIN. Для скрытого ввода запускайте инструмент из терминала |
| `Доступ не обновлён` | Проверьте состояние сервера и пользователя, затем выполните новый запуск с PIN |
| Отказ сервера при импорте | Прочитайте статус и тело ответа в сообщении. Проверьте права записи справочника, чтения и записи внешних связей, ограничения и политики целевого объекта |
| `Внешний объект уже связан с другим справочником` | Проверьте mapping и существующую внешнюю связь. Не меняйте имя внешней системы лишь для обхода ошибки: это создаст другой адрес источника |
| `Нет сопоставления значения` | Добавьте нужное непустое значение в `values` либо исправьте источник; импорт не подбирает значение сам |
| `Объект без Ref`, ошибка чтения XML или `XML оборван внутри объекта` | Проверьте полноту выгрузки и её формат; при необходимости получите XML заново |
| `В XML нет объектов …` | Сверьте `sourceObject` с именами элементов выгрузки и выберите нужный XML |
| Неверное число результатов или неизвестный результат импорта | Проверьте совместимость сервера и инструмента; отправленная порция могла сохраниться |

При ответе `401` на импорт инструмент один раз обновляет доступ через cookie и повторяет эту порцию. Другие ошибки останавливают запуск. Каждый HTTP-запрос ограничен временем ожидания 120 секунд. При большом времени обработки можно уменьшить `--batch-size`; уже сохранённые порции это не отменяет.

## Справочник CLI

```text
collection-xml-import --xml <файл> --mapping <файл> --server <адрес> [--batch-size <число>]
```

| Параметр | Обязательность и значение |
|---|---|
| `--xml` | Обязателен. Путь к универсальной XML-выгрузке 1С в UTF-8 |
| `--mapping` | Обязателен. Путь к JSON-файлу сопоставления |
| `--server` | Обязателен. Базовый адрес сервера без `/api`; конечный `/` допускается. Для удалённого сервера нужен HTTPS |
| `--batch-size` | Необязателен. Целое число от 1 до 500, по умолчанию 100 |
| `--help`, `-h` | Показ справки; импорт не запускается |

Пути разрешаются относительно каталога, из которого запускается исполняемый файл. Позиционные аргументы не принимаются. Для параметров также допустима запись `--xml=<файл>`. Код завершения `0` означает успех или показ справки, `1` означает ошибку выполнения, `2` означает ошибку аргументов. Выход за диапазон размера порции проверяется при выполнении и даёт код `1`.

PIN не принимается в аргументах. Если переменная окружения `COLLECTION_IMPORT_PIN` существует, инструмент использует её значение вместо запроса в терминале, в том числе если оно пустое. Для автоматизированного запуска передавайте PIN через окружение процесса и не записывайте его в команду, историю терминала или файл репозитория. После такого запуска удалите переменную из окружения, если она больше не нужна.

Режима предварительного просмотра и продолжения с номера записи нет. Проверку без изменения рабочей базы выполняйте на отдельном сервере или базе.

## Сопоставление полей

Файл `*.mapping.json` описывает перенос одного вида объектов и называется файлом сопоставления (mapping-файлом). [mapping.schema.json](https://github.com/EGSP/collection-zarplata/blob/main/tools/1c-xml-import/mapping.schema.json) является JSON Schema для проверки структуры и подсказок редактора. Передавайте в `--mapping` конкретное сопоставление, а не схему. Схема XML выгрузки и JSON Schema сопоставления описывают разные данные.

### Готовые сопоставления

Пути в таблице указаны относительно `tools/1c-xml-import/`.

| Файл | Источник и целевой справочник | Значения полей |
|---|---|---|
| [mappings/physical-persons.mapping.json](https://github.com/EGSP/collection-zarplata/blob/main/tools/1c-xml-import/mappings/physical-persons.mapping.json) | `CatalogObject.ФизическиеЛица` → `physicalPersons`, система `1c-col3` | ФИО из `Description`, пол из `Пол`, дата рождения из `ДатаРождения`, первый телефон из контактной информации |
| [mappings/nomenclature.mapping.json](https://github.com/EGSP/collection-zarplata/blob/main/tools/1c-xml-import/mappings/nomenclature.mapping.json) | `CatalogObject.Номенклатура` → `nomenclature`, система `1c-col3` | Название из `Description`; штрихкоды не загружаются |
| [mappings/sample.mapping.json](https://github.com/EGSP/collection-zarplata/blob/main/tools/1c-xml-import/mappings/sample.mapping.json) | `CatalogObject.ФизическиеЛица` → `sample`, система `1c-sample-check` | Название из `Description`, обязательное `active` равно `true`, табличная часть `lines` равна `[]` |

Пробное сопоставление использует своё имя системы, чтобы его внешние связи не пересекались со связями физических лиц. Не используйте `1c-col3` для разных баз 1С: одинаковые идентификаторы источника начнут обновлять одни и те же записи приложения.

В сопоставлении физических лиц при нескольких телефонах выбирается первый по порядку выгрузки. Его формат сохраняется, кроме удаления пробелов по краям. Отсутствующий телефон, незаданный пол и пустая дата рождения остаются `null`. Сопоставление номенклатуры переносит только название: выгрузка справочников, для которой оно подготовлено, не содержит штрихкодов.

### Как подготовить своё сопоставление

1. Скопируйте ближайший готовый mapping-файл. Если файл будет лежать в другом каталоге, исправьте относительный путь `$schema` для подсказок редактора.
2. Укажите имя элемента XML в `sourceObject`, имя существующего справочника приложения в `targetCatalog` и устойчивое имя исходной базы в `externalSystem`.
3. В `fields` задайте каждое пользовательское поле и табличную часть, которые должны сохраниться. Ключи являются именами полей API, а не их подписями на форме. Не задавайте служебные поля, например `guid`.
4. Проверьте файл по JSON Schema в редакторе. Затем выполните загрузку на отдельной базе и проверьте результат по инструкции выше. Проверка схемы не подтверждает наличие полей в справочнике или правильность путей XML; это выясняется при обработке и записи.

### Формат mapping-файла

Корень является JSON-объектом. Свойства `sourceObject`, `targetCatalog`, `externalSystem` и непустой `fields` обязательны. Неизвестные свойства корня и правил полей, неверный JSON и данные после корневого объекта отклоняются до входа на сервер. Инструмент проверяет формат самостоятельно; файл по пути `$schema` при запуске не читает.

| Свойство корня | Контракт |
|---|---|
| `$schema` | Необязательная строка с адресом JSON Schema для редактора |
| `sourceObject` | Полное локальное имя элемента XML с префиксом `CatalogObject.`, например `CatalogObject.ФизическиеЛица`. JSON Schema ограничивает длину 200 символами |
| `targetCatalog` | Непустое имя справочника приложения. JSON Schema требует латинское имя по шаблону `^[a-z][a-zA-Z0-9]*$` |
| `externalSystem` | Непустое имя конкретной исходной базы. Ограничение схемы и регистра внешних связей: до 100 символов |
| `fields` | Непустой объект: имя поля или табличной части приложения → правило получения значения |

Каждое правило содержит ровно одно из `path` и `constant`. Настройки `rowPath`, `whereField`, `whereValue` задаются только вместе. Константа не сочетается с выбором строки, `values` или включённым `dateOnly`.

| Свойство правила | Контракт |
|---|---|
| `path` | Непустой путь через `/` относительно объекта XML, либо выбранной строки табличной части. Пустые части пути запрещены. На каждом шаге берётся первый дочерний элемент с указанным именем; атрибуты и XPath не поддерживаются |
| `constant` | Постоянное JSON-значение вместо чтения XML: строка, число, логическое значение, массив или объект. Допустимость значения для целевого поля проверяет сервер |
| `rowPath` | Путь к строкам табличной части, например `КонтактнаяИнформация/Row`; должен включать таблицу и имя строки через `/` |
| `whereField` | Путь к полю выбранной строки, по которому она сравнивается |
| `whereValue` | Строковое значение для точного сравнения. Выбирается первая подходящая строка; пробелы значения при сравнении не удаляются |
| `dateOnly` | Необязательное логическое значение, по умолчанию `false`. При `true` возвращаются первые десять символов текста даты; значение с префиксом `0001-01-01` становится `null`. Короткое значение отклоняется; правильность календарной даты проверяет сервер |
| `values` | Объект явного сопоставления текста XML со значением приложения. JSON Schema допускает строку или `null` в качестве результата. Неизвестное непустое значение останавливает импорт |

JSON Schema допускает `constant: null`, но текущий инструмент отклоняет такое правило как не содержащее ни `path`, ни `constant`. Для пустого значения используйте чтение отсутствующего или пустого элемента через `path`; не рассчитывайте на константу `null`.

Если выбранная строка, элемент или его текст отсутствует либо текст после удаления пробелов по краям пуст, результат равен `null`. Пустое значение не ищется в `values`. При наличии `values` непустой текст сопоставляется по этой таблице; обрезка даты для сопоставленного результата не выполняется. Без `values` текст возвращается строкой, без автоматического преобразования в число или логическое значение.

### Внешние связи и границы переноса

Идентификатор источника читается из `Ref`, а сервер назначает собственный `guid`. Внешняя связь определяется тройкой `externalSystem`, `sourceObject`, `Ref`. Если такая связь есть, импорт обновляет связанную запись; если нет, создаёт запись и связь. По названию запись не ищется. Уже существующая запись без внешней связи может получить дубликат при первой загрузке.

Группы с `IsFolder=true` пропускаются. Иерархия справочника не восстанавливается. Пометка удаления 1С не переносится: запись с такой пометкой всё равно загружается, а решение об удалении принимает пользователь. Пустые значения полей отправляются как `null`; поля, которых нет в `fields`, сервер обрабатывает по правилам полной записи, а не частичного обновления.

XML читается потоком: в памяти находятся выбранный объект и текущая порция, а не вся выгрузка. Формат действия API и транзакционные гарантии описаны в [разделе об импорте](https://github.com/EGSP/collection-zarplata/blob/main/docs/1c-xml-import.md). Реализация чтения и преобразования находится в [source.go](https://github.com/EGSP/collection-zarplata/blob/main/tools/1c-xml-import/source.go) и [mapping.go](https://github.com/EGSP/collection-zarplata/blob/main/tools/1c-xml-import/mapping.go); параметры и сетевое поведение: в [main.go](https://github.com/EGSP/collection-zarplata/blob/main/tools/1c-xml-import/main.go) и [server.go](https://github.com/EGSP/collection-zarplata/blob/main/tools/1c-xml-import/server.go).
