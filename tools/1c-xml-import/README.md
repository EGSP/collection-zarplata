# Импорт из 1С

Инструмент читает универсальную XML-выгрузку 1С и загружает выбранный справочник через API приложения. Файлы выгрузки содержат персональные данные и не добавляются в репозиторий.

## Сборка и запуск

Для сборки нужен Rust с инструментами сборки Windows:

```powershell
cargo build --release --locked --manifest-path tools/1c-xml-import/Cargo.toml
cargo fmt --check --manifest-path tools/1c-xml-import/Cargo.toml
cargo clippy --release --locked --manifest-path tools/1c-xml-import/Cargo.toml -- -D warnings
```

Готовый `target/release/collection-xml-import.exe` запускается без установленного Rust. Скопируйте его вместе с JSON-файлами сопоставления и схемой. Сборка приложения Rust не требует.

Из корня репозитория:

```powershell
tools/1c-xml-import/target/release/collection-xml-import.exe `
  --xml 'C:\workroot\Разработка\Polygon\collection\col3\25.09.2026_Все справочники.xml' `
  --server http://127.0.0.1:3101 `
  --mapping tools/1c-xml-import/mappings/physical-persons.mapping.json
```

PIN вводится без отображения. Для автоматизированного запуска можно передать его через переменную окружения `COLLECTION_IMPORT_PIN`. PIN не принимается в аргументах. Для удалённого сервера требуется HTTPS. На сервере пользователь должен иметь права чтения и записи внешних связей и право записи целевого справочника.

`--batch-size` задаёт размер порции от 1 до 500 (по умолчанию 100). Ошибка отменяет всю текущую порцию; предыдущие порции уже сохранены. После исправления повторите запуск с начала: внешние связи позволят обновить прежние записи без дубликатов. Итог показывает число созданных и обновлённых записей.

## Сопоставление полей

Файл `*.mapping.json` является описанием сопоставления полей (mapping-файлом). `mapping.schema.json` является JSON Schema: она описывает структуру mapping-файла для проверки и подсказок редактора. Это разные виды файлов.

`sourceObject` задаёт полное имя элемента XML, например `CatalogObject.ФизическиеЛица`; `targetCatalog` задаёт имя справочника приложения, `externalSystem` обозначает конкретную исходную базу. Не используйте одно имя системы для разных баз 1С с разными записями.

`fields` сопоставляет имена полей приложения правилам чтения:

| Свойство | Назначение |
|---|---|
| `path` | Путь через `/` относительно объекта XML или выбранной строки |
| `constant` | Постоянное JSON-значение вместо чтения XML |
| `rowPath` | Путь к строкам табличной части, например `КонтактнаяИнформация/Row` |
| `whereField`, `whereValue` | Выбор первой строки с указанным значением поля |
| `dateOnly` | Первые десять символов даты; пустая дата 1С `0001-01-01` становится `null` |
| `values` | Явное сопоставление значений; неизвестное непустое значение останавливает импорт |

Пустой или отсутствующий элемент становится `null`. Группы справочника (`IsFolder=true`) пропускаются. Идентификатор источника читается из `Ref` и хранится во внешней связи, собственный guid назначает сервер. Пометка удаления источника не переносится: инструмент загружает записи, а решение об их удалении остаётся пользователю.

В примере физических лиц ФИО берётся из `Description`, пол из `Пол`, дата рождения из `ДатаРождения`, телефон из `Представление` первой строки контактной информации с типом `Телефон`. При нескольких телефонах выбирается первый по порядку выгрузки. Телефон сохраняется строкой без изменения формата. Незаданные пол и дата рождения остаются пустыми.

`mappings/sample.mapping.json` загружает тот же источник в пробный справочник и задаёт обязательные пробные поля константами. Для независимой проверки у него своё имя внешней системы.
