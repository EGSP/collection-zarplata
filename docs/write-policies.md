# Политики записи

Прикладные ограничения задаёт конфигурация через `.policy(...)` в описании объекта. У политики есть необязательные обработчики `save`, `post`, `unpost`, `markDeleted`, `unmarkDeleted` и `delete`: отсутствие обработчика не ограничивает соответствующее действие. Проверка `save` получает существующую запись (`null` у новой) и предлагаемую; проверки проведения получают существующий документ, а проверки пометки и физического удаления получают существующую запись. Для каждого изменяющего действия диспетчер строит команду с аргументами политик и эффектом выполнения. Общий конвейер читает запись, строит команду без изменяющих запросов, вызывает все применимые политики, исполняет команду и записывает результат в журнал. Только журнал после выполнения сравнивает исходную и полученную записи для списка изменённых полей; политика получает состояния, нужные её действию, до изменения базы. Все шаги идут в одной транзакции. Ошибка политики возвращает 409 с объяснением и откатывает весь пакет операций. Чтение политик не вызывает. Прямое изменение движений недоступно; сохранение и физическое удаление сведений вызывают политики.

Пробный пример закрытия периода состоит из документа «Закрытие периода» и переиспользуемой политики конфигурации. Поле «Закрыто по» содержит календарную дату включительно; дата самого документа показывает, когда закрытие оформили. Политика читает максимальную границу среди проведённых и не помеченных на удаление закрытий. Она подключена к пробному документу по его стандартной дате: при сохранении проверяет прежнюю и предлагаемую даты, при остальных изменениях — дату существующей записи. Если закрытий нет, запись разрешена. Прикладные объекты с другой учётной датой могут использовать тот же механизм с собственным извлекателем дат. Другая политика запрещает помечать проведённый документ на удаление; она подключена к пробному документу и к документу закрытия. Конкретный порядок повторного открытия периода ещё требует решения; пока граница меняется при отмене проведения или изменении документов закрытия.

Собственное действие, вызывающее `save` или `post` через `ActionDispatcher`, проходит те же проверки. В окружении собственных действий, обработчиков проведения и политик `Database` разрешает только чтение; попытка выполнить прямой изменяющий SQL прерывает и откатывает транзакцию. Платформенные шаги проведения продолжают пользоваться полным доступом к базе.
