# Единый эндпоинт

`POST /api/perform` выполняет стандартные действия объектов, собственные действия конфигурации и чтение журнала. Раздел предназначен для разработчика платформы или обработчика конфигурации. Экраны клиента работают с данными через [Web SDK](interface.md#web-sdk).

На странице разделены объяснение устройства и справочник API:

- [Как выполняется запрос](#как-выполняется-запрос): транзакция, проверки и вложенные действия.
- [Документы и проведение](#документы-и-проведение): связь записи документа с движениями.
- [Контракт API](#контракт-api): формат запроса, действия, поиск и ошибки.

## Как выполняется запрос

### Выполнение действия

Nest-контроллер проверяет вход пользователя и передаёт тело запроса диспетчеру вместе с `userGuid`. Диспетчер выполняет одну операцию или последовательность операций пакета в общей транзакции. Транзакция открывается до разбора операций и поиска объектов. Ошибка любой операции откатывает предыдущие изменения пакета, включая журнал.

Для каждой операции диспетчер находит объект в метаданных, проверяет право пользователя на действие и создаёт контекст. Затем проверяет входные данные и выполняет выбранный обработчик. Перед стандартным изменением записи проверяются политики конфигурации. После успешного изменения записывается журнал; транзакция фиксируется только после завершения всего запроса. Подробности описаны в разделах [«Политики записи»](write-policies.md) и [«Журнал действий»](journal.md).

Диспетчер и обработчики выполняются в Effect. Ошибки описаны через `Data.TaggedError`; отдельный фильтр контроллера переводит их в HTTP-ответы. Контроллер не содержит прикладной логики.

### Собственные и вложенные действия

Обработчик собственного действия получает из окружения Effect `ActionContext`, `ActionDispatcher`, `Database` и `Metadata`. База в этом окружении доступна только для чтения. Записи обработчик изменяет вложенными действиями через диспетчер, чтобы изменения прошли проверку прав и политик и попали в журнал.

Вложенное действие получает новый `actionGuid`, наследует `traceGuid` и `userGuid`, а в `parentActionGuid` сохраняет идентификатор вызывающего действия. Оно использует транзакцию внешнего запроса и проверяет права того же пользователя. Ошибка вложенного действия откатывает всю цепочку. Собственное действие оставляет строку журнала, с которой связаны вложенные изменения, даже если само только читает данные.

### Как выполняется поиск

Условия, которые можно выразить в SQL, применяются при чтении базы. Буквальная подстрока проверяется отдельно: SQL `LIKE` трактует `%` и `_` как шаблоны и не обеспечивает нужное сравнение кириллицы без учёта регистра.

Для `contains`, `search` или `presentation` сервер читает кандидатов порциями по 500 строк в порядке сортировки, проверяет оставшиеся условия, считает все совпадения и выбирает страницу. Поэтому `total` отражает весь отбор, а поиск выполняется до разбиения на страницы.

Связанные записи загружаются пакетами по целевым объектам, не более 500 ссылок на пакет; каждая ссылка читается один раз за запрос. Перед чтением целевого объекта сервер проверяет право чтения. Отсутствующие и недоступные записи не дают совпадения. Клиент использует представления выбранной страницы из ответа сервера, поэтому поиск и отображение используют один текст.

## Документы и проведение

### Нумерация

Номер и признак проведения заполняет платформа, во входных данных `save` их нет. Новый документ получает наибольший номер своего вида плюс один, дополненный нулями как минимум до шести знаков: `000001`, `000002`. Номер выдаётся внутри изменяющей транзакции, а они выполняются по очереди, поэтому два документа не получат один номер. Нумерация сквозная, без разбиения по годам и префиксов.

### Проведение

`post` отмечает документ проведённым, удаляет его прежние движения во всех регистрах и записывает строки, которые вернул обработчик проведения. Поэтому повторное проведение не дублирует движения. Очистка затрагивает все регистры: после изменения данных обработчик может перестать писать в один из них.

Строки проверяются по описанию регистра; ошибка возвращает 400 и откатывает проведение вместе с транзакцией. Номера строк сквозные внутри регистра для одного документа. Документ без обработчика тоже можно провести, но движений у него нет.

### Отмена проведения

`unpost` удаляет движения документа и снимает признак проведения.

### Шаги проведения

Проведение, отмена проведения, действия пометки и завершение `save` собраны из общих шагов работы с состоянием документа. Состояние содержит описание объекта и запись с табличными частями. Шаги проверяют пометку удаления, меняют служебные признаки, удаляют и записывают движения, перечитывают запись.

Шаг изменения признака обновляет базу и состояние, поэтому между шагами перечитывание не требуется. При проведении документ читается в начале и повторно после обработчика: обработчик может изменить документ вложенными действиями. Политики проверяются диспетчером до выполнения действия. Журнал описывает действие целиком, а не каждый его шаг.

### Запись проведённого документа

`save` проведённого документа заново записывает его движения, чтобы они соответствовали новым данным. Признак проведения сохраняется.

### Пометка удаления

Платформенное действие при пометке проведённого документа отменяет его проведение, чтобы помеченный документ не влиял на обороты. Политика пробных документов запрещает такую пометку до явной отмены проведения. Снятие пометки документ не проводит. Документ с пометкой удаления провести нельзя, `post` возвращает 400.

## Контракт API

### Запрос и ответ

Маршрут `POST /api/perform` требует входа. Тело содержит одну операцию или непустой массив операций:

```json
{
    "target": { "kind": "catalog", "name": "employees" },
    "action": "save",
    "payload": { "guid": "…", "fields": { "name": "…" } }
}
```

| Свойство | Значение |
|---|---|
| `target.kind` | Вид объекта: `catalog`, `document`, `register`, `informationRegister`; для журнала `platform` |
| `target.name` | Имя объекта из метаданных; для журнала `journal` |
| `action` | Имя стандартного или собственного действия |
| `payload` | Входные данные выбранного действия; можно опустить, если они не требуются |

Успешный ответ имеет статус 200. Одиночная операция возвращает свой результат, пакет возвращает массив результатов в исходном порядке. Пустой пакет даёт 400. Все операции пакета используют одну транзакцию.

Описания объектов и форм клиент получает через `GET /api/metadata`. Маршрут требует входа и возвращает только доступные пользователю объекты, действия и страницы.

### Стандартные действия

| Действие | Справочник | Документ | Регистр движений | Смысл |
|---|:-:|:-:|:-:|---|
| `list` | + | + | + | Список с фильтрами, сортировкой и страницами |
| `get` | + | + | | Один объект со всеми полями и табличными частями |
| `save` | + | + | | Запись объекта: новый без `guid`, существующий с `guid` |
| `markDeleted` | + | + | | Установить пометку удаления |
| `unmarkDeleted` | + | + | | Снять пометку удаления |
| `post` | | + | | Провести документ: записать движения регистров |
| `unpost` | | + | | Отменить проведение: удалить движения |

Регистры движений напрямую не изменяются: их записывают только документы при проведении. Остальные стандартные действия для регистра движений возвращают 404 с объяснением.

Справочники также поддерживают `import`; его контракт описан в разделе [«Импорт из XML 1С»](1c-xml-import.md).

#### Входные данные и результат

`save`: `payload: { "fields": { "name": "…", "active": true, "lines": [] } }` создаёт запись; `guid` в `payload` обновляет существующую. В `fields` передаются все заполняемые пользователем поля и все табличные части. Отсутствующие необязательные поля сохраняются как `null`. Обновление заменяет строки табличных частей и сохраняет пометку удаления.

`get`, `markDeleted`, `unmarkDeleted`: `payload: { "guid": "…" }`. `get` возвращает запись с табличными частями. Действия пометки возвращают обновлённую запись.

`post`, `unpost`: `payload: { "guid": "…" }`, возвращают документ. Описаны в подразделе [«Документы и проведение»](#документы-и-проведение).

#### Вычисляемые поля

Вычисляемые поля шапки и строк перед `save` заменяются серверным результатом формул: сначала строки, затем шапка. После расчёта проверяется полная запись, политики получают уже рассчитанное предлагаемое состояние. Клиент может не передавать вычисляемые поля или передать произвольное значение: оно не сохраняется.

Результат хранится обычным полем и участвует в отборе, сортировке и поиске. Ошибка расчёта возвращает 400 с путём вычисляемого поля. Входные строки собственного действия проходят такой же расчёт и проверку; ошибка ячейки указывает путь вида `payload.lines.0.item`.

#### Представления и табличные части

Ответы `get`, `save`, действий пометки и проведения справочника или документа содержат служебное поле `$presentation`. Тот же текст входит в строки `list`. Он вычисляется при чтении по описанию представления и не хранится в базе. Ссылки в представлении заменяются текстом доступных целевых записей, части читаются пакетами. Клиент использует этот текст во всех местах показа записи; параметр `presentation` ищет также по составному тексту.

Объявление частей для раскрытия списка не меняет состав `list`: массивы строк по-прежнему возвращает только `get`. Для составного представления сервер может читать используемые колонки частей, но в ответ списка их не добавляет.

### Параметры списка

Все свойства `payload` действия `list` необязательны:

```json
{
    "filter": [{ "field": "name", "operator": "contains", "value": "образец" }],
    "sort": [{ "field": "name", "direction": "ascending" }],
    "page": 1,
    "pageSize": 50
}
```

| Параметр | Назначение и ограничения |
|---|---|
| `filter` | Массив условий по полям объекта; условия соединяются через «и». По умолчанию `[]` |
| `sort` | Массив полей и направлений `ascending` или `descending`. По умолчанию `[]`; регистратор не допускает сортировки |
| `page` | Целое число от 1; по умолчанию 1 |
| `pageSize` | Целое число от 1 до 500; по умолчанию 50 |
| `search` | Строка поиска по колонкам описания списка; пустая строка отключает поиск |
| `presentation` | Строка поиска по представлению самой записи справочника или документа; пустая строка отключает поиск |

Ответ содержит `items`, `total`, `page`, `pageSize` и `presentations`. Последнее поле является словарём представлений ссылок выбранной страницы: ключ кодируется JSON-массивом `[kind, name, guid]`, значение содержит текст или `null`, если доступного текста нет.

При равенстве значений сортировки порядок стабилизируется по `guid`; у регистра движений по регистратору и номеру строки, у регистра сведений по всем измерениям.

#### Отбор по полю

Поля отбора и сортировки должны принадлежать объекту. Допустимые способы сравнения зависят от вида поля и совпадают с [форматом описаний списка](interface.md#формат-описаний); недопустимый способ даёт 400. `equals` с `null` отбирает незаполненные поля, `notEquals` с `null` отбирает заполненные.

`contains` ищет буквальную подстроку без учёта регистра. Значение передаётся строкой для строк, чисел, сумм, дат и дат со временем. Клиент не добавляет `%`; введённые `%` и `_` считаются обычными символами. Незаполненное поле не совпадает с подстрокой.

Поиск использует отображаемый формат: число с десятичной запятой, сумма в рублях с двумя цифрами копеек, дата `ДД.ММ.ГГГГ`, дата со временем `ДД.ММ.ГГГГ ЧЧ:ММ` в часовом поясе сервера. Пробельные разделители разрядов чисел и сумм не учитываются ни в значении, ни в запросе.

#### Поиск по колонкам и представлению

`search` ищет буквальную подстроку без учёта регистра в любой колонке из описания списка. Соседние колонки не склеиваются; скрытые GUID и пометка удаления не участвуют в поиске. Строки, числа, суммы и даты используют описанный выше формат, логические значения ищутся по словам «Да» и «Нет».

Ссылки, полные ссылки и регистратор ищутся по представлению целевой записи. У справочника с представлением по ссылке используется текст связанной записи. Недоступная или отсутствующая запись не даёт совпадения.

`presentation` ищет подстроку без учёта регистра в представлении самой записи, включая составной текст. Параметр нужен, например, для выбора записи справочника с представлением по ссылке: этот текст не хранится полем записи и не выражается обычным `filter`. Недоступная целевая запись не даёт совпадения. Непустой `presentation` у регистров возвращает 400; пустая строка допустима.

`filter`, `search` и `presentation` соединяются через «и». Нестроковое значение `search` или `presentation` возвращает 400.

#### Строки регистра движений

`list` регистра возвращает строки с регистратором `{ "document": "…", "guid": "…" }`, периодом, номером строки, измерениями и ресурсами. Отбор по регистратору принимает такое же значение: `{ "field": "recorder", "operator": "equals", "value": { "document": "sample", "guid": "…" } }`. Регистратор хранится в двух колонках. Оба способа сравнения выполняются в SQL: `equals` проверяется двумя условиями через `AND`, `notEquals` проверяется группой `recorderDocument != ? OR recorderGuid != ?`. Сортировать по регистратору нельзя.

### Действия регистра сведений

Цель операции: `{ "kind": "informationRegister", "name": "sample" }`. Доступны четыре стандартных действия:

| Действие | `payload` | Результат |
|---|---|---|
| `get` | `{ "dimensions": { "source": "system", "externalObject": "one" } }` | Все измерения и ресурсы; отсутствующая запись даёт 404 |
| `list` | [Параметры списка](#параметры-списка) | Страница сведений; можно отбирать по одному измерению |
| `save` | `{ "fields": { "source": "system", "externalObject": "one", "description": "Описание", "item": "<guid>" } }` | Созданная либо обновлённая запись |
| `delete` | `{ "dimensions": { "source": "system", "externalObject": "one" } }` | `{ "dimensions": { "source": "system", "externalObject": "one" }, "deleted": true }`; отсутствующая запись даёт 404 |

#### Ключ и запись ресурсов

Ключ передаётся целиком; порядок свойств JSON значения не имеет. Пропущенное, `null` или пустое строковое измерение, неверный тип либо неизвестное имя поля дают 400. Значения `0` и `false` допустимы для соответствующих видов измерений. Посторонние свойства оболочки, в том числе технический `guid`, отклоняются.

`save` заменяет все ресурсы: пропущенные необязательные ресурсы становятся `null`, обязательные нужно передать. Технического идентификатора для обновления нет: другой набор измерений создаёт другую запись. Для переноса сведений на другой ключ удаляют старую запись и создают новую в одном пакете или собственном действии.

#### Права, политики и журнал

`get` и `list` требуют `Rights.informationRegister.<имя>.read`, `save` и `delete` требуют `write`. Те же действия доступны через `ActionDispatcher` с общими гарантиями транзакции и проверки прав.

Политика `save` получает прежнюю запись в `existingRecord` (либо `null`) и предлагаемую в `proposedRecord`; политика `delete` получает существующую запись в `record`.

`delete` удаляет сведения физически. Журнал сохраняет измерения в `targetKey`, прежние значения полей в `changes`, а значения после удаления равны `null`. `targetGuid` строки журнала равен `null`. Для чтения истории одной записи `history` принимает `targetKey` со всеми измерениями; без ключа возвращает историю регистра. Полный контракт находится в разделе [«Чтение журнала»](journal.md#чтение-журнала).

### Собственные действия

Объект может объявить собственные действия в метаданных: входные данные и обработчик на Effect. Право на действие объявлять не нужно: каждое собственное действие получает своё право автоматически. Они вызываются через тот же эндпоинт: `"action": "dismiss"`. Собственное действие получает `payload` по полям `.input(...)` и возвращает результат обработчика.

#### Пробные действия

У пробного справочника `sample` есть действия для ручной проверки собственных и вложенных действий. `inspect` принимает `guid`, вызывает вложенное чтение записи и возвращает её вместе с идентификатором пользователя, трассы и исходного действия. `duplicate` принимает `guid` и создаёт копию записи вложенным `save`; в журнале строка копии ссылается на строку `duplicate` через `parentActionGuid`.

Пробное действие `checkInformationRollback` создаёт объект и сведения, затем возвращает ошибку 400: ни одна из записей и ни одна строка журнала не сохраняются.

### Чтение журнала

Журнал читается через тот же эндпоинт с целью `{ "kind": "platform", "name": "journal" }`. Действия описаны в подразделе [«Чтение журнала»](journal.md#чтение-журнала).

### Ошибки

| HTTP | Причина | Тело ответа |
|---|---|---|
| 400 | Неверные входные данные | `error` и `fields` с путями полей |
| 401 | Пользователь не вошёл | `error` |
| 403 | Нет права на действие | `error` и ключ недостающего права в `right` |
| 404 | Неизвестный объект, действие или отсутствующая запись | `error` |
| 409 | Политика конфигурации запретила изменение | `error` |
| 500 | Ошибка базы или непредвиденная ошибка | `error` без текста SQL и параметров |

Пути `fields` отсчитываются от начала операции через точку, например `payload.fields.name` или `payload.fields.lines.0.text` для поля первой строки табличной части.
