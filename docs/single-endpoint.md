# API данных

API позволяет читать и изменять справочники, документы и регистры конфигурации, вызывать собственные действия и читать журнал. Все действия вызываются через один маршрут `POST /api/perform`: объект и действие указываются в теле запроса. Описания доступных объектов, полей и действий возвращает `GET /api/metadata`.

Страница предназначена для разработчика, которому нужен контракт API. Экраны клиента обращаются к данным через [Web SDK](interface.md#web-sdk).

## Как выполняется запрос

Пользователь должен войти в приложение. Для каждого действия платформа проверяет его права и входные данные. Перед изменением записи проверяются [политики конфигурации](write-policies.md), после изменения оно записывается в [журнал](journal.md).

Один запрос может содержать одну операцию или пакет. Операции пакета выполняются по порядку в общей транзакции. При ошибке откатываются все изменения запроса, включая движения документов и журнал. Клиент получает ошибку вместо частичного результата.

Собственное действие может вызывать другие действия. Такие вложенные вызовы выполняются от имени того же пользователя, проходят проверку прав и политик и используют общую транзакцию. Журнал связывает вложенные изменения с вызвавшим их действием; вызов собственного действия фиксируется и тогда, когда оно только читает данные.

За выполнение отвечает [диспетчер данных](https://github.com/EGSP/collection-zarplata/blob/docs/documentation/endpoint-structure/src/server/data/data.service.ts). Подробности обработки документов находятся в [модуле проведения](https://github.com/EGSP/collection-zarplata/blob/docs/documentation/endpoint-structure/src/server/data/posting.ts).

## Справочник API

### Запрос и ответ

Тело `POST /api/perform` содержит одну операцию или непустой массив операций:

```json
{
    "target": { "kind": "catalog", "name": "employees" },
    "action": "save",
    "payload": { "fields": { "name": "Иван Петров" } }
}
```

| Свойство | Значение |
|---|---|
| `target.kind` | Вид объекта: `catalog`, `document`, `register`, `informationRegister`; для журнала `platform` |
| `target.name` | Имя объекта из метаданных; для журнала `journal` |
| `action` | Имя стандартного или собственного действия |
| `payload` | Входные данные действия; можно опустить, если они не требуются |

Успешный ответ имеет статус 200. Одиночная операция возвращает свой результат, пакет возвращает массив результатов в исходном порядке. Пустой массив операций возвращает 400.

`GET /api/metadata` также требует входа. Ответ содержит только объекты, действия и страницы, доступные пользователю. Формат описан в разделе [«Формат описаний»](interface.md#формат-описаний).

### Стандартные действия

| Действие | Справочник | Документ | Регистр движений | Регистр сведений |
|---|:-:|:-:|:-:|:-:|
| `list` | + | + | + | + |
| `get` | + | + | | + |
| `save` | + | + | | + |
| `markDeleted`, `unmarkDeleted` | + | + | | |
| `post`, `unpost` | | + | | |
| `delete` | | | | + |
| `import` | + | | | |

Чтение требует права `read` соответствующего объекта; запись, удаление и импорт требуют `write`. Проведение и его отмена требуют отдельного права `post`. Каждое собственное действие имеет отдельное право. Подробности находятся в разделе [«Права (RBAC)»](authorization.md).

### Справочники и документы

Записи справочников и документов адресуются по `guid`. Их общие действия имеют одинаковые входные данные и результаты:

| Действие | `payload` | Результат |
|---|---|---|
| `list` | [Параметры списка](#параметры-списка) | Страница записей |
| `get` | `{ "guid": "…" }` | Запись со всеми полями и табличными частями |
| `save` | `{ "fields": { … } }` для создания; `{ "guid": "…", "fields": { … } }` для обновления | Созданная или обновлённая запись с табличными частями |
| `markDeleted` | `{ "guid": "…" }` | Запись с пометкой удаления |
| `unmarkDeleted` | `{ "guid": "…" }` | Запись без пометки удаления |

Обращение к отсутствующему `guid` возвращает 404. Пометка удаления сохраняет запись; эти действия не удаляют её физически.

#### Запись полей и табличных частей

`save` заменяет пользовательские данные целиком. В `fields` нужно передать обязательные поля и все табличные части; пустая часть передаётся как `[]`. Пропущенные необязательные поля становятся `null`, прежние строки табличных частей заменяются новыми. Обновление сохраняет пометку удаления.

#### Вычисляемые поля

Перед записью сервер рассчитывает вычисляемые поля: сначала в строках табличных частей, затем в шапке. Клиент может не передавать такие поля; переданные значения заменяются результатом формул. Проверка записи и политик выполняется после расчёта.

Рассчитанные значения сохраняются и участвуют в отборе, сортировке и поиске. Ошибка расчёта возвращает 400 с путём поля. Поля входных данных собственных действий рассчитываются по тем же правилам.

#### Представления и табличные части

Результаты `get`, `save`, действий пометки и проведения содержат `$presentation`: текстовое представление записи. Этот же текст входит в строки `list`. Представление вычисляется при чтении по описанию объекта; ссылки заменяются текстом доступных целевых записей.

`list` не возвращает массивы табличных частей, даже если список позволяет раскрывать их на экране. Полную запись с частями возвращают `get` и изменяющие действия. Поиск по составному представлению может учитывать текст табличных частей без добавления этих частей в ответ списка.

#### Импорт справочника

Действие `import` импортирует записи справочника; его использует загрузчик XML 1С. Входные данные, результат и правила обновления описаны в разделе [«Импорт из XML 1С»](1c-xml-import.md).

### Документы

Документы поддерживают общие действия справочников и документов, а также проведение:

| Действие | `payload` | Результат |
|---|---|---|
| `post` | `{ "guid": "…" }` | Проведённый документ с табличными частями |
| `unpost` | `{ "guid": "…" }` | Документ с табличными частями после отмены проведения |

#### Нумерация

Платформа присваивает номер при первой записи документа. Следующий номер равен наибольшему номеру этого вида документов плюс один и дополнен нулями как минимум до шести знаков: `000001`, `000002`. Нумерация сквозная, без разбиения по годам и префиксов. Клиент не передаёт номер и признак проведения в `save`.

#### Проведение и отмена проведения

`post` устанавливает признак проведения и заменяет прежние движения документа во всех регистрах движениями обработчика конфигурации. Повторное проведение не дублирует строки. Документ без обработчика тоже можно провести, но движений у него нет.

Строки движений проверяются по описанию регистра. Неверные данные возвращают 400; проведение и остальные изменения запроса откатываются. `unpost` удаляет движения документа и снимает признак проведения.

`save` проведённого документа сохраняет признак проведения и заново формирует движения по новым данным.

#### Пометка удаления

Пометка проведённого документа отменяет его проведение и удаляет движения. Политика конфигурации может запретить пометку до явной отмены проведения; такое правило действует у пробных документов. Снятие пометки документ не проводит. Проведение помеченного документа возвращает 400.

### Регистры движений

Регистры движений поддерживают стандартное действие `list`. Прямые стандартные действия записи недоступны: движения записывают документы при проведении. Вызов остальных стандартных действий возвращает 404.

Строка списка содержит регистратор `{ "document": "…", "guid": "…" }`, период, номер строки, измерения и ресурсы. Номер строки назначается платформой и уникален внутри регистра для одного документа; период по умолчанию равен дате документа.

Отбор по регистратору принимает полную ссылку на документ:

```json
{
    "field": "recorder",
    "operator": "equals",
    "value": { "document": "sample", "guid": "…" }
}
```

Допустимы `equals` и `notEquals`. Сортировка по регистратору недоступна.

### Регистры сведений

Цель операции: `{ "kind": "informationRegister", "name": "sample" }`. Запись определяется полным набором измерений, а не `guid`.

| Действие | `payload` | Результат |
|---|---|---|
| `get` | `{ "dimensions": { "source": "system", "externalObject": "one" } }` | Все измерения и ресурсы записи |
| `list` | [Параметры списка](#параметры-списка) | Страница записей; отбор может использовать часть измерений |
| `save` | `{ "fields": { "source": "system", "externalObject": "one", "description": "Описание", "item": "<guid>" } }` | Созданная или обновлённая запись |
| `delete` | `{ "dimensions": { "source": "system", "externalObject": "one" } }` | `{ "dimensions": { "source": "system", "externalObject": "one" }, "deleted": true }` |

`get` и `delete` отсутствующей записи возвращают 404. `delete` удаляет запись физически.

#### Ключ и запись ресурсов

Все измерения обязательны; порядок свойств JSON значения не имеет. Пропущенное измерение, `null`, пустая строка, неверный тип или неизвестное поле возвращают 400. Значения `0` и `false` допустимы для соответствующих видов измерений. Посторонние свойства `payload`, в том числе `guid`, отклоняются.

`save` создаёт запись либо заменяет все ресурсы существующей записи с теми же измерениями. Пропущенные необязательные ресурсы становятся `null`, обязательные нужно передать. Другой набор измерений создаёт другую запись.

Историю одной записи можно получить действием журнала `history`, передав все измерения в `targetKey`. Без ключа возвращается история регистра. Контракт описан в разделе [«Чтение журнала»](journal.md#чтение-журнала).

### Параметры списка

Все свойства `payload` действия `list` необязательны:

```json
{
    "filter": [{ "field": "name", "operator": "contains", "value": "образец" }],
    "sort": [{ "field": "name", "direction": "ascending" }],
    "page": 1,
    "pageSize": 50
}
```

| Параметр | Назначение и ограничения |
|---|---|
| `filter` | Массив условий по полям объекта; по умолчанию `[]` |
| `sort` | Массив полей и направлений `ascending` или `descending`; по умолчанию `[]` |
| `page` | Целое число от 1; по умолчанию 1 |
| `pageSize` | Целое число от 1 до 500; по умолчанию 50 |
| `search` | Строка поиска по колонкам описания списка; по умолчанию поиск отключён |
| `presentation` | Строка поиска по представлению справочника или документа; по умолчанию поиск отключён |

Ответ содержит `items`, `total`, `page`, `pageSize` и `presentations`. `total` учитывает все совпадения до разбиения на страницы. `presentations` содержит представления ссылок выбранной страницы: ключ кодируется JSON-массивом `[kind, name, guid]`, значение содержит текст или `null`, если доступного текста нет.

Поля отбора и сортировки должны принадлежать объекту; сортировать по регистратору нельзя. При равенстве значений сортировки порядок стабилизируется по `guid`, у регистра движений по регистратору и номеру строки, у регистра сведений по всем измерениям.

#### Отбор по полю

Условие `filter` содержит `field`, `operator` и `value`. Несколько условий соединяются через «и». Допустимые операторы зависят от вида поля:

| Вид поля | Операторы |
|---|---|
| Строка | `equals`, `notEquals`, `contains` |
| Число, сумма, дата, дата со временем | `equals`, `notEquals`, `greater`, `greaterOrEqual`, `less`, `lessOrEqual`, `contains` |
| Логическое поле, ссылка, полная ссылка, GUID, регистратор | `equals`, `notEquals` |

Для обычных сравнений `value` передаётся в типе поля. `equals` с `null` отбирает незаполненные поля, `notEquals` с `null` отбирает заполненные. Неизвестное поле, недопустимый оператор или неверный тип возвращают 400.

`contains` принимает строку и ищет буквальную подстроку без учёта регистра. Клиент не добавляет `%`: символы `%` и `_` считаются обычными символами. Незаполненное поле не даёт совпадения.

#### Поиск по колонкам и представлению

`search` ищет буквальную подстроку без учёта регистра в любой колонке описания списка. Соседние колонки не склеиваются; скрытые GUID и пометка удаления не участвуют в поиске. Ссылки и регистратор ищутся по представлению целевой записи. Отсутствующая или недоступная запись не даёт совпадения.

`presentation` ищет подстроку в представлении самой записи, включая составной текст и представление по ссылке. Непустое значение у регистров возвращает 400.

`filter`, `search` и `presentation` соединяются через «и». Пустая строка отключает соответствующий поиск; нестроковое значение `search` или `presentation` возвращает 400.

#### Форматы поиска

`contains` и `search` используют отображаемые значения:

| Значение | Формат поиска |
|---|---|
| Число | С десятичной запятой |
| Сумма | В рублях с двумя цифрами копеек |
| Дата | `ДД.ММ.ГГГГ` |
| Дата со временем | `ДД.ММ.ГГГГ ЧЧ:ММ` в часовом поясе сервера |
| Логическое значение (только `search`) | «Да» или «Нет» |

Пробельные разделители разрядов чисел и сумм не учитываются ни в значении, ни в запросе. Символы `%` и `_` во всех вариантах поиска остаются буквальными.

### Собственные действия

Собственное действие вызывается тем же способом, что стандартное: его имя передаётся в `action`, например `"action": "dismiss"`. Состав `payload` задаётся описанием действия в конфигурации; ответ содержит результат обработчика. На каждый вызов требуется отдельное право этого действия.

Объявление действий описано в разделе [«Метаданные»](metadata.md). Гарантии вложенных вызовов приведены в разделе [«Как выполняется запрос»](#как-выполняется-запрос).

### Чтение журнала

Для чтения журнала укажите цель `{ "kind": "platform", "name": "journal" }`. Требуется отдельное право чтения журнала. Действия, параметры и результаты описаны в разделе [«Чтение журнала»](journal.md#чтение-журнала).

### Ошибки

| HTTP | Причина | Тело ответа |
|---|---|---|
| 400 | Неверные входные данные или ошибка расчёта | `error` и `fields` с путями полей |
| 401 | Пользователь не вошёл | `error` |
| 403 | Нет права на действие | `error` и ключ недостающего права в `right` |
| 404 | Неизвестный объект, действие или отсутствующая запись | `error` |
| 409 | Политика конфигурации запретила изменение | `error` |
| 500 | Ошибка базы или непредвиденная ошибка | `error` без текста SQL и параметров |

Пути `fields` для входных данных начинаются с `payload` и разделяются точками: `payload.fields.name`, `payload.fields.lines.0.text`. Последний путь обозначает поле `text` первой строки табличной части `lines`. Ошибка проверки движений указывает путь, начинающийся с `проведение.<имя регистра>`.

## Как перенести сведения на другой ключ

Чтобы изменить измерения записи регистра сведений, отправьте один пакет из двух операций: `delete` со старым набором измерений и `save` с новым набором и всеми ресурсами. В `delete` укажите ключ в `payload.dimensions`, в `save` передайте измерения и ресурсы вместе в `payload.fields`.

При успехе пакет возвращает результат удаления и новую запись. Если любая операция завершится ошибкой, старые сведения останутся на месте, а новая запись не появится.
