# API данных

Через API читают и изменяют справочники, документы и регистры, вызывают собственные действия и читают журнал. Все действия идут на один маршрут `POST /api/perform`: объект и действие указываются в теле запроса. Описания доступных объектов, полей и действий возвращает `GET /api/metadata`.

Страница описывает контракт для разработчика. Экраны клиента обращаются к данным через [Web SDK](web-sdk.md).

Служебная цель `platform.users` управляет учётными записями входа и их ролями. Форматы `list`, `get`, `save`, ограничения PIN и отдельные права чтения и записи приведены в [API пользователей](authentication.md#api-пользователей). Эти операции входят в общую транзакцию пакета.

Служебная цель `platform.backups` показывает состояние резервных копий (`list`), начинает копию (`create`) и прерывает её (`cancel`). Нужны права `platform.backups.read` и `platform.backups.write`; создание и отмена пишутся в журнал. Форматы описаны в разделе [«Резервное копирование»](backup.md#api-и-права).

Служебная цель `platform.authorization` читает полное дерево прав (`tree`) и объяснение доступа выбранного узла (`explain`). Оба действия требуют отдельного права `platform.authorization.read`, не создают строк журнала и выполняются в транзакции запроса. Форматы ответов приведены в [API дерева и объяснения](authorization.md#api-дерева-и-объяснения).

## Как выполняется запрос

Запрос выполняется только после входа в приложение. Для каждого действия платформа проверяет права и входные данные, перед изменением записи вызывает [политики конфигурации](write-policies.md), после изменения пишет строку в [журнал](journal.md).

Запрос содержит одну операцию или пакет. Операции пакета идут по порядку в общей транзакции. Любая ошибка откатывает все изменения запроса, включая движения документов и журнал: клиент получает ошибку, а не частичный результат.

Собственное действие может вызывать другие действия. Вложенные вызовы выполняются от имени того же пользователя, проходят проверку прав и политик и входят в общую транзакцию. Журнал связывает вложенные изменения с вызвавшим их действием. Вызов собственного действия попадает в журнал, даже если оно только читает данные.

Запрос выполняет [диспетчер данных](https://github.com/EGSP/collection-zarplata/blob/main/src/server/data/data.service.ts), документы обрабатывает [модуль проведения](https://github.com/EGSP/collection-zarplata/blob/main/src/server/data/posting.ts).

## Справочник API

### Запрос и ответ

Тело `POST /api/perform` содержит одну операцию или непустой массив операций:

```json
{
    "target": { "kind": "catalog", "name": "physicalPersons" },
    "action": "save",
    "payload": { "fields": { "name": "Иван Петров" } }
}
```

| Свойство | Значение |
|---|---|
| `target.kind` | Вид объекта: `catalog`, `document`, `register`, `informationRegister`; для служебных операций `platform` |
| `target.name` | Имя объекта из метаданных; для служебной операции её цель, например `records`, `users`, `authorization`, `journal`, `documents` |
| `action` | Имя стандартного или собственного действия |
| `payload` | Входные данные действия; можно опустить, если они не требуются |

Успешный ответ имеет статус 200. Одиночная операция возвращает свой результат, пакет возвращает массив результатов в исходном порядке. Пустой массив операций возвращает 400.

`GET /api/metadata` тоже требует входа и возвращает только объекты, действия и страницы, доступные пользователю. Формат описан в разделе [«Формат описаний»](interface.md#формат-описаний).

### Разрешение цели открытия

Служебная цель `platform.records`, действие `resolveOpening`, выбирает форму существующей записи по правилу конфигурации:

```json
{
    "target": { "kind": "platform", "name": "records" },
    "action": "resolveOpening",
    "payload": {
        "reference": { "kind": "document", "name": "saleInstallment", "guid": "01900000-0000-7000-8000-000000000001" },
        "original": false
    }
}
```

`reference` обязательна и указывает справочник или документ. Необязательный логический `original` по умолчанию равен `false`; `true` отключает правило. Ответ 200 содержит конечную ссылку `{ kind, name, guid }`. Если правила или связанной цели нет, возвращается исходная ссылка.

Операция требует чтения исходной и каждой следующей записи: нет права даёт 403 с ключом, нет объекта или записи даёт 404. Неверная ссылка, неверный тип `original`, цикл или превышение 32 записей цепочки дают 400. Отказ не заменяется открытием исходной формы. Операция выполняется в общей транзакции, не меняет данные и не пишет журнал. Отдельного права на разрешение цели нет; в режиме оригинала проверяется чтение исходной записи.

Создание, `get`, `list`, представления и подбор не применяют правила открытия. Клиент вызывает операцию перед открытием формы; обычный HTTP middleware не охватывает переходы внутри React Router. Описание правила находится в разделе [«Метаданные»](metadata.md#правило-открытия-записи).

### Стандартные действия

| Действие | Справочник | Документ | Регистр движений | Регистр сведений |
|---|:-:|:-:|:-:|:-:|
| `list` | + | + | + | + |
| `totals` | | | + | |
| `get` | + | + | | + |
| `save` | + | + | | + |
| `markDeleted`, `unmarkDeleted` | + | + | | |
| `post`, `unpost` | | + | | |
| `delete` | | | | + |
| `import` | + | | | |

Права проверяются так:

- чтение, включая итоги регистра, требует `read` объекта;
- запись, удаление и импорт требуют `write`;
- проведение и его отмена требуют отдельного права `post`;
- у каждого собственного действия своё право.

Подробности описаны в разделе [«Права (RBAC)»](authorization.md).

### Справочники и документы

Записи справочников и документов адресуются по `guid`. Их общие действия имеют одинаковые входные данные и результаты:

| Действие | `payload` | Результат |
|---|---|---|
| `list` | [Параметры списка](#параметры-списка) | Страница записей |
| `get` | `{ "guid": "…" }` | Запись со всеми полями и табличными частями |
| `save` | `{ "fields": { … } }` для создания; `{ "guid": "…", "fields": { … } }` для обновления; необязательный `"post": true` у документа | Созданная или обновлённая запись с табличными частями; с `post` проведённый документ |
| `markDeleted` | `{ "guid": "…" }` | Запись с пометкой удаления |
| `unmarkDeleted` | `{ "guid": "…" }` | Запись без пометки удаления |

Отсутствующий `guid` возвращает 404. Пометка удаления не удаляет запись физически.

#### Запись полей и табличных частей

`save` заменяет пользовательские данные целиком. В `fields` передаются обязательные поля и все табличные части, пустая часть как `[]`. Пропущенные необязательные поля становятся `null`, прежние строки табличных частей заменяются новыми. Обновление сохраняет пометку удаления.

`save` документа с `"post": true` записывает и проводит его в одной транзакции. Если проведение отклонено, откатывается и запись, поэтому новый документ не остаётся черновиком. Права на проведение проверяются, как для обычного `post`. Для справочника и других объектов, кроме документа, `post: true` возвращает ошибку валидации.

#### Значение составного поля

[Составное поле](metadata.md#составное-поле) передаётся и возвращается вместе с типом варианта. Простое значение содержит `type` и `value`, ссылка содержит цель и GUID:

```json
{ "type": "string", "value": "Сейф" }
```

```json
{ "type": "reference", "kind": "catalog", "name": "paymentReceivers", "guid": "…" }
```

Незаполненное поле равно `null`. Порядок свойств не важен, посторонние свойства отбрасываются. Запись значения другого типа заменяет прежнее целиком, и [журнал](journal.md) хранит значения до и после в этом же формате, поэтому смена типа в нём видна.

Ошибки возвращают 400:

| Случай | Путь в `fields` |
|---|---|
| Тип не входит в варианты поля или ссылка на объект вне перечня целей | `payload.fields.receiver` |
| Значение нарушает ограничения варианта | `payload.fields.receiver.value` или `payload.fields.receiver.guid` |

#### Вычисляемые поля

Перед записью сервер рассчитывает вычисляемые поля: сначала в строках табличных частей, затем в шапке. Клиент может их не передавать, а переданные значения заменяются результатом формул. Проверка записи и политики выполняются после расчёта.

Рассчитанные значения сохраняются и участвуют в отборе, сортировке и поиске. Ошибка расчёта возвращает 400 с путём поля. Поля входных данных собственных действий рассчитываются так же.

#### Представления и табличные части

Результаты `get`, `save`, пометки и проведения содержат `$presentation`, текстовое представление записи; этот же текст входит в строки `list`. Представление вычисляется при чтении по описанию объекта, ссылки заменяются текстом доступных целевых записей.

`list` не возвращает табличные части, даже если экран позволяет их раскрывать. Полную запись с частями возвращают `get` и изменяющие действия. Поиск по составному представлению может учитывать текст табличных частей, не добавляя их в ответ списка.

#### Импорт справочника

`import` загружает записи справочника; его вызывает загрузчик XML 1С. Входные данные, результат и правила обновления описаны в разделе [«Импорт из XML 1С»](1c-xml-import.md).

### Документы

Документы поддерживают общие действия справочников и документов, а также проведение:

| Действие | `payload` | Результат |
|---|---|---|
| `post` | `{ "guid": "…" }` | Проведённый документ с табличными частями |
| `unpost` | `{ "guid": "…" }` | Документ с табличными частями после отмены проведения |

#### Нумерация

Платформа присваивает номер при первой записи документа: наибольший номер этого вида плюс один, дополненный нулями минимум до шести знаков (`000001`, `000002`). Нумерация сквозная, без годов и префиксов. Клиент не передаёт в `save` номер и признак проведения.

#### Проведение и отмена проведения

`post` устанавливает признак проведения и заменяет прежние движения документа движениями обработчика конфигурации, поэтому повторное проведение строки не дублирует. Документ без обработчика проводится, но движений не создаёт. `unpost` удаляет движения и снимает признак.

`save` проведённого документа сохраняет признак и заново формирует движения по новым данным.

Строки движений проверяются по описанию регистра; неверные данные возвращают 400 и откатывают запрос.

После каждого изменения движений платформа проверяет [ограничения итога](metadata.md#итоги-и-ограничения-регистра). Нарушение возвращает 409 с текстом ограничения и откатывает запрос:

- `post` оставляет документ непроведённым;
- `unpost` оставляет его проведённым;
- `save` проведённого документа не меняет ни данные, ни движения.

Политики документа на эту проверку не влияют.

#### Пометка удаления

Пометка проведённого документа отменяет проведение и удаляет движения, поэтому её тоже может отклонить ограничение итога. Политика может запретить пометку до явной отмены проведения: так устроен документ «Закрытие периода». Снятие пометки документ не проводит. Проведение помеченного документа возвращает 400.

#### Перепроведение документов

Операция заново проводит все проведённые документы. Она нужна после изменения конфигурации, когда документ начал записывать новые движения или перестал записывать прежние: движения существующих документов меняет только проведение.

```json
{ "target": { "kind": "platform", "name": "documents" }, "action": "repost" }
```

Нужно право `Rights.platform.documents.repost` (ключ `platform.documents.repost`); `post` отдельных документов его не заменяет. Документы всех видов проводятся в порядке дат. Политики проведения не вызываются, как и при записи проведённого документа. Результат `{ "documents": 2 }` содержит число перепроведённых документов.

Каждый документ проходит проверку ограничений итога. Нарушение останавливает операцию с 409, неверные строки движений дают 400; в обоих случаях текст начинается с названия, номера и даты документа, а движения всех документов этого запроса откатываются. Успешная операция оставляет в [журнале](journal.md) одну строку с целью `platform.documents`.

### Регистры движений

Регистры движений поддерживают только `list` и `totals`: движения записывают документы при проведении, остальные стандартные действия возвращают 404.

Строка списка содержит регистратор `{ "document": "…", "guid": "…" }`, период, номер строки, измерения и ресурсы. Номер строки назначает платформа, он уникален внутри регистра для одного документа. Период по умолчанию равен дате документа.

Отбор по регистратору принимает полную ссылку на документ:

```json
{
    "field": "recorder",
    "operator": "equals",
    "value": { "document": "sample", "guid": "…" }
}
```

Допустимы `equals` и `notEquals`. Сортировка по регистратору недоступна.

#### Итоги регистра

`totals` возвращает суммы ресурсов по сочетаниям значений измерений:

```json
{
    "target": { "kind": "register", "name": "sample" },
    "action": "totals",
    "payload": {
        "by": ["item"],
        "where": [{ "field": "item", "operator": "equals", "value": "<guid>" }]
    }
}
```

| Параметр | Назначение и ограничения |
|---|---|
| `by` | Массив имён измерений группировки без повторов; по умолчанию `[]` |
| `where` | Массив условий в формате [отбора по полю](#отбор-по-полю); по умолчанию `[]`. Поле условия должно быть измерением или стандартным полем `period` |

Ответ `{ "items": [...] }` содержит строку на каждое сочетание значений измерений из `by`: эти значения и суммы всех ресурсов регистра, например `{ "item": "<guid>", "quantity": 5, "amount": 1000 }`. Строки упорядочены по измерениям группировки; сочетание без движений в ответ не входит. При пустом `by` ответ состоит из одной строки с суммами по всем отобранным движениям, без движений суммы равны нулю.

Группировка по составному измерению различает тип значения: строка «100» и число 100 попадают в разные строки, а одинаковые ссылки складываются.

Условия соединяются через «и» и применяются до суммирования. Период отбирается сравнениями поля `period`, например `greaterOrEqual` и `less` для границ интервала. Оператор `contains`, отбор по ресурсу, неизвестное или повторённое измерение и значение неверного типа возвращают 400. Сумма дробного ресурса округляется до девяти знаков после запятой.

Код конфигурации читает тот же итог функцией `totals`, см. [«Метаданные»](metadata.md#чтение-итога-из-конфигурации).

### Регистры сведений

Цель операции: `{ "kind": "informationRegister", "name": "sample" }`. Запись определяется полным набором измерений, а не `guid`.

| Действие | `payload` | Результат |
|---|---|---|
| `get` | `{ "dimensions": { "source": "system", "externalObject": "one" } }` | Все измерения и ресурсы записи |
| `list` | [Параметры списка](#параметры-списка) | Страница записей; отбор может использовать часть измерений |
| `save` | `{ "fields": { "source": "system", "externalObject": "one", "description": "Описание", "item": "<guid>" } }` | Созданная или обновлённая запись |
| `delete` | `{ "dimensions": { "source": "system", "externalObject": "one" } }` | `{ "dimensions": { "source": "system", "externalObject": "one" }, "deleted": true }` |

`get` и `delete` отсутствующей записи возвращают 404. `delete` удаляет запись физически.

#### Ключ и запись ресурсов

Все измерения обязательны, порядок свойств не важен. Пропущенное измерение, `null`, пустая строка, неверный тип и неизвестное поле возвращают 400; `0` и `false` допустимы для соответствующих видов. Составное измерение различает записи по типу, значению и цели ссылки: строка «100» и число 100 задают разные записи. Посторонние свойства `payload`, в том числе `guid`, отклоняются.

`save` создаёт запись или заменяет все ресурсы записи с теми же измерениями. Пропущенные необязательные ресурсы становятся `null`, обязательные нужно передать. Другой набор измерений создаёт другую запись.

Историю записи возвращает действие журнала `history` со всеми измерениями в `targetKey`; без ключа возвращается история регистра. Контракт описан в разделе [«Чтение журнала»](journal.md#чтение-журнала).

### Параметры списка

Все свойства `payload` действия `list` необязательны:

```json
{
    "filter": [{ "field": "name", "operator": "contains", "value": "образец" }],
    "sort": [{ "field": "name", "direction": "ascending" }],
    "page": 1,
    "pageSize": 50
}
```

| Параметр | Назначение и ограничения |
|---|---|
| `filter` | Массив условий по полям объекта; по умолчанию `[]` |
| `sort` | Массив полей и направлений `ascending` или `descending`; по умолчанию `[]` |
| `page` | Целое число от 1; по умолчанию 1 |
| `pageSize` | Целое число от 1 до 500; по умолчанию 50 |
| `search` | Строка поиска по колонкам описания списка; по умолчанию поиск отключён |
| `presentation` | Строка поиска по представлению справочника или документа; по умолчанию поиск отключён |

Ответ содержит `items`, `total`, `page`, `pageSize` и `presentations`. `total` считает все совпадения до разбиения на страницы. `presentations` хранит представления ссылок выбранной страницы: ключ это JSON-массив `[kind, name, guid]`, значение это текст или `null`, если доступного текста нет. Представления читаются в порядке зависимостей: объект, чьё представление ссылается на записи других объектов страницы, читается после них.

Поля отбора и сортировки должны принадлежать объекту; сортировать по регистратору нельзя. Составное поле сортируется по типу значения, затем по значению внутри типа ([«Составное поле»](metadata.md#составное-поле)). При равенстве порядок стабилизируется по `guid`, у регистра движений по регистратору и номеру строки, у регистра сведений по всем измерениям.

#### Отбор по полю

Условие `filter` содержит `field`, `operator` и `value`; условия соединяются через «и». Операторы зависят от вида поля:

| Вид поля | Операторы |
|---|---|
| Строка | `equals`, `notEquals`, `contains` |
| Число, сумма, дата, дата со временем | `equals`, `notEquals`, `greater`, `greaterOrEqual`, `less`, `lessOrEqual`, `contains` |
| Ссылка | `equals`, `notEquals`, `contains` |
| Логическое поле, полная ссылка, GUID, регистратор | `equals`, `notEquals` |
| Составное поле | `equals`, `notEquals`, `greater`, `greaterOrEqual`, `less`, `lessOrEqual`, `contains` |

Для обычных сравнений `value` передаётся в типе поля. `equals` с `null` отбирает незаполненные поля, `notEquals` с `null` отбирает заполненные. Неизвестное поле, недопустимый оператор или неверный тип возвращают 400.

Для составного поля `value` содержит [значение с типом](#значение-составного-поля):

```json
{ "field": "receiver", "operator": "equals", "value": { "type": "reference", "kind": "catalog", "name": "paymentReceivers", "guid": "…" } }
```

`equals` требует совпадения типа и значения: отбор по ссылке различает записи с одинаковым представлением, а отбор по строке не находит число с теми же цифрами. Упорядоченные операторы сравнивают только значения указанного простого типа: `greater` с `{ "type": "number", "value": 50 }` отбирает числа больше 50 и пропускает строки, ссылки и незаполненные поля. Упорядоченное сравнение со ссылкой или логическим значением возвращает 400.

`contains` принимает строку и ищет подстроку без учёта регистра. Символы `%` и `_` буквальные, добавлять `%` не нужно. Незаполненное поле не совпадает. У составного поля подстрока ищется в показанном тексте варианта: в простом значении по [формату поиска](#форматы-поиска), в ссылке по представлению записи. У самой ссылки `contains` работает так же: подстрока ищется в представлении целевой записи. Недоступная без права чтения, отсутствующая запись и пустая ссылка не совпадают.

#### Поиск по колонкам и представлению

`search` ищет подстроку без учёта регистра в любой колонке описания списка. Соседние колонки не склеиваются, скрытые GUID и пометка удаления не участвуют. Ссылки, регистратор и ссылочные значения составных полей ищутся по представлению целевой записи. Отсутствующая или недоступная запись не совпадает: без права чтения целевого объекта ни `search`, ни `contains` такую ссылку не находят.

`presentation` ищет подстроку в представлении самой записи, включая составной текст и представление по ссылке. У регистров непустое значение возвращает 400.

`filter`, `search` и `presentation` соединяются через «и». Пустая строка отключает поиск, нестроковое значение возвращает 400.

#### Форматы поиска

`contains` и `search` используют отображаемые значения:

| Значение | Формат поиска |
|---|---|
| Число | С десятичной запятой |
| Сумма | В рублях с двумя цифрами копеек |
| Дата | `ДД.ММ.ГГГГ` |
| Дата со временем | `ДД.ММ.ГГГГ ЧЧ:ММ` в часовом поясе сервера |
| Логическое значение (только `search`) | «Да» или «Нет» |

Значение составного поля использует формат своего типа. Пробельные разделители разрядов чисел и сумм не учитываются ни в значении, ни в запросе.

### Собственные действия

Собственное действие вызывается так же, как стандартное: имя передаётся в `action`, например `"action": "dismiss"`. Состав `payload` задаёт описание действия, ответ содержит результат обработчика, а право проверяется отдельное для каждого действия.

Объявление действий описано в разделе [«Метаданные»](metadata.md), гарантии вложенных вызовов в разделе [«Как выполняется запрос»](#как-выполняется-запрос).

### Чтение журнала

Цель чтения журнала: `{ "kind": "platform", "name": "journal" }`. Нужно отдельное право чтения журнала. Действия, параметры и результаты описаны в разделе [«Чтение журнала»](journal.md#чтение-журнала).

### Ошибки

| HTTP | Причина | Тело ответа |
|---|---|---|
| 400 | Неверные входные данные или ошибка расчёта | `error` и `fields` с путями полей |
| 401 | Пользователь не вошёл | `error` |
| 403 | Нет права на действие либо права, которое [потребовал код конфигурации](authorization.md#как-проверить-право-в-коде-конфигурации) | `error` и ключ недостающего права в `right` |
| 404 | Неизвестный объект, действие или отсутствующая запись | `error` |
| 409 | Политика конфигурации запретила изменение либо нарушено ограничение итога регистра | `error` |
| 500 | Ошибка базы или непредвиденная ошибка | `error` без текста SQL и параметров |

Пути в `fields` для входных данных действия начинаются с `payload` и разделяются точками: `payload.fields.lines.0.text` указывает поле `text` первой строки табличной части `lines`. Ошибки оболочки операции называют `операция`, `target`, `target.kind`, `target.name` или `action`; пустой пакет возвращает `fields: ["операции"]`. Ошибка проверки движений начинается с `проведение.<имя регистра>`.

## Как перенести сведения на другой ключ

Измерения записи регистра сведений меняет один пакет из двух операций: `delete` со старым ключом в `payload.dimensions` и `save` с новыми измерениями и всеми ресурсами в `payload.fields`.

Пакет возвращает результат удаления и новую запись. При ошибке любой операции старые сведения остаются на месте, новая запись не появляется.
