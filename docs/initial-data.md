# Первичные данные

При каждом запуске сервер заполняет базу данными, без которых с приложением нельзя работать: создаёт начальных пользователей, загружает справочники из выгрузок 1С и заводит случайных сотрудников. Раздел объясняет порядок этих шагов и перечисляет условия, при которых запуск останавливается.

## Когда применяются первичные данные

Шаги выполняет `InitialDataService.run`. Его вызывает `main.ts` сразу после `listen`, а не хук жизненного цикла Nest. Причина в импорте: утилита `tools/1c-xml-import` загружает справочники через HTTP API, поэтому сервер к этому моменту уже должен принимать запросы.

```text
NestFactory.create → хуки модулей (метаданные, синхронизация структуры) → listen → run
```

Пока `run` не завершился, сервер отвечает на запросы, но данные в нём неполные. Ошибка любого шага записывается в журнал запуска, после чего сервер закрывается и процесс завершается с кодом `1`: работа с частично загруженными данными не продолжается.

## Порядок шагов

Шаги собраны в один эффект. Независимые ветки идут параллельно, зависимые ждут друг друга:

```text
пользователи → ┬ импорт физических лиц → случайные сотрудники
               └ импорт номенклатуры
```

1. **Пользователи.** Пользователи из `initialUser` файла настроек или из параметров `--test-pin` создаются только в пустой таблице и получают роли. Без списка ролей пользователь получает все роли конфигурации. Имена ролей проверяются при каждом запуске.
2. **Импорт.** Для каждого из сопоставлений `physical-persons` и `nomenclature` сервер запускает утилиту импорта отдельным процессом с параметром `--local-source`. Утилита сама находит в каталоге `tools/1c-xml-import/local-source` выгрузки с нужным видом объектов. Сервер передаёт ей адрес `http://127.0.0.1:<порт>` и PIN начального пользователя через переменную окружения `COLLECTION_IMPORT_PIN`. Повторный запуск обновляет записи по внешним связям и не создаёт дубликатов; устройство импорта описано в разделе [«Импорт из универсальной XML-выгрузки 1С»](1c-xml-import.md).
3. **Случайные сотрудники.** После загрузки физических лиц сервер выбирает четырёх случайных лиц без пометки удаления и создаёт на них сотрудников с кодами `000001`–`000004`. Записи проходят через диспетчер действий одним пакетом, поэтому проверяются политики справочника и пишется журнал. Если сотрудники уже есть, шаг ничего не создаёт: иначе файловая база пополнялась бы при каждом запуске.

Импорт и создание сотрудников выполняются от имени начального пользователя со всеми ролями. Пользователь с ограниченными ролями для этого не выбирается: у него могло бы не оказаться прав на запись справочников и внешних связей.

## Условия запуска

Запуск останавливается, если не выполнено любое из условий:

| Условие | Сообщение в журнале |
|---|---|
| В настройках есть начальный пользователь без `roles` (`initialUser` или `--test-pin` без ролей) | «Для применения первичных данных нужен начальный пользователь со всеми ролями…» |
| PIN этого пользователя совпадает с сохранённым в базе, и пользователь не отключён | «Начальный пользователь не найден в базе или отключён…» |
| Утилита собрана в `tools/1c-xml-import` по [её руководству](https://github.com/EGSP/collection-zarplata/blob/main/tools/1c-xml-import/README.md) | «Не удалось запустить утилиту импорта…» |
| В `tools/1c-xml-import/local-source` есть выгрузки с физическими лицами и номенклатурой | «Импорт „…“ завершился с кодом 1: …» с текстом ошибки утилиты |
| Сервер слушает loopback-адрес: `127.0.0.1` или `0.0.0.0` | Ошибка соединения утилиты |
| Загружено не меньше четырёх физических лиц без пометки удаления, если сотрудников ещё нет | «Для 4 случайных сотрудников нужно столько же физических лиц…» |

Каталог `local-source` исключён из Git: выгрузки содержат персональные данные. В новом рабочем каталоге его нужно заполнить вручную, иначе запуск, в том числе `npm run start:check`, остановится на шаге импорта.
