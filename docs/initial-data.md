# Первичные данные

При каждом запуске сервер дополняет базу: создаёт начальных пользователей, загружает справочники из выгрузок 1С и заводит ставку собственной рассрочки. Создание случайных сотрудников для демонстрации включается настройкой `initialData.createRandomEmployees`; в обычном файловом режиме по умолчанию оно выключено. Если любое из условий ниже не выполнено, запуск останавливается.

## Когда применяются первичные данные

Шаги выполняет `InitialDataService.run`. Его вызывает `main.ts` сразу после `listen`, а не хук жизненного цикла Nest: утилита `tools/1c-xml-import` загружает справочники через HTTP API, поэтому сервер к этому моменту уже должен принимать запросы.

```text
NestFactory.create → хуки модулей (метаданные, синхронизация структуры) → listen → run
```

Пока `run` не завершился, сервер отвечает на запросы, но данные в нём неполные. Ошибка любого шага попадает в журнал запуска, сервер закрывается, процесс завершается с кодом `1`: работа с частично загруженными данными не продолжается.

## Порядок шагов

Независимые ветки идут параллельно, зависимые ждут друг друга:

```text
пользователи → ┬ импорт физических лиц → случайные сотрудники
               ├ импорт номенклатуры
               └ ставка собственной рассрочки
```

1. **Пользователи.** Пользователи из `initialUser` файла настроек или из параметров `--test-pin` создаются только в пустой таблице. Без списка `roles` пользователь получает все роли конфигурации. Имена ролей проверяются при каждом запуске, чтобы опечатка не ждала следующей новой базы.
2. **Импорт.** Для сопоставлений `physical-persons` и `nomenclature` сервер запускает утилиту отдельным процессом с параметром `--local-source`. Утилита сама находит в `tools/1c-xml-import/local-source` выгрузки нужного вида. Ей передаются адрес сервера (см. [адрес импорта](#адрес-импорта)) и PIN начального пользователя через переменную окружения `COLLECTION_IMPORT_PIN`. Повторный запуск обновляет записи по внешним связям и не создаёт дубликатов. Устройство импорта описано в разделе [«Импорт из универсальной XML-выгрузки 1С»](1c-xml-import.md).
3. **Случайные сотрудники.** При `initialData.createRandomEmployees: true` после загрузки физических лиц сервер выбирает четырёх случайных лиц без пометки удаления и создаёт сотрудников с кодами `000001`–`000004`. При `false` или отсутствии настройки шаг пропускается. Если сотрудники уже есть, шаг ничего не создаёт, иначе файловая база пополнялась бы при каждом запуске. Существующие сотрудники при выключении настройки сохраняются. Тестовые режимы `--database=memory` и `--test-database` не читают файл настроек и включают этот шаг для проверок.
4. **Ставка собственной рассрочки.** Если в справочнике «Ставки по рассрочке» нет записи «Собственная», сервер создаёт её с процентом 0. Запись с пометкой удаления считается найденной, иначе каждый запуск создавал бы новую. Ставку получает каждая собственная рассрочка, поэтому она должна быть в любой базе. Шаг не зависит от импорта.

Сотрудники и ставка записываются через диспетчер действий: проверяются политики справочника и пишется журнал.

Все шаги, кроме создания пользователей, выполняются от имени начального пользователя со всеми ролями. Пользователь с ограниченными ролями не подходит: у него может не быть прав на запись справочников и внешних связей.

## Адрес импорта

Утилита обращается к серверу по адресу, который тот слушает. Сервер, привязанный только к адресу сети магазина, не принимает соединений на `127.0.0.1`, поэтому такой адрес утилита получает как есть:

| `host` в настройках | Адрес, который получает утилита |
|---|---|
| `127.0.0.1`, `localhost`, `::1` | тот же адрес |
| `0.0.0.0`, `::` | `127.0.0.1`: сервер слушает все адреса, и loopback среди них |
| `192.168.1.71` (адрес в сети магазина) | `192.168.1.71` |

Адрес IPv6 записывается в квадратных скобках. Утилита принимает HTTP без шифрования для локального адреса: loopback и адресов сетевых интерфейсов этого компьютера. Запрос на собственный адрес система отправляет внутри машины, поэтому PIN не попадает в сеть. Адрес, которого нет среди интерфейсов компьютера, утилита отклонит с сообщением «Для удалённого сервера требуется HTTPS».

## Условия запуска

| Условие | Сообщение в журнале |
|---|---|
| В настройках есть начальный пользователь без `roles` (`initialUser` или `--test-pin` без ролей) | «Для применения первичных данных нужен начальный пользователь со всеми ролями…» |
| PIN этого пользователя совпадает с сохранённым в базе, и пользователь не отключён | «Начальный пользователь не найден в базе или отключён…» |
| Утилита собрана в `tools/1c-xml-import` по [её руководству](https://github.com/EGSP/collection-zarplata/blob/main/tools/1c-xml-import/README.md) | «Не удалось запустить утилиту импорта…» |
| В `tools/1c-xml-import/local-source` есть выгрузки с физическими лицами и номенклатурой | «Импорт „…“ завершился с кодом 1: …» с текстом ошибки утилиты |
| В `host` указан адрес этого компьютера: `127.0.0.1`, `localhost`, `::1`, `0.0.0.0`, `::` или адрес его сетевой карты | Ошибка соединения утилиты или «Для удалённого сервера требуется HTTPS» |
| При включённом `initialData.createRandomEmployees` загружено не меньше четырёх физических лиц без пометки удаления, если сотрудников ещё нет | «Для 4 случайных сотрудников нужно столько же физических лиц…» |

Каталог `local-source` исключён из Git: выгрузки содержат персональные данные. В новом рабочем каталоге его нужно заполнить вручную, иначе запуск, в том числе `npm run start:check`, остановится на шаге импорта.
