# Поставка

Поставка для Windows x64 содержит исполняемый файл приложения, файл настроек и комплект первичного импорта: утилиту, сопоставления и XML. Страница описывает сборку, развёртывание, проверку, обновление и причины выбора Node SEA. Запуск из исходников описан в разделе [«Сборка и запуск»](build-and-launch.md).

## Условия

| Место | Условия |
|---|---|
| Машина сборки | Windows x64, Node.js 24.8 или новее, npm, исходники и зависимости проекта |
| Машина запуска | Windows x64; Node.js и `node_modules` не нужны |
| Каталог поставки | Исполняемый файл и `collection-zarplata.settings.json`; относительный `databasePath` отсчитывается от этого каталога. Рядом приложение создаёт каталог `backups` с [резервными копиями](backup.md) |
| Права процесса | Чтение настроек, запись в каталог базы и во временный каталог (туда извлекается нативный модуль) |

[Скрипт упаковки](https://github.com/EGSP/collection-zarplata/blob/main/scripts/build-executable.mjs) отклоняет сборку на других системах и архитектурах.

## Как собрать исполняемый файл

В корне проекта выполните:

```powershell
npm ci
npm run build:executable
```

Команда собирает сервер, клиент и сайт документации и упаковывает их в `dist/executable/collection-zarplata.exe`. Промежуточные файлы упаковки для поставки не нужны. Утилита первичного импорта и её файлы поставляются отдельно, как описано ниже.

Если упаковка сообщает об изменении загрузчика нативного модуля Turso, подготовку поставки нужно остановить и проверить совместимость скрипта с установленной версией драйвера. Иначе выйдет файл, который не загрузит базу.

## Комплект для тестирования в магазине

Рядом с приложением и настройками положите `collection-xml-import.exe`, каталог `mappings` с файлами сопоставления и `mapping.schema.json`, а также `local-source` с XML-выгрузками. Встроенный сервер запускает утилиту из своего каталога и передаёт ей сопоставления из `mappings`; выгрузки утилита ищет рядом с собой. Node.js и Go на компьютере магазина не нужны.

Для первого входа укажите `initialUser` без `roles`: при пустой таблице пользователей создаётся администратор со всеми ролями. Используйте отдельные PIN и `pinHmacSecret` для этой установки. Параметр `initialData.createRandomEmployees` оставьте `false`, чтобы сотрудников магазина заводили вручную, а не выбирали случайно из выгрузки. Готовый комплект передаётся без базы: при первом запуске создаётся новая база и загружаются справочники.

## Как развернуть приложение

1. Скопируйте `collection-zarplata.exe` в каталог поставки.
2. Скопируйте [образец настроек](https://github.com/EGSP/collection-zarplata/blob/main/collection-zarplata.settings.example.json) рядом с ним под именем `collection-zarplata.settings.json`.
3. Укажите `host`, свободный `port` и `databasePath`. Относительный путь считается от каталога исполняемого файла, а не от рабочего каталога оболочки. Для доступа только с этой машины оставьте `host` равным `127.0.0.1`.
4. При первой установке заполните `pinHmacSecret` случайным секретом не короче 32 символов (в образце он пустой) и задайте `initialUser` для первого входа. При обновлении сохраните прежние настройки и секрет. Формат настроек и создание первого пользователя описаны в [разделе о запуске](build-and-launch.md), последствия замены секрета в разделе [«Вход в приложение»](authentication.md).
5. Запустите приложение из каталога поставки:

   ```powershell
   .\collection-zarplata.exe
   ```

Отсутствующий файл настроек или недопустимое значение останавливают запуск. Проверку выполняет [сервис настроек](https://github.com/EGSP/collection-zarplata/blob/main/src/server/settings/settings.service.ts).

## Как проверить поставку

Проверяйте файл в отдельном каталоге без исходников и `node_modules`. Чтобы не трогать рабочую базу, запустите его с пустой базой в памяти:

```powershell
.\collection-zarplata.exe --database=memory --test-pin=482915 --port=3101
```

Этот запуск не читает файл настроек. Если порт занят, выберите другой.

1. Откройте `http://127.0.0.1:3101/`: должна появиться страница входа, а файлы клиента загрузиться из исполняемого файла.
2. Войдите с PIN `482915` и откройте список справочника. Это проверяет загрузку нативного модуля и работу базы.
3. Откройте `http://127.0.0.1:3101/docs/` и любую страницу документации. Сайт должен работать без каталога `dist/docs`.
4. Остановите процесс и убедитесь, что порт свободен. Данные в памяти исчезнут.

Проверка в памяти подтверждает упаковку, но не рабочие настройки. После развёртывания запустите приложение обычным способом, войдите с PIN настроенного пользователя и убедитесь, что открыт ожидаемый файл базы.

## Как сохранить резервную копию и обновить поставку

1. Сделайте резервную копию на странице «Администрирование → Обслуживание → Резервные копии» и дождитесь её появления в списке. Приложение копирует базу на ходу, останавливать его не нужно. Копия лежит в каталоге `backups` рядом с исполняемым файлом ([подробности](backup.md)). Копировать файл работающей базы вручную нельзя: он может быть записан не полностью.
2. Сохраните копию, настройки с прежним `pinHmacSecret` (без секрета пользователи восстановленной базы не войдут со своими PIN) и, если нужно, файл базы по `databasePath`: его копируйте только после остановки приложения.
3. Остановите приложение и дождитесь завершения процесса.
4. Замените исполняемый файл новой сборкой, сохранив настройки, базу и каталог `backups`.
5. Запустите приложение, проверьте вход и данные. Миграции схемы описаны в разделе [«База данных»](database.md).
6. Если новая сборка записывает документами другие движения, [перепроведите документы](#как-перепровести-документы-после-обновления).

Миграции выполняются один раз при запуске. Две последние влияют на обновление:

- `20261015_remove_installment` удаляет документ «Рассрочка»: товар в рассрочку теперь продаётся продажей с оплатой способом «Рассрочка». Миграция стирает таблицы документа и его табличных частей, его движения в регистрах и записи журнала о нём. Необязательные ссылки на документ она очищает, записи с обязательной ссылкой удаляет. Долги и взносы по таким рассрочкам восстановить нельзя, поэтому до обновления нужна резервная копия.
- `20261016_rename_registers` переименовывает регистры: «Продажи» стали «Продажами за вычетом возвратов», «Расчёты с покупателями» стали «Долгами по рассрочкам», «Рассрочки по продажам» стали «Неоформленными рассрочками». Таблицы переименовываются вместе с данными, индексы пересоздаются, движения сохраняются, перепроводить документы не нужно.

В базе без соответствующих таблиц и документа обе миграции ничего не меняют.

## Как перепровести документы после обновления

Движения документа записывает только его проведение, поэтому документы, проведённые до обновления, сохраняют прежние движения. Например, продажи, возвраты и рассрочки, проведённые до появления регистров «Продажи за вычетом возвратов» и «Долги по рассрочкам», не имеют в них движений: итоги пусты, а возврат по такой продаже не проводится. Взносы рассрочек, принятые до появления их движений в регистре «Поступления денег», в его итоги не входят.

1. Сохраните резервную копию базы.
2. Войдите пользователем с правом перепроведения; у роли «Администратор» оно есть.
3. Выполните запросом к API [перепроведение документов](single-endpoint.md#перепроведение-документов). Кнопки в интерфейсе нет.
4. Сверьте число документов в ответе с ожидаемым и проверьте итог регистра по одному из документов.

Документы проводятся в порядке дат. Операция останавливается на первом документе, нарушающем [правила учёта](accounting-rules.md), и отменяет все свои изменения. Текст отказа называет документ: исправьте его или отмените проведение и повторите операцию. Например, операцию остановит проведённый возврат по непроведённой продаже.

Непроведённые документы операция не затрагивает. Рассрочка по продаже, принимавшая до обновления взносы без проведения, после него взносов не принимает и не показана в списке незакрытых рассрочек, пока её не провели. Такие рассрочки и продажи, по которым ожидаются возвраты, проведите обычным проведением.

## Почему используется Node SEA

Node SEA встраивает приложение и ресурсы в копию Node.js. Администратор переносит один исполняемый файл, а настройки и данные остаются отдельными файлами и сохраняются при обновлении.

esbuild объединяет сервер NestJS с зависимостями в один сценарий, Vite собирает клиент, VitePress собирает сайт документации. Упаковщик встраивает сценарий, оба сайта и нативный модуль Turso в исполняемый файл. Файлы сайтов отдают прямо из ресурсов SEA [модуль клиента](https://github.com/EGSP/collection-zarplata/blob/main/src/server/client/client.module.ts) и [модуль документации](https://github.com/EGSP/collection-zarplata/blob/main/src/server/documentation/documentation.module.ts). Страницу графа модулей из тех же ресурсов клиента отдаёт [модуль графа](https://github.com/EGSP/collection-zarplata/blob/main/src/server/modules-graph/modules-graph.module.ts).

Рабочий поток снимка базы для [резервных копий](backup.md#как-устроено-копирование) собирается отдельным сценарием `snapshot-worker.cjs` с тем же загрузчиком Turso и встраивается ресурсом SEA: потоку из исполняемого файла нечего загружать с диска. Путь к нативному модулю он берёт из `process.env`, общего для потоков процесса.

Нативный модуль нужно загрузить как файл с диска. При запуске [точка входа](https://github.com/EGSP/collection-zarplata/blob/main/scripts/executable-entry.cjs) извлекает его в `collection-zarplata/<хеш>` системного временного каталога (обычно `%TEMP%`). Хеш SHA-256 зависит от содержимого модуля. Перед повторным использованием файла точка входа сверяет хеш и при несовпадении записывает встроенную копию заново. Путь передаётся загрузчику Turso через `NAPI_RS_NATIVE_LIBRARY_PATH`.

Выбор связан с загрузкой `@tursodatabase/database`: проверенный вариант `bun build --compile` не смог загрузить нативный модуль. Это основание выбора текущего способа, а не утверждение о совместимости всех версий Bun.
