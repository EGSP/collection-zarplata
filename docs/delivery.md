# Поставка

Поставка для Windows x64 состоит из исполняемого файла приложения и отдельного файла настроек. Этот раздел описывает сборку для разработчика, развёртывание и проверку для администратора, затем объясняет упаковку в Node SEA. Запуск из исходников описан в разделе [«Сборка и запуск»](build-and-launch.md).

## Условия сборки и запуска

| Место | Условия |
|---|---|
| Машина сборки | Windows x64, Node.js 24.8 или новее, npm, исходники и зависимости проекта |
| Машина запуска | Windows x64; отдельная установка Node.js и каталог `node_modules` не нужны |
| Каталог поставки | Исполняемый файл и `collection-zarplata.settings.json`; при относительном `databasePath` файл базы располагается относительно этого каталога |
| Права процесса | Чтение настроек, запись в каталог базы и временный каталог для извлечения нативного модуля |

[Скрипт упаковки](https://github.com/EGSP/collection-zarplata/blob/main/scripts/build-executable.mjs) отклоняет сборку на других операционных системах и архитектурах. Образец настроек содержит пустой секрет: перед запуском его нужно заполнить.

## Как собрать исполняемый файл

В корне проекта выполните команды последовательно:

```powershell
npm ci
npm run build:executable
```

Команда собирает сервер, клиент и сайт документации, затем упаковывает их. Результат находится в `dist/executable/collection-zarplata.exe`. Для поставки нужен этот файл; промежуточные файлы из `dist/executable` переносить не требуется.

Если упаковка сообщает об изменении загрузчика нативного модуля Turso, остановите подготовку поставки и проверьте совместимость скрипта с установленной версией драйвера. Эта проверка защищает от выпуска файла, который не сможет загрузить базу данных.

## Как развернуть приложение

1. Скопируйте `collection-zarplata.exe` в каталог поставки на машине запуска.
2. Скопируйте [образец настроек](https://github.com/EGSP/collection-zarplata/blob/main/collection-zarplata.settings.example.json) рядом с исполняемым файлом под именем `collection-zarplata.settings.json`.
3. Укажите адрес `host`, свободный порт `port` и путь `databasePath`. Относительный путь считается от каталога исполняемого файла, независимо от рабочего каталога оболочки. В образце база называется `collection-zarplata.db` и лежит рядом с приложением. Для доступа только с этой машины оставьте `host` равным `127.0.0.1`.
4. При первой установке заполните `pinHmacSecret` случайным секретом длиной не меньше 32 символов и задайте `initialUser` для первого входа. При обновлении сохраните прежние настройки и секрет. Формат и создание первого пользователя описаны в [настройках запуска](build-and-launch.md), последствия замены секрета в разделе [«Вход в приложение»](authentication.md).
5. Откройте PowerShell в каталоге поставки и запустите приложение:

   ```powershell
   .\collection-zarplata.exe
   ```

При обычном запуске приложение читает настройки рядом с исполняемым файлом и открывает базу по `databasePath`. Отсутствующий файл настроек или недопустимое значение останавливают запуск. Чтение и проверка настроек реализованы в [сервисе настроек](https://github.com/EGSP/collection-zarplata/blob/main/src/server/settings/settings.service.ts).

## Как проверить поставку

Проверяйте файл в отдельном каталоге без исходников и `node_modules`. Для проверки упаковки используйте пустую базу в памяти, чтобы не открывать рабочую базу и не создавать постоянного пользователя:

```powershell
.\collection-zarplata.exe --database=memory --test-pin=482915 --port=3101
```

Этот запуск не читает файл настроек. Если порт занят, выберите другой, отличный от портов работающих экземпляров приложения.

1. Откройте `http://127.0.0.1:3101/`. Должна появиться страница входа; файлы клиента должны загружаться из исполняемого файла.
2. Войдите с PIN `482915` и откройте список справочника. Успешный вход и чтение данных проверяют загрузку нативного модуля и работу базы.
3. Откройте `http://127.0.0.1:3101/docs/` и одну из страниц документации. Сайт должен работать без внешнего каталога `dist/docs`.
4. Остановите проверочный процесс и убедитесь, что выбранный порт свободен. Данные базы в памяти исчезнут после остановки.

Проверка в памяти подтверждает упаковку, но не проверяет настройки рабочей установки. После развёртывания запустите приложение обычным способом, откройте его по выбранному адресу и войдите с PIN настроенного пользователя. Убедитесь, что используется ожидаемый файл базы.

## Как сохранить резервную копию и обновить поставку

1. Остановите приложение и убедитесь, что его процесс завершился. Копирование файла работающей базы не является описанным здесь способом резервного копирования.
2. Скопируйте файл базы по фактическому `databasePath` в каталог резервных копий. Сохраните рядом копию настроек, включая прежний `pinHmacSecret`: без этого секрета пользователи восстановленной базы не смогут войти с прежними PIN.
3. Замените исполняемый файл новой сборкой, сохранив настройки и рабочую базу.
4. Запустите приложение и проверьте вход и доступ к данным. Если новая сборка требует миграции схемы, следуйте разделу [«База данных»](database.md).

## Почему используется Node SEA

Node SEA встраивает приложение и его ресурсы в копию Node.js. Поэтому администратор переносит один исполняемый файл, а настройки и данные остаются отдельными файлами, которые сохраняются при обновлении.

esbuild объединяет сервер NestJS и его зависимости в один сценарий. Vite собирает клиент, VitePress собирает сайт документации. Упаковщик встраивает сценарий, оба сайта и нативный модуль Turso в исполняемый файл. [Модуль клиента](https://github.com/EGSP/collection-zarplata/blob/main/src/server/client/client.module.ts) и [модуль документации](https://github.com/EGSP/collection-zarplata/blob/main/src/server/documentation/documentation.module.ts) отдают файлы сайтов непосредственно из ресурсов SEA.

Нативный модуль нужно загрузить как файл с диска. При запуске [точка входа](https://github.com/EGSP/collection-zarplata/blob/main/scripts/executable-entry.cjs) извлекает его в подкаталог `collection-zarplata/<хеш>` системного временного каталога Windows, обычно `%TEMP%`. Хеш SHA-256 зависит от содержимого модуля. Перед повторным использованием файла точка входа сверяет его хеш и при несовпадении записывает встроенную копию заново. Путь передаётся загрузчику Turso через `NAPI_RS_NATIVE_LIBRARY_PATH`.

Выбор Node SEA связан с загрузкой нативного модуля `@tursodatabase/database`: проверенный вариант `bun build --compile` не смог его загрузить. Это основание выбора текущего способа поставки, а не утверждение о совместимости всех версий Bun.
