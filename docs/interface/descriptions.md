# Описания интерфейса

`GET /api/metadata` требует сессию и возвращает `{ objects, pages, shell, userName }`. Пользователь получает описания объектов, которые может читать, и страниц, которые может открывать. `pages` содержит имя, заголовок и необязательный значок страницы. `userName` содержит имя вошедшего пользователя из учётной записи. Формат `shell` описан в [схеме оболочки](shell.md#схема-оболочки).

Типы ответа объявлены в [`descriptions.ts`](https://github.com/EGSP/collection-zarplata/blob/main/src/server/ui/descriptions.ts). Имена полей, частей и действий из ответа используются в [API данных](../single-endpoint.md).

## Объект и форма

`ObjectView` содержит `kind`, `name`, `title`, `presentation`, `form`, `list`, `tableParts`, `lookup` и `functions`. Верхнеуровневый `tableParts` перечисляет части независимо от раскладки формы. `presentation: null` означает собственное представление объекта. У регистра `form: null`. `lookup` описывает колонки подбора или равен `null`, если объект подбор не объявил.

`functions` содержит доступные [функции объекта](../metadata.md#функции-объектов). У функции есть `name`, `title`, `input` и `tableParts`. Входные поля и части имеют тот же формат, что у собственного действия.

| Свойство `FormView` | Содержимое |
|---|---|
| `fields` | Поля в порядке объявления. Описание поля задаёт имя, вид, доступ, ограничения и настройки ввода |
| `tableParts` | Именованные части с описаниями колонок и необязательной заменой компонента ввода |
| `groups` | Группы раскладки. Строка в `elements` обозначает поле или часть, `{ element }` обозначает собственный элемент. Каждое поле и часть раскладки входят ровно в одну группу |
| `traversal` | Имена полей и частей в порядке клавиатурного обхода |
| `actions` | Доступные стандартные и собственные действия. У собственных есть входные поля, части, место показа и необязательное подтверждение |
| `calculations` | Поля и части для расчётов, включая скрытые в раскладке |
| `creationMode` | Место открытия новой записи по умолчанию. `tab` открывает вкладку, `dialog` открывает окно |

Описание поля (`FormField`) передаёт `name`, `title`, `kind`, `target`, `readOnly` и `rules`. Для конкретных видов оно добавляет перечень `choices`, начальное значение `initial`, вычисление `computed`, подсказки `suggestions`, варианты `variants` и режим `inputMode`. Ввод и отображение описаны в [Web SDK](../web-sdk/fields.md).

`access` задаёт доступ к публичному полю. Недоступное значение исключается из записи, а карта `$access` отличает недоступное поле от пустого. `readOnly` обозначает, например, номер, состояние проведения и вычисляемые поля. Внутренние поля в описание не входят. [Права на поля](../authorization.md).

`rules` передаёт обязательность, границы длины и числа и признак целого числа. Длина строки считается в единицах UTF-16, как `String.length`. Денежные значения и их границы передаются в копейках.

## Список

| Свойство `ListView` | Содержимое |
|---|---|
| `columns` | Колонки с типами полей. Для измерений и ресурсов регистра задан `role` |
| `filters` | Поля отбора и допустимые `operators`. У составного поля также передаются варианты и `inputMode` |
| `sortable` | Поля, по которым разрешена сортировка |
| `defaultSort` | Справочники идут по наименованию, документы по дате и номеру от новых к старым, движения от новых к старым, сведения по измерениям в порядке объявления |
| `deletionMark` | Поддержка пометки удаления |
| `tableParts` | Имена частей, доступных для раскрытия строки |

Используйте операторы из `filters` при вызове `list`. Для `contains` регистр букв не важен, а `%` и `_` считаются обычными символами. Составное значение отбора содержит тип варианта. [Формат отбора](../single-endpoint.md#отбор-по-полю).
