# Формы записей

## Выбор формы и место показа

Для каждого объекта клиент отдельно выбирает список, форму новой записи и форму существующей записи. По умолчанию он показывает стандартный список или стандартную форму записи. Конфигурация может заменить любой из трёх видов через [формы объекта](../metadata.md#формы-объекта).

Форма записи получает `presentation: 'page'` во вкладке и `presentation: 'dialog'` в окне. Список открывается во вкладке. Настройка `.form(...).creation(...)` задаёт место создания по умолчанию, а вызов [`useOpenRecord`](../web-sdk/hooks.md#область-окна-и-открытие-записи) может выбрать режим сам. Прямой адрес новой записи открывает вкладку.

Собственная форма подключает [`useRecordFormContract`](../web-sdk/hooks.md#контракт-формы-записи) ровно один раз, напрямую или через `useRecordForm`. Контракт передаёт [области окна](shell.md#область-окна) состояние и результат записи. При отсутствии контракта или двойном подключении область показывает ошибку.

## Переопределение формы

Билдер `.form(...)` меняет стандартную раскладку. Без настройки поля и части идут в порядке объявления в одной группе без заголовка.

| Настройка | Результат |
|---|---|
| `group(title, elements)` | Собирает элементы в заданном порядке. Остальные попадают в заключительную группу без заголовка |
| `hide(name)` | Убирает поле или часть из раскладки и клавиатурного обхода |
| `title(name, title)` | Меняет подпись на форме |
| `creation(mode)` | Задаёт `tab` или `dialog` для создания. Режим задаётся один раз |

Подключения `defineFormComponent` добавляют собственный блок или заменяют ввод поля либо части. Замена сохраняет имя, подпись и место в раскладке. При запуске сервер отклоняет несуществующую группу, замену скрытого места и двойную замену. [Элементы формы](../metadata.md#элементы-формы) · [Компоновка полей](../web-sdk/components.md#компоновка-полей).

## Начальные значения

Для новой записи `initial` из вызова открытия имеет приоритет над значениями по умолчанию. Обязательный флажок по умолчанию снят, обязательное поле `dateTime` получает текущий момент, поле `date` остаётся пустым. Строковое значение из описания применяется также к новой строке табличной части. Номер документа и другие служебные значения назначаются при записи.

## Доступность и проверка

Без `save` в описании форма открывается для просмотра. Собственные элементы могут временно отключать поля, части, форму целиком или скрывать действия через [ограничения SDK](../web-sdk/hooks.md#ограничения-формы). Форма объединяет ограничения. Временно недоступное поле сохраняет своё значение, скрытое действие недоступно и с клавиатуры. Права сервера описаны в [правилах доступа](../authorization.md).

Действие `save` получает полную запись. При изменении форма объединяет введённые значения с загруженной записью, чтобы сохранить поля, скрытые раскладкой.

Форма проверяет данные до отправки. При отказе она сохраняет ввод и показывает сообщение сервера. Пути `fields` из ответа `400` отмечают ошибочные поля и ячейки. Вычисляемые поля обновляются при изменении зависимых значений и доступны для чтения. Сервер повторяет расчёт и проверку перед сохранением.

## Действия и результат записи

Действия берутся из описания формы и учитывают состояние записи. Например, отмена проведения доступна у проведённого документа. `placement` управляет местом собственного действия. `buttons` выводит кнопку, `more` помещает действие в меню «Ещё», `hidden` оставляет его для вызова кодом экрана. Команда `opens: 'journal'` открывает [журнал](../journal.md#просмотр-из-карточки).

Действие записи применяется к текущим значениям. Перед другим действием форма сохраняет несохранённые изменения и затем вызывает действие с `guid`. Если действие отклонено после успешной записи, запись уже сохранена, форма остаётся открытой. После изменяющего действия SDK помечает кеш данных как устаревший, чтобы открытые списки и ссылки перечитали результат.

Кнопка действия с входными данными открывает окно с полями и частями из описания. Экран может передать значения сам через SDK. В ошибках действия путь строки начинается с `payload.lines.0`, при записи путь начинается с `payload.fields.lines.0`. Действие в меню «Ещё» подставляет `guid` текущей записи во входные ссылки на тот же объект. `confirmation` задаёт подтверждение в интерфейсе. [Выполнение действий в SDK](../web-sdk/hooks.md#выполнение-действий) · [Подтверждение действия](../web-sdk/components.md#подтверждение-действия).

## Работа с клавиатуры

`Enter` и `Shift+Enter` обходят редактируемые поля по `traversal`. Элемент, заменяющий поле, принимает фокус по контракту поля ввода. Элемент группы без назначенного поля в обход не входит. При входе в пустую табличную часть создаётся первая строка. После последней ячейки обход продолжится в следующей строке, а если её ещё нет, создаст её. Обратный обход из первой ячейки возвращает в предыдущую строку или поле формы.

| Сочетание | Действие активной формы |
|---|---|
| `Ctrl+S` | Записать |
| `Ctrl+Enter` | Провести и закрыть после успеха |
| `Esc` | Закрыть с проверкой несохранённых изменений |

Открытый выбор, календарь или окно действия получают клавиши первыми. Сочетания формы доступны для тех же действий, что и кнопки. Пока запрос выполняется, повторное нажатие его не дублирует. [Клавиатура в ячейках](../components.md#ячейка-табличной-части).
