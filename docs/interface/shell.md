# Оболочка и навигация

## Схема оболочки

`shell()` задаёт рабочие места и подсистемы. Рабочее место ведёт на страницу конфигурации. Подсистема содержит группы со списками объектов и страницами. Пункты идут в порядке объявления. В примере `SellerWorkplace`, `Employees` и `Shift` обозначают импортированные билдеры конфигурации.

```ts
export const applicationShell = shell()
    .workplaces([SellerWorkplace])
    .subsystem('masterData', (subsystem) => subsystem
        .title('НСИ')
        .icon('referenceData')
        .group('Справочники', [Employees])
        .group('Документы', [Shift]));
```

Одну страницу или объект можно включить в несколько групп. Повторный `workplaces(...)` добавляет страницы к перечисленным. Значок выбирается по назначению из [реестра SDK](../web-sdk.md#иконки-и-пиктограммы). Объект или страницу вне схемы можно открыть по адресу, если у пользователя есть доступ.

`GET /api/metadata` возвращает схему в свойстве `shell`.

```json
{
  "workplaces": ["sellerWorkplace"],
  "subsystems": [{
    "name": "masterData",
    "title": "НСИ",
    "icon": "referenceData",
    "groups": [
      { "title": "Справочники", "items": [{ "kind": "catalog", "name": "employees" }] },
      { "title": "Документы", "items": [{ "kind": "document", "name": "shift" }] }
    ]
  }]
}
```

`workplaces` содержит имена страниц. У пункта `kind` равен виду объекта или `page`. Заголовки пунктов берутся из `objects` и `pages`, `icon` у подсистемы необязателен. Сервер исключает недоступные пункты и рабочие места, пустые группы и подсистемы.

Имя вошедшего пользователя выводится над версиями платформы и конфигурации внизу развёрнутой боковой панели. На `sm` оно входит в заголовок выдвижной панели в формате «Меню - Имя пользователя».

## Группы оболочки

Клиентские группы добавляют компоненты на главный экран (`ShellGroups.home`) и над стандартным списком (`ShellGroups.list(Objects.<вид>.<имя>)`). Они объявляются отдельно от серверной схемы и отсутствуют в `GET /api/metadata`.

`defineShellGroups` принимает записи с `parent` и `content`. Содержимым может быть компонент или вложенная группа. `shellGroup(name, orientation)` объявляет группу с уникальным именем и раскладкой `vertical`, `horizontal` или `grid`. Порядок записей задаёт порядок показа, пустые группы места не занимают. Циклы, повторный родитель и разные ориентации одного имени приводят к ошибке загрузки. В `grid` вложенная группа занимает всю строку. В одном ряду помещается один компонент на `sm`, два на `md` и четыре начиная с `lg`.

Чтобы компонент монтировался только при доступе к нужным объектам, перечислите их в `requiredObjects`. При собственной проверке сначала прочитайте описание через `useObjectView`, затем монтируйте компонент, который запрашивает данные.

## Адреса

| Адрес | Что открывает |
|---|---|
| `/` | Главный экран |
| `/<вид>/<имя>` | Список объекта |
| `/<вид>/<имя>/new` | Форму новой записи |
| `/<вид>/<имя>/<guid>` | Форму существующей записи |
| `/page/<имя>` | Страницу конфигурации |

Страница конфигурации должна быть в ответе сервера и в реестре клиента. Неизвестное или недоступное имя даёт «не найдено». Без сессии по запрошенному адресу показывается вход. После входа открывается запрошенная страница, после явного выхода приложение возвращается на главный экран. [Как работает сессия](../authentication.md).

## Вкладки открытых окон

Путь адреса определяет вкладку. Новый путь открывает её, путь открытой вкладки активирует её. Строка запроса принадлежит вкладке и сохраняет состояние списка при переключении. Страница скрытой вкладки остаётся смонтированной, поэтому форма сохраняет введённое, а список сохраняет поиск и отбор. Глобальные сочетания обрабатывает активная область.

Вкладка новой записи после сохранения получает адрес созданной записи. Закрытие активной вкладки выбирает соседнюю слева или главный экран. После перезагрузки восстанавливаются главный экран и текущий адрес. Оформление и управление полосой описаны в [компонентах](../components.md#полоса-вкладок).

## Область окна

Страница передаёт ближайшей области заголовок, несохранённые изменения и результат записи. Область решает, где показать заголовок, как обработать результат и можно ли закрыть страницу. Вкладка, главный экран и модальное окно предоставляют один контракт. Компоненты работают с ним через [хуки Web SDK](../web-sdk/hooks.md#область-окна-и-открытие-записи).

Проверка несохранённых изменений охватывает вложенные окна, закрытие вкладки приложения и выход. При закрытии страницы браузера используется подтверждение браузера. Переключение вкладки оставляет введённые значения в её области.

## Модальные окна

Модальное окно формы принадлежит области, из которой его открыли, и видно вместе с ней. У него нет собственного адреса. После успешного создания окно возвращает `guid` вызвавшему коду. Начальные значения и результат открытия описаны в [`useOpenRecord`](../web-sdk/hooks.md#область-окна-и-открытие-записи).

Крестик и `Esc` запускают обычное закрытие с проверкой несохранённых изменений. Нажатие на фон окно не закрывает. Пока выполняется собственное действие, его окно остаётся открытым. При отказе сервера оно показывает ошибку и снова допускает закрытие.
