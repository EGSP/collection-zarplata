# Списки и ссылки

Стандартный список открывается по адресу `/<вид>/<имя>` и строится из [описания списка](descriptions.md#список). Список можно заменить [формой объекта](../metadata.md#формы-объекта).

## Поиск, отбор и сортировка

Поиск ищет фрагмент по видимым колонкам и действует вместе с отбором. При изменении поиска список возвращается на первую страницу, сохраняя отборы и сортировку. Условия отбора соединяются через «и». Условие без значения не применяется. Составной отбор хранит значение вместе с типом, поэтому число `100` и строка «100» различаются.

Поиск, отбор, сортировка и страница хранятся в адресе вкладки. Закладка и перезагрузка восстанавливают то же состояние. [Формат поиска и отбора](../single-endpoint.md#отбор-по-полю).

## Действия списка

Двойной щелчок по строке открывает её запись. Ссылка в колонке открывает запись, на которую она указывает. Для обоих переходов применяется [правило открытия записи](../metadata.md#правило-открытия-записи).

Создание предлагается при наличии `save` в описании формы. Режим вкладки или окна берётся из [настройки формы](forms.md#переопределение-формы). Пометка удаления остаётся признаком строки. Поставить или снять её можно при наличии соответствующего действия. Списки регистров доступны для просмотра. Ссылка регистратора ведёт на документ.

Если объект объявил видимые части, строку можно раскрыть. Данные частей читаются при раскрытии отдельным `get`. `list` возвращает страницу без массивов частей. Признак раскрытия всей страницы сохраняется в адресе как `expandTableParts=true`.

Компонент группы стандартного списка может скрыть создание или действия строки через `useListControls`. Ограничения нескольких компонентов объединяются в пределах одного списка. Серверные права задаются отдельно.

```ts
useListControls({ hideCreate: true, hiddenRowActions: ['markDeleted', 'unmarkDeleted'] });
```

## Представления записей

Пользователь видит представление записи вместо её `guid`. Обычно это наименование справочника или вид, номер и дата документа. Конфигурация может задать [представление по ссылке или из частей](../metadata.md#представление-из-частей).

`list` отдаёт представления вместе со страницей, `get` возвращает `$presentation`. Заголовок формы и подпись ссылки используют общий формат. Клиент объединяет одновременные чтения ссылок в пакет `get` и переиспользует сохранённые ответы запросов. Выбор ссылки на форме описан в [полях Web SDK](../web-sdk/fields.md#поле-ссылки).

## Доступ к данным из клиента

Ресурс Refine задаётся парой вида и имени, например `catalog.sample`. Поставщик данных переводит методы Refine в [операции API](../single-endpoint.md).

| Метод | Операция |
|---|---|
| `getList` | `list` с отбором, сортировкой, поиском и страницей |
| `getOne` / `getMany` | `get` одной записи или пакет чтений |
| `create` / `update` | `save` без `guid` или с `guid` |
| `deleteOne` | `markDeleted` |
| `custom` | Операция, указанная ресурсом и именем действия |

Сравнения Refine преобразуются в операторы API. `and` разворачивается в список условий, `or` и неподдерживаемые операторы приводят к ошибке. В серверном режиме читается одна страница. Если вызывающий код запросил все записи, поставщик собирает их постранично. Экран конфигурации обращается к данным через [хуки Web SDK](../web-sdk/hooks.md#чтение-данных).
