# Web SDK

Страница для тех, кто пишет собственные экраны клиента: страницы конфигурации, элементы форм и компоненты групп оболочки. Как сервер описывает формы и списки, рассказано в разделе [«Интерфейс (SDUI)»](interface.md).

Web SDK (`src/web/sdk`) служит публичным контрактом клиента. Экран импортирует возможности платформы только из точки входа `src/web/sdk/index.ts`; остальные модули `src/web` внутренние и могут меняться без предупреждения. Стандартная форма записи `StandardRecordForm` лежит в самом SDK, а стандартный список объекта (`src/web/lists/`) собран из SDK; по ним удобно смотреть приёмы.

## Границы SDK

В SDK входит только то, что связано с платформой: данные, права, описания объектов, область окна, фокус. Раскладку (сетку `Grid` и `Column`, стек `Stack`) экран берёт из слоя `ds` по правилам [«Компонентов и раскладки»](components.md): компонент заполняет выделенное место и не задаёт себе ширину. Остальные элементы и типографику экран берёт из Ant Design напрямую, обёрток для них нет.

Хуки данных SDK — единственный путь экрана к API. Хуки Refine и `/api/perform` экран не вызывает: сброс сохранённых ответов сервера после действия и показ ошибок должны оставаться в одном месте.

Экран пишется функциональными компонентами и хуками. Базовых классов нет: классовый компонент не может вызывать хуки, на которых построен клиент.

Если экрану не хватает элемента или хука, который пригодится и другим экранам, его добавляют в SDK, а не пишут на месте.

## Слои SDK

Каталог `src/web/sdk` делится на `ds` (основа дизайн-системы: сетка, стек, иконки, пиктограммы, плитка) и `platform` (блоки платформы: хуки данных, формы, списки, группы оболочки). Слои `derivations` и `external` предусмотрены под компоненты, собранные из `ds`, и под исключения из правил раскладки; каталогов у них пока нет. Что кладётся в каждый слой, описано в разделе [«Компоненты и раскладка»](components.md#слои-sdk). Экран слои не видит: все экспорты идут через `index.ts`.

## Как подключить собственный экран

1. Объявите страницу или элемент формы в конфигурации по правилам [метаданных](metadata.md#страницы-конфигурации).
2. Импортируйте возможности платформы из `src/web/sdk/index.ts`. Для точных типов записи и действий используйте `Objects.<вид>.<имя>` из `objects.generated.ts`. Серверные модули допускаются только в импортах типов.
3. Читайте и изменяйте данные [хуками SDK](web-sdk/hooks.md). Раскладку стройте на `Grid`, `Column` и `Stack`, остальные элементы берите из Ant Design, значки из [реестров](#иконки-и-пиктограммы).
4. Для собственного экрана с формой поставьте `FormDataProvider` внутри формы Ant Design. Если элементы объявляют ограничения, передайте ему учёт `useFormRestrictionRegistry`.
5. Чтобы заменить список или форму записи объекта, объявите [форму объекта](metadata.md#формы-объекта). Форму записи собирайте из `useRecordForm` и частей раскладки или возвращайте `StandardRecordForm` ([«Компоненты»](web-sdk/components.md#стандартная-форма-и-её-части)); форма записи обязана подключить [контракт с областью окна](web-sdk/hooks.md#контракт-формы-записи).
6. Выполните `npm run typecheck`: он проверяет и границы импортов. Откройте экран в приложении с нужными правами.

Объявление страницы описано в [«Страницы конфигурации»](metadata.md#страницы-конфигурации), установка элемента в [«Элементы формы»](metadata.md#элементы-формы), замена списка и формы в [«Формы объекта»](metadata.md#формы-объекта). Элемент на месте поля ввода собирайте функцией `fieldInput`: он обязан поддержать [обе компоновки](web-sdk/components.md#компоновка-полей) поля, иначе проверка типов его отклонит.

## Иконки и пиктограммы

Значки экран берёт только из двух реестров и выбирает по смыслу, а не по рисунку. Тогда одно действие выглядит одинаково на всех экранах, а рисунок меняется в одном месте.

| Реестр | Что в нём | Источник рисунков |
|---|---|---|
| `Icons` | Иконки действий, состояний и видов объектов, способов оплаты и типов рассрочки, раскрытия и сворачивания группы строк (`expand`, `collapse`), изменения записи (`edit`) и окна подтверждения (`confirmDanger`, `confirmWarning`, `confirmInfo`) | `@ant-design/icons`; пакет импортирует только реестр |
| `Pictograms` | Крупные рисунки разделов для плиток, в том числе `salary` для зарплаты и `report` для отчётов | Пиктограммы Carbon, встроенные как SVG |

Пиктограммы взяты из Carbon, потому что иконки Ant Design при крупном размере выглядят жирными. Если нужного смысла в реестре нет, в него добавляют запись. У иконки без подписи рядом должны быть название для чтения с экрана и подсказка.

Для действий присоединённой рассрочки реестр содержит `Icons.acceptPayment` (приём взноса) и `Icons.closeInstallment` (подтверждение закрытия). Значки меняются в реестре, компоненты конфигурации импортируют их через SDK.

## Типизация объектов

Хуки и компоненты принимают объект двумя способами:

- **Описание с сервера** (`ObjectView`) типов записи не несёт: записи общего типа, имена полей и действий остаются строками. Так работают стандартные список и форма.
- **Ссылка на объект** `Objects.<вид>.<имя>` несёт тип строки списка, тип записи и имена действий. По ней компилятор проверяет колонки `RecordTable`, поля сортировки и постоянного отбора `useRecordList` вместе с типом значения, имя действия у `ActionButton` и `useAction`. Опечатка в имени не собирается.

Условия отбора и сортировку хуки списка и записи принимают в формате действия `list`, тех же типов, что в описании списка. Типы Refine в контракт SDK не входят.
