# Компоненты Web SDK

`RecordLink` показывает представление исходной ссылки, а форму открывает через общий серверный [выбор цели](../interface.md#открытие-существующей-записи). Shift-клик открывает оригинал; значение ссылки от перехода не меняется.

`ActionDialog` ведёт ввод независимо от недоступности родительской формы: например, взнос доступен из продажи, открытой для просмотра. Поля самого окна блокируются только на время выполнения его запроса.

Для поля вида `date` компонент `FieldInput` принимает свойство `dateLimits` с необязательными границами `minimum` и `maximum`. Границы включительны и задаются строками `YYYY-MM-DD`: даты вне них остаются видимыми в календаре, но не выбираются и не подтверждаются вводом с клавиатуры. Например, `minimum: '2026-10-16'` исключает закрытый период по 15 октября включительно. Значение поля остаётся в формате сервера.

Окно `ActionDialog` принимает `dateLimits` по именам входных полей. Например, значение свойства для поля `closedThrough`:

```ts
{ closedThrough: { minimum: '2026-10-16', maximum: '2026-10-18' } }
```

Окно ограничивает календарь и проверяет значение перед отправкой формы, в том числе если границы изменились после открытия окна. Эти ограничения помогают выбрать допустимую дату; серверные бизнес-правила остаются обязательными.

## Каркас страницы

`Page` сообщает области окна свой заголовок; `windowTitle` задаёт области другой заголовок или отключает его. В модальном окне каркас выводит заголовок с отметками в шапку окна, а кнопки вниз. Иначе у окна было бы два заголовка, а кнопки уезжали бы при прокрутке.

Свойство `model` выбирает ширину страницы: `high-density` (по умолчанию) занимает всю область, `product` не шире 1584 px и прижата влево. В модальном окне модель не действует. `RecordFormPage` выводит формы записей с `model="product"`; подробнее в [«Компонентах и раскладке»](../components.md#модели-страницы).

## Таблица записей

`RecordTable` показывает выбор строки, но не хранит его: выбранную строку экран передаёт таблице сам и узнаёт о новом выборе из её обработчика.

## Кнопка действия

`ActionButton` не выводится, если действия нет в описании формы объекта, то есть у пользователя нет на него права. Не выводится и действие, неприменимое к записи в её состоянии: из пары «Пометить на удаление» и «Снять пометку удаления» применимо одно, отмена проведения применима только к проведённому документу. Если у собственного действия есть входные данные, кнопка сначала открывает окно с их полями. Экран может передать входные данные сам, тогда окно не открывается.

Если у действия есть `confirmation`, кнопка перед выполнением открывает [окно подтверждения](#подтверждение-действия): после окна входных данных, если оно есть. Отказ действие не выполняет и не считается ошибкой.

Действие `save` кнопка сама не выполняет: значения полей знает только форма. Экран заменяет выполнение своим, а кнопка сохраняет проверку прав, окно входных данных и признак ожидания. Так устроена стандартная форма: перед действием она записывает несохранённые изменения.

### Подтверждение действия

`ActionConfirmationDialog` показывает окно по `FormAction.confirmation` (`delay`, `title`, `message`, `tone`). Без `title` заголовком служит вопрос с названием действия. Кнопки «Подтверждаю», «Отмена» и крестик:

- «Подтверждаю» недоступна до конца задержки, на ней идёт обратный отсчёт в секундах;
- «Отмена», крестик и Esc доступны сразу, закрытие нажатием на затемнённую область отключено;
- при открытии фокус стоит на «Отмена», а Enter во время отсчёта не обрабатывается;
- каждое открытие окна начинает отсчёт заново;
- `tone` задаёт значок (`confirmDanger`, `confirmWarning`, `confirmInfo` из `Icons`); у `danger` кнопка подтверждения красная.

Свой экран запрашивает подтверждение хуком `useActionConfirmation()`: он возвращает `confirm(action)` и `dialog`. `confirm` возвращает `Promise<boolean>`: для действия без `confirmation` ответ `true` приходит сразу, окно не открывается. Элемент `dialog` экран выводит в своей разметке.

```tsx
const confirmation = useActionConfirmation();
const run = async () => {
    if (await confirmation.confirm(action)) await state.run(action, input);
};
return <>{confirmation.dialog}<Button onClick={() => void run()}>{action.title}</Button></>;
```

Подтверждение работает только в интерфейсе: сервер выполняет действие, вызванное через API, без него.

## Стандартная форма и её части

`StandardRecordForm` выводит форму записи или новой записи по описанию формы: каркас страницы, отметки состояния, кнопки действий и все группы полей. Она собрана из `useRecordForm` ([«Хуки»](hooks.md#контракт-формы-записи)) и частей, а область окна показывает её, если конфигурация не заменила форму [формой объекта](../metadata.md#формы-объекта). Принимает свойства `RecordFormProperties` или `NewFormProperties`.

Собственной форме, которой в одном из мест показа менять нечего, достаточно вернуть стандартную:

```tsx
export default function SampleNewForm(properties: NewFormProperties) {
    if (properties.presentation === 'dialog') return <StandardRecordForm {...properties} />;
    return <SampleNewPage {...properties} />;
}

function SampleNewPage(properties: NewFormProperties) {
    const state = useRecordForm(properties);
    return (
        <RecordFormPage state={state}>
            <Alert type="info" showIcon title="Строки и оплату можно заполнить и после записи документа" />
            <RecordFormLayout state={state} />
        </RecordFormPage>
    );
}
```

Ветвление стоит до `useRecordForm`. Стандартная форма подключает контракт с областью окна сама, и если бы собственная форма вызвала `useRecordForm` до ветвления и затем вернула `StandardRecordForm`, контракт подключился бы дважды и область показала бы ошибку. Поэтому собственная раскладка выносится в отдельный компонент, как `SampleNewPage`. Место показа за время жизни формы не меняется, так что ветвление по `presentation` не нарушает порядок хуков.

### Части формы

Части получают состояние хука свойством `state` и заменяются по отдельности. Например, форма выводит свои группы, а кнопки и каркас берёт стандартные.

| Часть | Что выводит |
|---|---|
| `RecordFormPage` | Каркас `Page`: заголовок по представлению записи, отметки, кнопки и тело формы с содержимым `children` |
| `RecordFormBody` | Форма Ant Design со значениями, `FormDataProvider` и перехват клавиш для обхода полей. Поля выводятся внутри тела |
| `RecordFormLayout` | Группы полей по описанию формы; свойство `groups` выбирает показываемые группы, по умолчанию выводятся все. У новой записи служебные поля не выводятся, пустая группа тоже |
| `RecordFormActions` | «Провести и закрыть», видимые действия, меню «Ещё» для журнала и действий с местом показа «Ещё» и «Закрыть»; подписи заменяет свойство `titles`, набор кнопок действий свойство `buttons` |
| `RecordFormMarks` | Отметки «Помечен на удаление» и «Проведён» |

Меню «Ещё» строится по команде `opens: 'journal'` в серверном списке `form.actions` и по собственным действиям с `placement: 'more'` (`state.menuActions`). Действие меню выполняется через форму после подтверждения, если оно требуется. Окна входных данных у меню нет: действие получает `guid` записи в каждом поле-ссылке на объект формы. Кнопками выводятся только действия с `placement: 'buttons'`. Свойство `buttons.actions` выбирает кнопки изменения записи и не скрывает служебную команду просмотра. У новой записи просмотр недоступен до сохранения. Собственная форма получает то же меню, если использует `RecordFormActions` или `RecordFormPage`.

У новой записи `RecordFormLayout` пропускает служебные поля: только для чтения и не вычисляемые, например номер документа и «Проведён». Их значение назначит запись, вводить его нечего. Если в группе не осталось элементов, она не выводится. Собственная раскладка получает тот же отбор от `recordFormElements(state, items)`: функция принимает элементы группы по именам и возвращает элементы для `FieldGroup` без служебных полей новой записи.

### Подписи кнопок

Окно может называть действия иначе, чем вкладка: открытие новой смены записывает документ, но продавцу «Записать» ни о чём не говорит. Свойство `titles` у `RecordFormPage` и `RecordFormActions` (тип `RecordFormTitles`) заменяет подписи:

```tsx
<RecordFormPage state={state} titles={{ actions: { save: 'Открыть' }, close: 'Отменить' }}>
```

`actions` сопоставляет имени действия подпись, `postAndClose` подписывает «Провести и закрыть», `close` подписывает «Закрыть». Подпись меняет только показ: кнопку, подсказку и `aria-label`. Действие, права, сочетания клавиш и уведомления остаются прежними.

### Набор кнопок

Собственная форма, которая выводит своё главное действие сама, скрывает стандартные кнопки свойством `buttons` (тип `RecordFormButtons`) у `RecordFormPage` и `RecordFormActions`:

```tsx
<RecordFormPage state={state} buttons={{ actions: [], postAndClose: false }}>
```

`actions` перечисляет имена действий, кнопки которых выводятся; по умолчанию выводятся кнопки всех видимых действий. `postAndClose: false` убирает «Провести и закрыть». Без этой кнопки проведение и запись выводятся с подписями, а не значками. «Закрыть» выводится всегда. Скрывается только кнопка: действие остаётся доступным собственной кнопке формы (`state.run`) и сочетаниям клавиш.

`RecordFormBody` берёт компоненты элементов формы из контекста формы записи, поэтому элементы конфигурации ([`defineFormComponent`](../metadata.md#элементы-формы)) работают и в собственной форме, выводящей группы внутри тела.

## Компоновка полей

Компоновку полей группы выбирает свойство `layout` у `FieldGroup`:

| Значение | Вид |
|---|---|
| `stacked` | Подпись над полем; по умолчанию |
| `fluid` | Подпись в сегменте перед значением, граница сегмента служит разделителем. Занимает меньше высоты, поэтому подходит строкам из нескольких коротких полей |

Стандартные виджеты простых полей выводятся в обеих компоновках сами, а ошибка проверки в `fluid` стоит под полем. Составное поле и табличная часть выводятся с подписью над собой в любой компоновке. Свойство `fullWidth` группы называет поля, которым нужна вся ширина строки, например поле с переключателем и пояснением рядом, а `tablePartOptions` передаёт [настройки](#табличная-часть) табличным частям группы по их именам.

Поля группы стоят в сетке дизайн-системы. Ширину поля в колонках задаёт `widths` группы или ширина из конфигурации: `standard` занимает 4 колонки, `long` 8, `free` подбирает число колонок по значению, но не меньше 4. Число колонок группы зависит от её собственной ширины, поэтому на узкой группе обычное поле занимает строку, на средней половину, на широкой четверть. Поля `fullWidth`, табличные части и собственные элементы занимают всю строку. Подряд идущие поля `fluid`-группы стоят своей сеткой с зазором `narrow` (16 px), табличные части и элементы той же группы отделены обычным. Подробности в [«Полях форм»](../components.md#поля-форм).

У группы нет внешних отступов: расстояние до соседей задаёт родитель, например `Stack gap={6}` между группой и кнопкой.

Собственное поле ввода должно поддержать обе компоновки, потому что компоновку выбирает группа. Его собирает `fieldInput` из двух компонентов: `stacked` выводит только значение, `fluid` получает ещё `label` и `required` и выводит подпись обёрткой `FluidField`:

```tsx
function Comment(properties: InputProperties<string>) { return <Input … />; }

export default fieldInput<string>({
    stacked: Comment,
    fluid: ({ label, required, ...properties }) => (
        <FluidField label={label} required={required}><Comment {...properties} /></FluidField>
    ),
});
```

Поле ввода должно заполнять ячейку сетки целиком (`width: '100%'`), как стандартные виджеты: иначе его ширина не совпадёт с соседними. `FluidField` растягивается на всю ширину места; `block={false}` оставляет полю собственную ширину, например переключателю. Значение, которое не является элементом ввода Ant Design, ставят в `FluidValue`: тогда его рамка совпадает с рамкой сегмента названия (см. таблицу ниже). Результат `fieldInput` несёт метку `FieldInputMark`: по ней клиентский реестр элементов отклоняет при проверке типов элемент на месте поля, собранный иначе ([«Элементы формы»](../metadata.md#контракт-элемента)). Для элементов на месте табличной части и блоков вставки `fieldInput` не нужен.

| Компонент | Свойство | Назначение |
|---|---|---|
| `FluidValue` | `content` | `control`: собственный контрол с узким отступом вокруг; `text`: значение только для чтения высотой поля ввода |
| `FormStack` | `gap` | Шаг шкалы `spacing` между элементами формы, по умолчанию 6 (24 px) |

Правила описаны в разделе [«Компоненты и раскладка»](../components.md#значение-в-fluid-поле).

## Форма из `Form.Item`

`FormStack` оборачивает элементы формы, собранной из `Form.Item` вручную: поля, сообщения об ошибках, пояснения. Он убирает нижний отступ `Form.Item` (`itemMarginBottom: 0` через `ConfigProvider`) и расставляет элементы стеком. Поля по описаниям объекта ставит `FieldGroup`, он `FormStack` не использует. Причины и пример описаны в разделе [«Компоненты и раскладка»](../components.md#форма-из-formitem).

## Табличная часть

`TablePart` принимает настройки `TablePartOptions`. Группа передаёт их части свойством `tablePartOptions`, а элемент, который заменил часть, передаёт `TablePart` сам. Настройки меняют вид, а не данные: колонки описания часть сохраняет.

| Настройка | Действие |
|---|---|
| `showTitle` | Выводить ли название части над таблицей; по умолчанию выводится |
| `columnWidths` | Ширины колонок в пикселях по именам. Колонки без ширины делят остаток. С заданными ширинами таблица не сдвигает колонки при вводе, а в обычной раскладке браузер подгоняет их под содержимое |
| `columnShares` | Доли остатка у колонок без ширины; по умолчанию у каждой 1, остаток делится поровну |
| `columnOrder` | Порядок колонок на экране: названные идут первыми, остальные за ними в порядке описания. За порядком следует обход с клавиатуры |
| `columnInputs` | Поля ввода колонок вместо виджета вида поля, например переключатель; получают свойства виджета и участвуют в обходе |
| `addTitle` | Подпись кнопки добавления строки; по умолчанию «Добавить строку» |
| `addIcon` | Значок кнопки добавления строки; по умолчанию «+» |
| `initialRow` | Пустая таблица получает одну пустую строку, когда становится доступной для изменения. Строка не считается несохранённым изменением |
| `newRow` | Функция значений новой строки вместо значений по умолчанию; вызывается при каждом добавлении, поэтому может предложить, например, остаток суммы |
| `totals` | Колонки, суммы которых выводятся последней строкой «Итого» |
| `expandedRow` | Функция, возвращающая содержимое под строкой. Строки изначально раскрыты, пользователь может их свернуть; для `null` строка не раскрывается. Заменяет раскрытие по ссылке `expandedTablePart`. Функция вызывается при отрисовке как компонент, поэтому хуки используют в возвращаемом компоненте |

Название части выводит `TablePartTitle`, чтобы названия всех таблиц выглядели одинаково. Строка удаляется крестиком (`Icons.removeRow`), а не корзиной: строка убирается из несохранённой формы, и до записи удаление ничего не стирает.

## Форма на собственном экране

`FormDataProvider` стоит внутри формы Ant Design и снаружи групп полей. Без поставщика `FieldGroup` выводит поле виджетом его вида, а элемент формы пропускает. Если экран не передал поставщику учёт ограничений, элемент с ограничениями завершается ошибкой: молча не применённое ограничение выглядело бы как работающее.

Собственный элемент на месте поля ввода соблюдает контракт поля из реестра виджетов: значение, обработчик изменения, недоступность, приём фокуса. На этом контракте держатся обход с клавиатуры и проверка ввода.

Замена табличной части получает `TablePartInputProperties<Row>`. Строки хранятся в форме, поэтому при смене представления не теряются. `TablePart` работает с тем же хранилищем и сохраняет стандартную проверку ячеек, начальные значения и обход клавишей Enter. Компонент замены соблюдает недоступность и передаёт фокус доступному полю или таблице.
