# Хуки Web SDK

| Хук | Назначение |
|---|---|
| `useObjectView`, `usePageView` | Описание объекта и страницы конфигурации, если они доступны пользователю |
| `useRecordList` | Страница списка с отбором, поиском, сортировкой и постоянным отбором экрана |
| `useRecord` | Запись по `guid` |
| `useRecords` | Несколько записей объекта по списку `guid` одним запросом, со строками табличных частей |
| `useAction` | Выполнение действия |
| `useActionResult` | Результат только читающего собственного действия как запрос с кешем и функция его обновления |
| `useActionConfirmation` | Запрос подтверждения действия: `confirm` и окно `dialog` |
| `useReferencePresentation`, `useRecordPresentation` | Представление записи по ссылке и уже прочитанной записи |
| `useWindowTitle`, `useWindowScope`, `useUnsavedChanges` | Заголовок, закрытие, активность и несохранённые изменения области окна |
| `useOpenRecord` | Открытие формы записи во вкладке или в модальном окне |
| `useListControls` | Скрытие кнопки создания и действий строки ближайшего стандартного списка |
| `useListControlsState` | Объединённые ограничения для собственного каркаса списка |
| `useFormData`, `useFormValue` | Данные формы для элемента на ней и текущее значение поля |
| `useFormRestrictions` | Ограничения формы от элемента: недоступность и скрытые действия |
| `useFormRestrictionRegistry` | Учёт ограничений для собственного экрана с формой |
| `useFieldTraversal` | Обход полей с клавиатуры |
| `useRecordFormContract` | Контракт формы записи с областью окна: обработчики, запись и действия |
| `useRecordForm` | Поведение стандартной формы записи на основе контракта |

## Область окна и открытие записи

Хуки области окна обращаются к ближайшей области и вне её завершаются ошибкой. Экран не знает, показан он во вкладке или в модальном окне. `useUnsavedChanges` можно вызвать несколько раз, по разу на каждую часть экрана со своим признаком изменений.

`useOpenRecord` отдаёт команду открытия формы. Она принимает объект, `guid` записи или `null` для новой записи и необязательный режим `tab` или `dialog`:

```text
режим не указан, новая запись    → режим создания из описания формы (creationMode)
режим не указан, есть guid       → вкладка
tab                              → переход по адресу записи
dialog                           → после закрытия окна: guid записанной записи или null
```

Режим указывает место вызова, а конфигурация задаёт только умолчание. Общей настройки «как открывать записи объекта» нет: страницы всех вкладок смонтированы одновременно, и результат зависел бы от порядка их монтирования.

Для существующей записи команда сначала вызывает серверное [правило открытия](../metadata.md#правило-открытия-записи). Оно одинаково действует во вкладке и окне. При отказе команда показывает сообщение сервера, оставляет текущую форму и возвращает `null`. Создание с `guid: null` не применяет правило.

Четвёртый аргумент принимает `original: true` для открытия исходной формы с проверкой права чтения. Например:

```ts
await openRecord(Objects.document.saleInstallment, guid, 'tab', { original: true });
```

Обычный вызов для связанной рассрочки открывает продажу, вызов с `original: true` открывает рассрочку. Во вкладке режим оригинала сохраняется в адресе как `?original=1`. Параметры `initial` и `width` сохраняют своё назначение: значения новой записи и ширина окна.

## Чтение данных

Постоянный отбор `useRecordList`, например «только непроведённые», действует вместе с отбором пользователя. Пользователь его не видит и снять не может.

По настройке `useRecordList` хранит состояние списка в адресе вкладки. Адрес у вкладки один, поэтому так может работать только один список на экране; остальные хранят состояние в памяти.

`useRecords(object, guids)` читает несколько записей одним пакетом действий `get`. Он нужен экрану, которому требуются строки табличных частей нескольких записей: список их не отдаёт, а `useRecord` на каждую запись отправил бы отдельный запрос. Хук возвращает `records` (словарь `guid` → запись со строками табличных частей), `loading` и `error`:

```tsx
const sales = useRecords(Objects.document.sale, guids);
const sale = sales.records.get(guid);
```

Уведомление об отказе сервера хук не показывает: об ошибке сообщает сам экран. Пакет выполняется целиком, поэтому отказ в одной записи оставляет словарь пустым и относится ко всем. При пустом списке запрос не отправляется.

## Выполнение действий

`useAction` сам показывает уведомления об успехе и об отказе и после успеха помечает устаревшими сохранённые ответы сервера. Отказ завершает вызов ошибкой `ApiError`: по её перечню `fields` экран отмечает поля.

`useActionResult({ object, action, payload, enabled, refreshInterval })` читает результат собственного действия, которое только читает данные, например перечень уже возвращённых товаров. Это запрос с кешем (`ActionQuery`): он возвращает `data`, `loading` и `refresh` (тип `ActionResult`), обновляется после любого изменяющего действия и не показывает уведомлений. Отказ, например нехватка права на действие, оставляет `data` пустым. `refresh()` читает результат заново: он нужен, когда данные на сервере могли измениться без действия этого клиента, например сервер отклонил запись из-за изменений другого пользователя. Пока `enabled` равен `false`, запрос не отправляется. Число в `refreshInterval` (миллисекунды) включает перечитывание результата с этим интервалом, `false` (по умолчанию) отключает его: параметр нужен, когда сервер меняет данные сам, например пока идёт резервная копия. Изменяющие действия выполняет `useAction`.

`useActionConfirmation()` возвращает `confirm(action)` и `dialog`. Экран с собственной кнопкой вызывает `confirm` перед `useAction` или `state.run` и выводит `dialog`; для действия без `confirmation` ответ `true` приходит сразу. Окно и его правила описаны в [«Компонентах»](components.md#подтверждение-действия).

## Данные формы

Элемент формы получает данные хуками, а не свойствами. `useFormData` отдаёт описание объекта и формы, записанное состояние, признак «только просмотр», изменение значения и `runAction`. Элемент перерисовывается, когда форму записали, перечитали или изменились её ограничения. `useFormValue` перерисовывает элемент только при изменении своего поля и учитывает несохранённый ввод.

Оба хука принимают ссылку на объект. Элемент со ссылкой на форме другого объекта завершается ошибкой, потому что типы записи были бы неверны. Элемент без ссылки подходит любой форме.

Изменение значения через `useFormData` форма считает вводом пользователя: оно не сохранено, сразу проверяется по правилам поля и уходит в `save` вместе с остальными значениями. Ограничения:

- Значение, зависящее от прежнего, передают функцией от текущего значения формы. Значение из `useFormValue` приходит с отрисовкой, и второе из двух изменений подряд отменило бы первое.
- Изменить можно только редактируемое поле формы или строки табличной части. Другое имя завершает вызов ошибкой.
- Форма сразу проверяет новое значение и показывает ошибки под полем. Третий параметр `{ validate: false }` (`SetValueOptions`) откладывает проверку до ввода пользователя или записи и снимает прежние ошибки поля. Так элемент ставит пустую строку для заполнения, и «Заполните поле» не появляется раньше, чем пользователь начал её заполнять.
- На форме только для просмотра и у поля, которое элемент сделал недоступным, значение не меняется.

`runAction` выполняет действие формы так же, как его кнопка: записывает несохранённые изменения, выполняет действие и показывает запись в новом состоянии. Отказ сервера завершает вызов ошибкой, уведомление уже показано. Во входные данные собственного действия форма `guid` записи не добавляет, его передаёт элемент. Так элемент выводит свою кнопку для действия, которому нужны `guid` или данные с формы, а стандартную кнопку скрывает через `useFormRestrictions`. Выполнить можно только действие из описания формы, то есть разрешённое пользователю.

## Ограничения формы

`useFormRestrictions` объявляет ограничения от имени элемента: `readOnly` для всей формы, `readOnlyFields` для полей и табличных частей, `hiddenActions` для действий. Ограничения действуют, пока элемент стоит на форме. Требования нескольких элементов объединяются: поле недоступно, если этого требует хотя бы один.

Условие элемент вычисляет при каждой отрисовке и передаёт готовые ограничения. Поэтому форма меняет состояние вслед за условием: после записи, после действия, после чтения других данных. Пока условие не известно, элемент передаёт `null`.

Пока требования не собраны, форма недоступна целиком, а все действия скрыты. Так запись, которую менять нельзя, не выглядит изменяемой даже во время загрузки. Требования не собраны до первого сбора и пока хотя бы один элемент передаёт `null`. Элементы объявляют их в эффекте раскладки, и форма применяет их до того, как браузер её покажет.

## Контракт формы записи

Форма записи и форма новой записи, объявленные как [форма объекта](../metadata.md#формы-объекта), работают в области окна: вкладке или модальном окне. Области нужно знать о несохранённых изменениях, записанной и созданной записи. `useRecordFormContract` берёт эти сообщения на себя, а форма предоставляет четыре обработчика:

```tsx
const controller = useRecordFormContract({
    changed: () => changed.current,
    save: async (record, post) => { /* проверить, записать (и провести, если задан post), вернуть запись или null */ },
    perform: async (action, input, record) => { /* выполнить действие, вернуть { record, result } */ },
    show: (record) => { /* показать запись от сервера, сбросить признак изменений */ },
});
```

| Обработчик | Что делает |
|---|---|
| `changed` | Сообщает, есть ли несохранённые изменения. Область спрашивает по нему подтверждение перед закрытием |
| `save` | Проверяет и записывает введённые значения поверх `record`; у новой записи `record` равен `null`. Возвращает запись от сервера либо `null`, если запись не состоялась и форма уже показала ошибки. Второй параметр `post` просит записать и провести документ одним запросом |
| `perform` | Выполняет действие, кроме записи, над записанной записью и возвращает `{ record, result }`. Отказ сервера завершает вызов ошибкой |
| `show` | Заменяет значения формы записью от сервера и сбрасывает признак изменений |

Все обработчики обязательны: пропуск не проходит проверку типов. Хук читает их в момент вызова, поэтому их можно создавать заново при каждой отрисовке. Вне формы записи, показанной областью окна, хук завершается ошибкой.

### Что делает run

Хук возвращает `RecordFormController`: `record` (записанное состояние, у новой записи `null`), `running` (имя выполняемого действия), `isRunning()` и `run(action, input?, { close?, atomic? })`. Входные данные действия `input` задаются значениями либо функцией от записанной записи (`RecordFormActionInput`). Функция нужна новой записи: её `guid`, который требует собственное действие, появляется только после записи, и `run` вызывает функцию уже с записанной записью:

```ts
state.run(sell, (saved) => ({ sale: saved['guid'], person }));
```

`run` выполняет действие так:

1. Для `save`, новой записи и записи с несохранёнными изменениями вызывает `save`. Если запись не состоялась, `run` завершается ошибкой «Запись не сохранена», а область ничего не узнаёт. С `atomic: true` стандартное действие `post` над новой записью вызывает `save` с `post`: запись и проведение идут одним запросом, и при отказе проведения запись не создаётся. Тогда отдельного второго запроса нет, и шаг 2 пропускается.
2. Для любого другого действия вызывает `perform` над записанной записью. Действие применяется к записанному состоянию, поэтому запись и действие уходят двумя последовательными запросами.
3. Принимает запись от сервера и передаёт её в `show`.
4. Сообщает области `guid` записанной записи, даже если следующее действие отклонено: запись уже изменена на сервере.
5. Закрывает область, если действие выполнено и передан `close: true`. Иначе, если запись была новой, сообщает области о создании: вкладка переходит на адрес записи, окно закрывается.

Повторный вызов во время выполнения завершается ошибкой «Действие уже выполняется». Эти проверки и сообщения выполняет хук, а не форма, поэтому поведение собственной и стандартной форм в области окна одинаково.

### Подключение и ошибки

Контракт подключается ровно один раз в компоненте формы. Область окна проверяет это после монтирования формы:

| Нарушение | Что видит пользователь |
|---|---|
| Форма не вызвала `useRecordFormContract` или `useRecordForm` | Вместо формы ошибка: компонент не подключил контракт |
| Контракт подключён дважды | Вместо формы ошибка: область узнала бы о записи дважды |

Дважды контракт подключается, например, когда форма вызывает `useRecordForm` и в одной из ветвей возвращает `StandardRecordForm`; как этого избежать, описано в [«Компонентах»](components.md#стандартная-форма-и-её-части).

Сочетания клавиш контракт не подключает: форма обрабатывает их сама. `useRecordForm` подключает Ctrl+S (запись), Ctrl+Enter (проведение с закрытием) и Esc (закрытие) и учитывает, что область может быть скрыта, а поверх формы может быть открыто окно.

### useRecordForm

Список `state.actions` содержит действия изменения записи с `placement: 'buttons'`; доступные действия с `placement: 'more'` лежат в `state.menuActions`, их выводит меню «Ещё», а `hidden`-действия есть только в `state.view.actions`, и на форме их вызывает собственный экран через `runByName`. Служебные команды с `opens` остаются в `state.view.actions` для меню «Ещё». Команда просмотра журнала не выполняется через `runByName` и не запускает сохранение формы.

`useRecordForm(properties, options)` принимает свойства формы записи или формы новой записи целиком и подключает контракт сам. Значения `initial` формы новой записи (раздел [«Формы объекта»](../metadata.md#виды-форм)) ставятся поверх значений по умолчанию. Хук ведёт записанное состояние, запись с разметкой ошибок сервера под полями, действия, ограничения элементов формы, обход полей и сочетания клавиш. Возвращает `RecordFormState`: форма Ant Design, начальные значения, записанная запись, имя выполняемого действия, признак доступности для изменения, видимые действия и действие проведения, `run` и `runByName`, обход и корневой элемент. Параметр `atomicPosting: true` в `options` включает `atomic` для кнопок, Ctrl+Enter и `run` формы, пока вызов не задал его сам. Так новый возврат при отказе проведения не остаётся черновиком. Состояние передаётся [частям формы](components.md#стандартная-форма-и-её-части) свойством `state`.

Второй параметр `RecordFormOptions` необязателен. Обработчик `beforeSave(values)` вызывается перед проверкой записи: он получает все значения формы и возвращает исправленные либо `undefined`, если менять нечего. Форма показывает и записывает исправленные значения, поэтому пользователь видит то же, что сохранено. Так форма продажи превращает сложную оплату из одной заполненной строки в простую.
