# Журнал действий

Журнал хранит историю изменений записей, действия пользователей и связи между внешним действием и вложенными вызовами. В него попадают только успешные изменяющие действия вместе с изменениями данных. Ошибки и чтение журнал не фиксирует.

## Гарантии записи

- Каждое стандартное изменяющее действие и каждое собственное действие конфигурации оставляет одну строку. Вложенные действия оставляют свои строки, связанные с вызывающим.
- Запись тех же значений тоже фиксируется, даже если данные не изменились.
- Строки пишутся в той же транзакции, что и данные. Ошибка любой операции пакета откатывает данные и строки всего пакета.
- Стандартное чтение (`get`, `list`) и чтение журнала строк не оставляют. Собственное действие, которое только читает данные, журналируется как вызов собственного действия.
- [Перепроведение документов](single-endpoint.md#перепроведение-документов) оставляет одну строку на всю операцию: цель `platform.documents`, действие `repost`. Записи документов оно не меняет.
- Запись учётной записи оставляет строку с целью `platform.users` и действием `save`: изменения имени, ролей и состояния, для PIN только факт смены `pinChanged`. Исходный PIN и HMAC не передаются в журнал. Строки доступны в общем списке журнала; история объектов конфигурации служебные учётные записи не включает.

## Чтение журнала

### Просмотр из карточки

В карточке справочника или документа откройте «Ещё» → «Журнал действий». Меню доступно с правом `platform.journal.read`; у новой записи пункт недоступен до сохранения. Просмотр не записывает несохранённые изменения формы.

Журнал открывается в отдельном окне в виде ленты сообщений: имя автора, время и действие. Сначала показаны новые события, по 20 на странице. «Обновить» перечитывает текущую страницу. Пустая история и ошибка чтения показаны явно; после ошибки доступен повтор запроса.

В блоке «Изменения» видны значения «Было» и «Стало», деньги, даты и ссылки используют обычное представление полей. Изменённые табличные части показаны полностью до и после действия. «Цепочка действий» загружает всю внешнюю операцию, включая её родителей и вложенные вызовы. Каждый уровень раскрывается отдельно, выбранное событие отмечено подписью. В цепочке могут быть действия над другими объектами, поскольку право журнала открывает всю историю.

Имя автора и представления ссылок соответствуют текущим данным, а значения изменённых полей берутся из журнала. Если пользователь больше не найден, вместо имени показан его GUID; у действия без пользователя указано «Система». Для поля, отсутствующего в текущем описании формы, показывается исходное значение.

Журнал читается через `POST /api/perform` с целью `{ "kind": "platform", "name": "journal" }`. Нужны вход в приложение и право `Rights.platform.journal.read` (ключ `platform.journal.read`). Право открывает журнал всех объектов: права на чтение отдельных объектов результат не ограничивают. Общая оболочка запроса описана в [API данных](single-endpoint.md).

### Действия и параметры

| Действие | Обязательные поля `payload` | Необязательные поля | Результат |
|---|---|---|---|
| `history` | `targetKind`, `targetName` | `targetGuid` или `targetKey`, `page`, `pageSize` | Страница истории одной записи или всех записей объекта |
| `userActions` | `userGuid` | `page`, `pageSize` | Страница действий пользователя, включая вложенные |
| `trace` | `traceGuid` | Нет | Дерево одной цепочки: `{ traceGuid, actions }` |

Правила параметров:

- `targetKind` и `targetName` непустые и указывают на существующий объект конфигурации.
- Историю записи справочника или документа выбирает `targetGuid`. Историю записи регистра сведений выбирает `targetKey`: объект со всеми измерениями без пропусков, `null` и посторонних полей, типы значений соответствуют метаданным, порядок полей не важен. `targetGuid` для сведений и `targetKey` для других объектов запрещены.
- Без ключа `history` возвращает все строки объекта, включая вызовы собственных действий.
- `targetGuid`, `userGuid` и `traceGuid` принимают строку формата GUID. Существование записи, пользователя или цепочки не проверяется: корректный идентификатор без совпадений даёт пустой результат.
- `page` начинается с 1 (по умолчанию 1), `pageSize` от 1 до 500 (по умолчанию 50). Оба значения целые, и смещение `(page - 1) * pageSize` тоже должно быть точным целым. `trace` возвращает всю цепочку без пагинации.

Пример: история справочника без отбора по записи.

```json
{
  "target": { "kind": "platform", "name": "journal" },
  "action": "history",
  "payload": { "targetKind": "catalog", "targetName": "employees", "pageSize": 50 }
}
```

### Формат результатов

`history` и `userActions` возвращают `{ items, total, page, pageSize }`, где `total` равно числу всех строк по отбору, а пустая страница содержит `items: []`. Строки идут по времени начала действия от новых к старым; при равном времени первыми идут строки, записанные позже.

| Поле строки | Смысл |
|---|---|
| `guid` | Идентификатор строки журнала |
| `occurredAt` | Время начала действия, ISO 8601 |
| `userGuid` | GUID пользователя, начавшего цепочку; допускает `null` |
| `userName` | Текущее имя пользователя; `null`, если пользователь не найден или действие системное |
| `traceGuid` | GUID цепочки одной внешней операции и её вложенных действий |
| `actionGuid` | GUID текущего вызова действия |
| `parentActionGuid` | GUID вызывающего действия; `null` у внешней операции |
| `targetKind`, `targetName` | Вид и имя объекта конфигурации; у перепроведения `platform` и `documents` |
| `targetGuid` | GUID записи справочника или документа; `null` у сведений, импорта, собственных действий и перепроведения |
| `targetKey` | Объект с измерениями записи сведений; `null` у остальных строк |
| `action` | Имя выполненного действия |
| `changes` | Объект `{ "поле": { "before": …, "after": … } }`; `null` у импорта, собственных действий и перепроведения |

`changes` и `targetKey` приходят объектами JSON, а не строками. `before` и `after` содержат значения полей или массивы строк табличной части; отсутствующее значение записано как `null`. Значение составного поля хранится вместе с типом варианта, поэтому смена типа видна как изменение.

В ответе `trace` массив `actions` содержит корни дерева. Узел включает все поля строки и массив `children` с вложенными действиями. Узлы одного уровня идут от старых к новым по времени начала, при равном времени по порядку записи. Действие, родитель которого не оставил строки, становится корнем. Для неизвестного `traceGuid` возвращается `{ traceGuid, actions: [] }`.

### Ошибки чтения

| HTTP-код | Условие | Тело ответа |
|---|---|---|
| 400 | Неверный `payload`, пропущенная обязательная строка, неверный GUID, ключ сведений или параметры страницы | `{ error, fields }`, где `fields` содержит пути ошибочных полей |
| 401 | Нет действующего входа в приложение | `{ error }` |
| 403 | Нет права `platform.journal.read` | `{ error, right }` |
| 404 | Неизвестный объект в `history` или неизвестное действие журнала | `{ error }` |
| 500 | Ошибка базы или непредвиденная ошибка выполнения | `{ error }` |

Право проверяется раньше параметров. Отсутствие строк по корректному отбору ошибкой не считается.

## Контекст действия

Диспетчер создаёт `ActionContext` для каждой внешней операции. Вложенный вызов через `ActionDispatcher` получает новый `actionGuid` и ссылку `parentActionGuid` на вызывающее действие, а `traceGuid` и `userGuid` наследует. Поэтому вся цепочка принадлежит пользователю, начавшему внешнюю операцию. Обработчик получает контекст из окружения Effect без дополнительных параметров.

Операции пакета выполняются в одной транзакции, но каждая внешняя операция получает собственный `traceGuid`. Общая транзакция не превращает операции пакета в одно дерево журнала.

`occurredAt` фиксируется перед выполнением действия, а строка пишется после успешного завершения. Вложенное действие обычно записывает строку раньше вызывающего, поэтому время начала и порядок записи описывают разные события. Дерево восстанавливается по `actionGuid` и `parentActionGuid`.

## Запись журнала

Стандартные действия справочников и документов (`save`, `markDeleted`, `unmarkDeleted`, `post`, `unpost`) сравнивают запись до выполнения с результатом. Все изменения полей и табличных частей попадают в одну строку, сколько бы запросов к базе ни понадобилось. Например, пометка удаления проведённого документа содержит изменения `deletedAt` и `posted`. Движения регистров в `changes` не входят: журнал фиксирует действие над документом и смену признака проведения.

Правила содержимого `changes`:

- Изменённая табличная часть записывается целиком, массивами строк до и после. У строк нет идентификатора, поэтому при замене журнал отдельные строки не сопоставляет.
- У новой записи в `changes` попадают все заполненные поля и непустые табличные части с `before: null`. Значения `false`, `0` и пустая строка считаются заполненными, `null` и пустые массивы не включаются.
- Стандартный `guid` хранится в `targetGuid`, в изменения не входит.
- Если ничего не изменилось, `changes` равен `{}`.

У сведений `save` и `delete` записывают полный ключ измерений в `targetKey`. При удалении поля переходят из прежних значений в `null`. Ключ остаётся в строке, поэтому история доступна и после физического удаления записи.

Собственное действие записывается с `targetGuid: null` и `changes: null`, потому что его результат не обязан быть записью одного объекта. Изменения данных видны в строках вложенных стандартных действий. Так же устроен `import` справочника: строка импорта связывает вложенные сохранения записей и внешних связей с одним вызовом.

Строки хранятся в таблице `platform_journal` с индексами по времени, объекту, пользователю и цепочке. Запись, сравнение и чтение реализует [модуль журнала](https://github.com/EGSP/collection-zarplata/blob/main/src/server/journal/journal.ts), журналирование стандартных действий выполняет [диспетчер данных](https://github.com/EGSP/collection-zarplata/blob/main/src/server/data/data.service.ts).
