# Журнал действий

Журнал позволяет разработчику получить историю изменений записи, действия пользователя и связи между внешним действием и вложенными вызовами. Он хранит успешные действия вместе с изменениями данных. Журнал не служит протоколом ошибок и обращений на чтение.

## Гарантии записи

Каждое стандартное изменяющее действие и каждое собственное действие конфигурации оставляет одну строку. Вложенные действия оставляют свои строки, связанные с вызывающим действием. Запись тех же значений тоже фиксируется, даже если данные не изменились.

Строки журнала записываются в той же транзакции, что и данные. Если любая операция пакета завершается ошибкой, откатываются данные и строки журнала всего пакета. Стандартное чтение (`get`, `list`) и чтение журнала строк не оставляют. Собственное действие, которое только читает данные, журналируется как вызов собственного действия.

## Чтение журнала

Журнал читается через `POST /api/perform` с целью `{ "kind": "platform", "name": "journal" }`. Требуются вход в приложение и право `Rights.platform.journal.read` (ключ `platform.journal.read`). Это право открывает журнал всех объектов; права на чтение отдельных объектов не ограничивают результат. Общая оболочка запроса описана в [API данных](single-endpoint.md).

### Действия и параметры

| Действие | Обязательные поля `payload` | Необязательные поля | Результат |
|---|---|---|---|
| `history` | `targetKind`, `targetName` | `targetGuid` или `targetKey`, `page`, `pageSize` | Страница истории одной записи либо всех записей объекта |
| `userActions` | `userGuid` | `page`, `pageSize` | Страница действий пользователя, включая вложенные |
| `trace` | `traceGuid` | Нет | Дерево одной цепочки: `{ traceGuid, actions }` |

`targetKind` и `targetName` должны быть непустыми строками и указывать на существующий объект конфигурации. Для истории записи справочника или документа используется `targetGuid`. Для регистра сведений используется `targetKey`: объект со всеми измерениями записи, без пропусков, `null` и посторонних полей; типы значений должны соответствовать метаданным. Порядок полей ключа в запросе не имеет значения. `targetGuid` для сведений и `targetKey` для других объектов запрещены. Без ключа `history` возвращает все строки журнала данного объекта, включая вызовы собственных действий.

`targetGuid`, `userGuid` и `traceGuid` принимают строку в формате GUID. Наличие записи, пользователя или цепочки не проверяется: корректный идентификатор без совпадений даёт пустой результат.

У `history` и `userActions` номер `page` начинается с 1, по умолчанию равен 1. Размер `pageSize` составляет от 1 до 500 строк, по умолчанию 50. Оба значения должны быть точно представимыми целыми числами; вычисленное смещение `(page - 1) * pageSize` тоже должно быть точно представимым целым. `trace` возвращает всю цепочку без пагинации.

Например, история справочника без отбора по записи:

```json
{
  "target": { "kind": "platform", "name": "journal" },
  "action": "history",
  "payload": { "targetKind": "catalog", "targetName": "employees", "pageSize": 50 }
}
```

### Формат и порядок результатов

`history` и `userActions` возвращают `{ items, total, page, pageSize }`. `items` содержит строки журнала, `total` обозначает число всех строк по отбору. Пустая страница содержит `items: []`. Строки идут по времени начала действия от новых к старым; при совпадении времени первыми идут строки, записанные позже.

| Поле строки | Тип и смысл |
|---|---|
| `guid` | Строка, идентификатор строки журнала |
| `occurredAt` | Строка, время начала действия в формате ISO 8601 |
| `userGuid` | GUID пользователя, начавшего цепочку; тип допускает `null` |
| `traceGuid` | GUID цепочки одной внешней операции и её вложенных действий |
| `actionGuid` | GUID текущего вызова действия |
| `parentActionGuid` | GUID вызывающего действия; `null` у внешней операции |
| `targetKind`, `targetName` | Строки, вид и имя объекта конфигурации |
| `targetGuid` | GUID записи справочника или документа; `null` у сведений, импорта и собственных действий |
| `targetKey` | Объект с измерениями записи сведений; `null` у остальных строк |
| `action` | Строка, имя выполненного действия |
| `changes` | Объект изменений `{ "поле": { "before": …, "after": … } }`; `null` у импорта и собственных действий |

`changes` и `targetKey` возвращаются объектами JSON, а не строками с JSON. Значения `before` и `after` содержат значения полей или массивы строк табличной части; отсутствие значения представлено `null`.

В ответе `trace` массив `actions` содержит корни дерева. Каждый узел включает все поля строки и массив `children` с вложенными действиями. Узлы одного уровня идут по времени начала от старых к новым; при совпадении времени используется порядок записи строк. Действие, родитель которого не оставил строки, становится корнем. Для неизвестного `traceGuid` возвращается `{ traceGuid, actions: [] }`.

### Ошибки чтения

| HTTP-код | Условие | Тело ответа |
|---|---|---|
| 400 | Неверный `payload`, пропущенная обязательная строка, неверный GUID, ключ сведений или параметры страницы | `{ error, fields }`, где `fields` содержит пути ошибочных полей |
| 401 | Нет действующего входа в приложение | `{ error }` |
| 403 | Нет права `platform.journal.read` | `{ error, right }` |
| 404 | Неизвестный объект в `history` или неизвестное действие журнала | `{ error }` |
| 500 | Ошибка базы или непредвиденная ошибка выполнения | `{ error }` |

Проверка права выполняется до проверки параметров действия журнала. Отсутствие строк по корректному отбору не является ошибкой.

## Контекст действия

Диспетчер создаёт `ActionContext` для каждой внешней операции. Вложенный вызов через `ActionDispatcher` получает новый `actionGuid` и ссылку `parentActionGuid` на вызывающее действие, но наследует `traceGuid` и `userGuid`. Поэтому вся цепочка относится к пользователю, который начал внешнюю операцию.

Контекст передаётся через окружение Effect; обработчик получает его без дополнительных параметров. В пакете внешние операции используют одну транзакцию, но каждая получает собственный `traceGuid`. Транзакционная связь пакета не означает, что его операции образуют одно дерево журнала.

`occurredAt` фиксируется перед выполнением действия, а строка записывается после его успешного завершения. Вложенное действие обычно записывает строку раньше вызывающего. Поэтому время начала и порядок записи строк описывают разные события; дерево восстанавливается по `actionGuid` и `parentActionGuid`.

## Запись журнала

Стандартные действия справочников и документов (`save`, `markDeleted`, `unmarkDeleted`, `post`, `unpost`) сравнивают запись до выполнения с результатом действия. Все изменения полей и табличных частей попадают в одну строку, сколько бы запросов к базе ни понадобилось. Например, пометка удаления проведённого документа содержит изменения `deletedAt` и `posted`. Движения регистров в `changes` не входят: журнал фиксирует действие над документом и изменение признака проведения.

Изменённая табличная часть записывается целиком: массивы строк до и после действия. У строк нет собственного идентификатора, поэтому журнал не сопоставляет отдельные строки при замене. Для новой записи в `changes` включаются все заполненные поля и непустые табличные части с `before: null`. Значения `false`, `0` и пустая строка считаются заполненными; `null` и пустые массивы не включаются. Стандартный `guid` хранится в `targetGuid` и в изменения не входит. При отсутствии изменений `changes` равен `{}`.

У сведений действия `save` и `delete` записывают полный ключ измерений в `targetKey`. При удалении значения полей переходят из прежних значений в `null`; ключ сохраняется в строке журнала, чтобы история оставалась доступной после физического удаления записи.

Собственное действие конфигурации записывается с `targetGuid: null` и `changes: null`: его результат не обязан быть записью одного объекта. Изменения данных видны в строках вложенных стандартных действий. Так же устроен `import` справочника: строка импорта связывает вложенные сохранения записей и внешних связей с одним вызовом.

Строки хранятся в служебной таблице `platform_journal` с индексами по времени, объекту, пользователю и цепочке. Код записи, сравнения и чтения находится в [модуле журнала](https://github.com/EGSP/collection-zarplata/blob/main/src/server/journal/journal.ts); журналирование стандартных действий выполняет [диспетчер данных](https://github.com/EGSP/collection-zarplata/blob/main/src/server/data/data.service.ts).
