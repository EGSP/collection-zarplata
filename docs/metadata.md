# Метаданные

## Виды объектов

| Вид | Назначение | Функция описания |
|---|---|---|
| Справочник | Условно-постоянные данные: сотрудники, номенклатура, точки | `catalog(name)` |
| Документ | Событие с датой, номером и статусом «проведён / не проведён» | `document(name)` |
| Регистр | Строки, которые документ записывает при проведении; по ним считаются обороты | `register(name)` |
| Регистр сведений | Текущие независимые значения по уникальному набору измерений | `informationRegister(name)` |

Регистры поддерживаются платформой. Нужны ли они в конкретной задаче, решает конфигурация. Строка регистра (движение) всегда ссылается на документ-регистратор. Один документ может записать несколько строк, например по одной на каждого сотрудника смены. При повторном проведении старые строки документа удаляются и записываются заново, поэтому проведение идемпотентно.

Пока поддерживаются только регистры оборотов: ресурсы строк суммируются. Регистры остатков с видом движения «приход / расход» добавим, когда они понадобятся.

Регистр сведений имеет отдельный вид `informationRegister`. У него нет документа-регистратора, периода, номера строки, `guid` и пометки удаления. Все измерения обязательны и вместе определяют запись; ресурсы содержат её значения и допускают все прикладные виды полей, включая строки и ссылки. Периодичность и история значений не поддерживаются. История действий доступна в общем журнале.

## Независимые сведения

Один файл `*.information-register.ts` экспортирует билдер регистра. Например, пробный регистр описан так:

```ts
import { informationRegister } from '../../server/metadata/index.js';
import { Sample } from '../catalogs/sample.catalog.js';

export const SampleInformation = informationRegister('sample')
    .title('Пробный регистр сведений')
    .dimension('source', (field) => field.string().title('Источник').maximumLength(100))
    .dimension('externalObject', (field) => field.string().title('Внешний объект').maximumLength(100))
    .resource('description', (field) => field.string().title('Описание').maximumLength(500))
    .resource('item', (field) => field.reference(() => Sample).title('Элемент справочника'));
```

Обязательность измерений добавляет сам билдер, в том числе в выведенный тип записи. `commit()` требует хотя бы одно измерение и один ресурс. Порядок ключа совпадает с порядком объявления измерений. При синхронизации создаётся таблица `informationRegister_<имя>` с составным первичным ключом по измерениям и ограничением `NOT NULL` для каждого измерения. База не допускает двух строк с одним ключом; запись при конфликте ключа заменяет только ресурсы. Индексы измерений позволяют искать сведения по части ключа. Политики `.policy(...)` проверяют сохранение и физическое удаление; форм, табличных частей и собственных действий у этого вида объекта нет.

## Описание объекта

Объект описывается цепочкой вызовов билдера. Билдер собирает описание объекта из полей, табличных частей, действий и формы; описание создаётся при вызове `commit()`. Код билдеров находится в `src/server/metadata`.

```ts
import { Effect } from 'effect';
import { catalog, document, movements, register } from '../../server/metadata/index.js';
import { Positions } from './positions.catalog.js';
import { closedPeriodByDocumentDate } from '../policies/closed-period.js';
import { preventPostedDocumentDeletion } from '../policies/posted-document-deletion.js';

export const Employees = catalog('employees')
    .title('Сотрудники')
    .field('position', (field) => field.reference(Positions).title('Должность'))
    .field('hiredAt', (field) => field.date().title('Дата приёма').required())
    .field('rate', (field) => field.money().title('Ставка').minimum(0))
    .tablePart('contacts', (part) => part
        .title('Контакты')
        .field('kind', (field) => field.string().title('Вид').required().maximumLength(20))
        .field('value', (field) => field.string().title('Значение')))
    .action('dismiss', (action) => action          // собственное действие
        .title('Уволить')
        .input((input) => input.field('dismissedAt', (field) => field.date().required()))
        .handle((input) => Effect.log(input.dismissedAt)))
    .form((form) => form                           // необязательное переопределение формы
        .group('Основное', ['name', 'position'])
        .hide('rate'));

export const Accruals = register('accruals')
    .title('Начисления')
    .dimension('employee', (field) => field.reference(Employees))
    .resource('amount', (field) => field.money().required());

export const Shift = document('shift')
    .title('Смена')
    .tablePart('staff', (part) => part
        .field('employee', (field) => field.reference(Employees).required())
        .field('amount', (field) => field.money().required()))
    .policy(closedPeriodByDocumentDate())
    .policy(preventPostedDocumentDeletion())
    .posting((record) => Effect.succeed([                 // обработчик проведения
        movements(Accruals, record.staff.map((line) => ({ employee: line.employee, amount: line.amount }))),
    ]));
```

- Файл конфигурации экспортирует **билдер**, а не готовое описание. `commit()` в файлах конфигурации не вызывается.
- Билдеры неизменяемы: каждый вызов возвращает новый билдер.
- Платформенный сервис метаданных получает билдеры всех объектов из сгенерированного реестра. Перед сборкой он добавляет стандартные поля вида объекта методом `withStandardFields()`.
- Затем сервис вызывает `commit(configuration)`, где `configuration` — билдеры всех объектов, или `commitConfiguration(builders)` для всех объектов сразу. `commit()` проверяет описание и собирает из него неизменяемое описание объекта (`ObjectDescription`), с которым работает остальная платформа. Результат — `Effect`; при ошибках он завершается `MetadataError` со списком всех найденных проблем.
- Ссылки на другие объекты передаются самими билдерами (`field.reference(Positions)`), а не строками. Если файлы импортируют друг друга по кругу, цель передаётся функцией: `field.reference(() => Employees)`. Ссылаться можно на справочники и документы.
- Каждый вызов `.field(...)`, `.tablePart(...)`, `.dimension(...)` и `.resource(...)` расширяет тип билдера, поэтому TypeScript выводит тип записи из цепочки без отдельной генерации типов: `RecordOf<typeof Employees>`. Стандартные поля известны заранее по виду объекта и тоже входят в тип. Обязательное поле имеет тип значения, необязательное — значение или `null`, табличная часть — массив строк.
- Справочник может объявить представление по ссылке: `.presentation('person')` называет поле-ссылку, и запись показывается представлением записи, на которую это поле ссылается. Так сотрудник называется ФИО физического лица, а ФИО хранится в одном месте. Правила описаны в разделе [«Ссылки»](interface.md#ссылки).
- Обработчик проведения `.posting(...)` есть только у документа. Он получает сохранённую запись документа с табличными частями и возвращает Effect со строками регистров. Строки одного регистра собирает `movements(Регистр, строки)`: тип строки выводится из билдера регистра, поэтому TypeScript отклоняет неизвестные измерения и ресурсы. `period` строки можно не указывать — платформа подставит дату документа; регистратор и номер строки платформа заполняет сама. Обработчику, как и собственному действию, доступны из окружения Effect `ActionContext`, `ActionDispatcher`, `Database` для чтения и `Metadata` — описания объектов конфигурации. Изменения через прямой вызов `Database.run` запрещены; для вложенной записи используется `ActionDispatcher`.
- Собственные действия выполняет диспетчер после проверки прав и входных данных. Имя действия попадает в тип билдера, поэтому право на него доступно переменной `Rights.catalog.employees.actions.dismiss`. Переопределение формы применяется при построении описаний форм (раздел [«Интерфейс (SDUI)»](interface.md)). `.policy(...)` привязывает к объекту именованную проверку: она получает действие, прежнюю и предлагаемую запись и выполняется до изменения данных.

## Поля

Полная ссылка на запись содержит `kind` (`catalog` или `document`), `name` объекта конфигурации и `guid` записи. Функция `objectReference` собирает её из известной цели и GUID. Поле `field.reference()` принимает такую ссылку; поле с заданной целью `field.reference(Объект)` сохраняет прежний формат GUID, поскольку цель уже есть в метаданных. Оба вида полей показывают представление записи и открывают её карточку по общему правилу формирования адресов. В таблицах это наименование справочника или представление документа, в полях ввода — выбор записи с кнопкой открытия. Без права чтения целевого объекта представление не запрашивается: показывается «Нет доступа».

| Поле | Значение в записи | Свойства |
|---|---|---|
| `field.string()` | строка | `minimumLength`, `maximumLength` |
| `field.number()` | число | `minimum`, `maximum`, `integer` |
| `field.money()` | целое число копеек | `minimum`, `maximum` в копейках |
| `field.date()` | строка `YYYY-MM-DD` | |
| `field.dateTime()` | строка ISO 8601 с часовым поясом | |
| `field.boolean()` | логическое значение | |
| `field.reference(Объект)` | `guid` объекта; цель задана в метаданных | |
| `field.reference()` | `{ kind, name, guid }`, ссылка на любой справочник или документ | |

У всех полей есть `title` и `required`. Табличные части и входные данные действий состоят из тех же полей. Поля регистра делятся на измерения (`.dimension`) — разрезы, по которым строки отбирают и группируют, — и ресурсы (`.resource`) — числа или деньги, которые суммируются. У регистра должен быть хотя бы один ресурс.

## Проверка повторов имён в типах

Методы билдера отклоняют повтор литерального имени при проверке типов. Для полей объекта проверяются также совпадения со стандартными полями его вида. Измерения и ресурсы регистра используют общий набор имён. Поля табличной части и входных данных действия проверяются внутри своей части или действия, поэтому одинаковое имя в разных частях допустимо. Отдельно проверяются повторы имён самих табличных частей и собственных действий.

Ограничение сохраняет тип имени и добавляет в ошибку текст причины, например `имя поля повторяется` или `имя поля совпадает со стандартным полем`, вместе с конфликтующим именем. Оно не меняет состояние билдера и поведение при выполнении.

Имя типа `string` не раскрывает конкретное значение, поэтому проходит проверку типов. После такого объявления накопленный набор ключей тоже может расшириться до `string`, и проверка повторов этого набора остаётся за `commit()`. Проверка стандартных полей выполняется отдельно и продолжает отклонять явно указанные стандартные имена. Все проверки сборки описания сохраняются, включая проверку имён, полученных во время выполнения.

## Проверки при сборке

`commit()` сообщает обо всех проблемах описания сразу:
- имена объектов, полей, табличных частей и действий — lowerCamelCase латиницей без `_`, не длиннее 60 символов и не совпадают с ключевыми словами SQLite: из них строятся имена таблиц и колонок;
- имена полей не повторяются и не совпадают со стандартными полями; имя табличной части не совпадает с именем поля;
- ссылка указывает на справочник или документ, который есть в конфигурации;
- границы и длины согласованы: минимум не больше максимума, у денег границы целые;
- имя собственного действия не совпадает со стандартным, у действия задан обработчик;
- обработчик проведения задан только у документа;
- представление по ссылке задано только у справочника и называет существующее обязательное поле-ссылку с заданной целью; цель сама не строит представление по ссылке: цепочки не поддерживаются;
- форма ссылается на существующие поля и табличные части; элемент входит не больше чем в одну группу, не бывает одновременно скрыт и выведен в группу; группа не пуста; `guid` и `deletedAt` не выводятся в группы; обязательное поле, которое заполняет пользователь, не скрыто; режим создания записи задан не больше одного раза;
- собственный элемент формы объявлен в файле `*.form-element.ts`; полем ввода он назначен существующему полю, которое пользователь заполняет на форме: не табличной части, не скрытому полю и не полю, которое заполняет платформа; одному полю назначен один элемент;
- стандартные поля добавлены, то есть вызван `withStandardFields()`.

`commitConfiguration` дополнительно проверяет, что имена объектов одного вида не повторяются.

## Проверка входных данных

По описанию строится Effect Schema (`src/server/metadata/schema.ts`):
- `inputSchema(description)` — входные данные записи объекта: поля, которые заполняет пользователь, и табличные части. Поля, которые заполняет платформа (`guid`, `deletedAt`, `number`, `posted`, `recorder`, `lineNumber`), в схему не входят;
- `actionInputSchema(description, action)` — входные данные собственного действия;
- `fieldsSchema(fields)` и `fieldSchema(field)` — схема набора полей и одного поля.

Обязательное поле должно быть передано, а обязательная строка не может быть пустой. Необязательное поле можно пропустить или передать `null`. Сообщения об ошибках — на русском.

## Стандартные поля

Стандартного поля `code` у справочников нет. Запись определяется GUID, а пользователю показывается наименование. Миграция `20261007_remove_catalog_code` удаляет прежнюю стандартную колонку и её индексы из существующих справочников, сохраняя GUID, остальные поля и внешние связи. Если прикладная конфигурация самостоятельно объявляет поле с именем `code`, миграция сохраняет это поле.

У каждого вида объектов есть свой набор стандартных полей. Он задан в одном месте — `src/server/metadata/standard-fields.ts`:
- у справочников: `guid`, `deletedAt`, `name`;
- у документов: `guid`, `deletedAt`, `number`, `date`, `posted`;
- у регистров движений: `recorder` — документ-регистратор (`{ document, guid }`), `period` — дата и время строки, `lineNumber` — номер строки среди строк того же регистратора. Своего `guid` и пометки удаления у строки регистра нет: её определяют регистратор и номер строки.

Список может уточняться по ходу работы. `guid` генерируется как UUIDv7: такие идентификаторы упорядочены по времени, поэтому новые записи добавляются в конец индекса, а не в случайные его места.

## Пометка удаления

Справочники и документы физически не удаляются. Пометкой служит поле `deletedAt`: если дата заполнена, объект помечен на удаление. Кто поставил пометку, фиксирует журнал. Сведения удаляются физически по измерениям, а движения удаляются при отмене проведения.

## Обнаружение объектов конфигурации

Во время работы исполняемого файла исходники `.ts` недоступны, поэтому объекты, страницы и элементы формы обнаруживаются на этапе сборки. Скрипт `scripts/metadata-generate.ts` (`npm run metadata:generate`) находит файлы объектов `src/configuration/**/*.{catalog,document,register,information-register}.ts`, файлы страниц (подраздел [«Страницы конфигурации»](#страницы-конфигурации)) и файлы элементов формы (подраздел [«Элементы формы»](#элементы-формы)) и генерирует в `src/configuration` четыре файла:

| Файл | Кому нужен | Содержимое |
|---|---|---|
| `configuration.generated.ts` | серверу | Импорт каждого файла объекта и каждого объявления страницы и элемента формы целиком, списки `configurationModules`, `pageModules` и `formElementModules` с путём файла и его экспортом, объект прав `Rights`, построенный из модулей объектов и страниц (раздел [«Права (RBAC)»](authorization.md)) |
| `objects.generated.ts` | клиенту | Ссылки на объекты `Objects` для страниц и элементов формы; файлы объектов импортируются только как типы |
| `pages.generated.ts` | клиенту | Реестр страниц: объявление и компонент каждой страницы |
| `form-elements.generated.ts` | клиенту | Реестр элементов формы: объявление и компонент каждого элемента |

- Сгенерированные файлы исключены из git и помечены комментарием, что вручную их не редактируют. Команды `dev`, `build` и `typecheck` сначала запускают генерацию, поэтому в новом клоне или worktree файлы появляются сами.
- В `npm run dev` скрипт работает с флагом `--watch`: при появлении, удалении или переименовании файла объекта или страницы реестры обновляются, `tsc --watch` пересобирает сервер, `node --watch` перезапускает его, а Vite обновляет клиент. Файл перезаписывается, только если его текст изменился.
- Ссылки на объекты и реестры компонентов лежат в разных файлах. Реестр импортирует компоненты страниц или элементов, а компоненты импортируют ссылки на объекты: в одном файле получился бы циклический импорт, и при загрузке компонента ссылки могли бы быть ещё не определены.
- Скрипт выполняется Node без сборки: Node 24 сам удаляет аннотации типов. Поэтому в скриптах допустим только стираемый синтаксис TypeScript, это проверяет `scripts/tsconfig.json` с `erasableSyntaxOnly`.

Платформа читает только сгенерированный реестр. Сервис метаданных (`MetadataService` в глобальном модуле `MetadataModule`) при запуске сервера:
1. извлекает билдер из экспорта каждого файла и проверяет соглашение: файл экспортирует ровно один билдер, а его вид совпадает с суффиксом файла (`*.catalog.ts` — `catalog(...)` и т. д.). Кроме билдера файл может экспортировать другие значения;
2. так же извлекает билдеры элементов формы из файлов объявлений и составляет перечень их имён;
3. добавляет стандартные поля методом `withStandardFields()`;
4. собирает описания через `commitConfiguration`, передавая перечень элементов формы для проверки форм.

Если нарушено соглашение о файлах или в описании есть ошибки, запуск останавливается с `MetadataError`, где перечислены все проблемы: файл или объект, место в описании и суть ошибки. Готовые описания сервис отдаёт платформе: `objects` — все объекты, `find(kind, name)` — один объект.

## Страницы конфигурации

Интерфейс объекта строится по его описанию: список и форма. Экран, который к ним не сводится, например рабочее место, конфигурация объявляет страницей. Страница состоит из двух файлов с общим началом имени:

```ts
// src/configuration/pages/sample-workplace.page.ts — объявление
import { page } from '../../server/ui/pages.js';

export const SampleWorkplace = page('sampleWorkplace').title('Пробное рабочее место');
```

```tsx
// src/configuration/pages/sample-workplace.page-component.tsx — компонент, экспорт по умолчанию
import { ActionButton, Page, RecordTable, useRecordList } from '../../web/sdk';
import { Objects } from '../objects.generated';

export default function SampleWorkplacePage() {
    const documents = Objects.document.sample;
    const list = useRecordList(documents, { permanentFilter: [{ field: 'posted', operator: 'equals', value: false }] });
    return (
        <Page title="Пробное рабочее место">
            <RecordTable object={documents} list={list} columns={['number', 'date', 'item']} />
        </Page>
    );
}
```

- Объявление отделено от компонента. Сервер собирает `src/configuration` без React и DOM, а имя и заголовок страницы нужны ему для меню и прав. Файлы `*.tsx` каталога конфигурации исключены из серверной сборки и проверяются настройками клиента.
- Имя страницы подчиняется правилам имён объектов и не повторяется. Оно входит в адрес `/page/<имя>` и в ключ права.
- Генератор находит страницы по именам файлов и сам проверяет парность: объявление без компонента и компонент без объявления останавливают генерацию с названием файла. В режиме слежения нарушение только выводится в журнал, а реестры остаются прежними: файлы страницы создаются по одному. Экспорт объявления (ровно один билдер страницы) и имя страницы сервер проверяет при запуске и останавливается с `MetadataError`.
- Страница не импортирует значения из файлов объектов. Файл объекта тянет за собой билдеры, Effect, обработчики действий и политики с чтением базы: такой импорт включил бы серверный код в сборку клиента. Объект страница указывает ссылкой `Objects.<вид>.<имя>` из `objects.generated.ts`. Тип ссылки выведен из билдера импортом только типа, а вид и имя во время работы берутся из пути обращения, который компилятор сверяет с билдерами. Поэтому генератору по-прежнему не нужно разбирать исходники, чтобы узнать имена объектов.
- Из клиента страница импортирует только web SDK. Границу проверяет скрипт `scripts/configuration-imports-check.ts`, который `npm run typecheck` запускает перед проверкой типов: импорт внутреннего модуля `src/web`, импорт значения из серверного кода или файла объекта останавливают проверку с названием файла и строки. Компилятор запрещать импорты по каталогам не умеет, поэтому проверка вынесена в скрипт.
- Описание страницы сервером в виде JSON отклонено: компонент попадает в клиент при сборке, а не через `/api/metadata`. Сервер сообщает клиенту только имена и заголовки доступных страниц.

Пробная страница «Пробное рабочее место» показывает непроведённые пробные документы и кнопку «Провести» для выбранной строки.

## Элементы формы

Стандартная форма выводит поля и табличные части из описания объекта. Блок с собственной логикой, например итог по табличной части или поле ввода с кнопкой, конфигурация объявляет элементом формы. Как и страница, элемент состоит из двух файлов с общим началом имени:

```ts
// src/configuration/form-elements/sample-total.form-element.ts — объявление
import { formElement } from '../../server/metadata/form-elements.js';

export const SampleTotal = formElement('sampleTotal');
```

```tsx
// src/configuration/form-elements/sample-total.form-element-component.tsx — компонент, экспорт по умолчанию
import { FieldDisplay, useFormValue } from '../../web/sdk';
import { Objects } from '../objects.generated';

export default function SampleTotal() {
    const lines = useFormValue(Objects.document.sample, 'lines');
    const total = lines.reduce((sum, line) => sum + (line.amount ?? 0), 0);
    return <FieldDisplay field={{ kind: 'money', target: null }} value={total} />;
}
```

- У объявления есть только имя. Оно подчиняется правилам имён объектов и не повторяется среди элементов. Место на форме задаёт переопределение формы объекта (подраздел [«Переопределение формы»](interface.md#переопределение-формы)), поэтому один элемент можно поставить на формы разных объектов.
- Обнаружение, парность файлов и граница импортов устроены так же, как у страниц: генератор находит пары файлов, сервер при запуске проверяет экспорт объявления, скрипт проверки импортов разрешает компоненту только web SDK и типы серверного кода.
- Права у элемента нет: он виден там, где видна форма, а доступ к данным проверяется по правам объектов.
- Элемент не обращается к форме Ant Design и к API напрямую. Значения формы и запись он получает из SDK (`useFormData`, `useFormValue`, раздел [«Web SDK»](interface.md#web-sdk)). Иначе смена устройства формы в платформе ломала бы элементы конфигурации.
- Сервер называет в описании формы только имя элемента и его место. Компонент клиент находит по имени в реестре `form-elements.generated.ts`. Реестр подключает стандартная форма, а не SDK: компоненты элементов сами импортируют SDK, и импорт реестра из SDK замкнул бы модули в кольцо.

- Элемент может управлять состоянием формы: сделать недоступной для изменения всю форму, отдельное поле или табличную часть и скрыть действие. Для этого он объявляет ограничения хуком `useFormRestrictions` (раздел [«Web SDK»](interface.md#web-sdk)) и может ничего не выводить. Условие вычисляет компонент, а не настройка в описании объекта: оно может зависеть от состояния записи, значений формы и данных других объектов, и описание объекта не разрастается настройками на каждый случай.
- Ограничения управляют только интерфейсом. Права и единый эндпоинт они не меняют: действие, скрытое на форме, по-прежнему выполняется через `/api/perform`, а запрет изменения записи задаёт политика записи объекта (раздел [«Политики записи»](write-policies.md)).

```tsx
// Элемент, который управляет состоянием формы и ничего не выводит
export default function SampleLock() {
    const form = useFormData(Objects.document.sample);
    const locked = (form.saved?.comment ?? null) !== null;
    useFormRestrictions(Objects.document.sample, locked ? { readOnly: true, hiddenActions: ['post'] } : {});
    return null;
}
```

Пробные элементы стоят на форме пробного документа: блок «Итого» под табличной частью «Строки» показывает сумму колонки «Сумма», а поле «Комментарий» заменено собственным полем ввода с кнопкой, которая подставляет текст «Проверено». Третий элемент управляет состоянием формы: документ с записанным комментарием нельзя изменить и провести с формы, о чём элемент сообщает строкой под полями.

## Пробные объекты

Пока прикладных объектов нет, платформу проверяют на пробных объектах: справочнике `src/configuration/catalogs/sample.catalog.ts`, документе `src/configuration/documents/sample.document.ts` и регистре `src/configuration/registers/sample.register.ts`. Документ ссылается на справочник в шапке и в табличной части, а при проведении записывает строки табличной части в регистр. Справочник `src/configuration/catalogs/sample-delegate.catalog.ts` строит представление по ссылке на пробный справочник; на него ссылается поле шапки пробного документа. На форме документа стоят пробные элементы формы из `src/configuration/form-elements/`.
