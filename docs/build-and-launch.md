# Сборка и запуск

| Команда | Что делает |
|---|---|
| `npm run dev` | Режим разработки: генератор реестров следит за файлами объектов и страниц, `tsc --watch` собирает сервер, `node --watch` перезапускает его при изменениях, Vite раздаёт клиент на порту 5173 и проксирует `/api` и `/docs` на Nest. Сайт документации собирается один раз при запуске |
| `npm run build` | Генерация реестров конфигурации, сборка сервера (`tsc`) в `dist/server`, клиента (Vite) в `dist/web` и сайта документации (VitePress) в `dist/docs` |
| `npm run build:docs` | Сборка сайта документации из каталога `docs` в `dist/docs` |
| `npm run docs:dev` | Сайт документации на порту 5174 с обновлением при правке файлов (раздел [«Документация»](documentation.md)) |
| `npm run build:executable` | На Windows x64 собирает сервер, клиент и сайт документации, затем создаёт `dist/executable/collection-zarplata.exe` |
| `npm start` | Запуск собранного приложения: Nest отдаёт API, клиент и сайт документации на порту из файла настроек |
| `npm run start:check` | Сборка и запуск на пустой базе в памяти без файла настроек, для ручной проверки. Дополнительные параметры передаются после `--`: `npm run start:check -- --test-pin=482915 --port=3101` |
| `npm run docs:check` | Перечень разделов документации, код которых изменён относительно `main` (раздел [«Документация»](documentation.md#связь-разделов-с-кодом)) |
| `npm run typecheck` | Генерация реестров, проверка импортов страниц конфигурации, проверка связи документации с кодом, проверка типов и правил Effect для сервера, скриптов, настройки сайта документации и клиента |
| `npm run metadata:generate` | Генерация реестров конфигурации: объектов и страниц |

- Сервер компилируется самим `tsc` (TypeScript 7), без Nest CLI.
- Сервер использует ES-модули (`"type": "module"`), поэтому относительные импорты пишутся с расширением `.js`.
- Конфигурации TypeScript: `tsconfig.base.json` — общие правила и плагин Effect; `tsconfig.json` — сервер и конфигурация без компонентов страниц и сгенерированных файлов клиента; `scripts/tsconfig.json` — служебные скрипты, только проверка; `docs/tsconfig.json` — настройка сайта документации, только проверка; `src/web/tsconfig.json` — клиент, компоненты страниц конфигурации и сгенерированные файлы клиента.
- Настройки запуска читаются из `collection-zarplata.settings.json`. При запуске `.exe` файл должен лежать рядом с ним; при `npm start` и `npm run dev` — в корне проекта. Образец — `collection-zarplata.settings.example.json`. Отсутствие файла или неверные значения останавливают запуск с сообщением об ошибке.
- Поля настроек: `host` — адрес интерфейса, `port` — порт от 1 до 65535, `databasePath` — путь к файлу базы относительно каталога настроек (допустим и абсолютный путь), `pinHmacSecret` — секрет длиной не меньше 32 символов для HMAC PIN и подписи access-токенов. Заполните секрет случайным значением, например сгенерируйте 32 байта командой `node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"` на машине сборки. Настоящий секрет хранится только в локальном файле настроек; этот файл исключён из Git. Для создания первого пользователя временно добавьте `initialUser`, как описано в разделе [«Вход в приложение»](authentication.md). В режиме разработки оставляйте порт 3000, на который Vite направляет запросы `/api`.
- Параметры запуска передаются в виде `--имя=значение` после `main.js` или имени `.exe`. Неизвестный параметр или неверное значение останавливают запуск.
  - `--database=memory` открывает пустую базу в памяти. Файл настроек в этом режиме не читается: сервер слушает `127.0.0.1`, порт по умолчанию 3100, секрет HMAC создаётся случайным при каждом запуске. Данные, пользователи и токены исчезают после остановки процесса, о чём сервер предупреждает в журнале при запуске. Таблицы создаёт синхронизация структуры, как на новом файле базы. `--database=file` — обычный режим, он действует без параметра.
  - `--test-pin=<4–12 цифр>` в режиме памяти создаёт при запуске тестового пользователя с этим PIN и всеми ролями конфигурации. Роли можно ограничить: `--test-pin=111111:reader` или `--test-pin=111111:reader,cashier`. Параметр можно повторять, чтобы создать нескольких пользователей с разными PIN; неизвестная роль или повтор PIN останавливают запуск. Вне режима памяти параметр останавливает запуск: он создал бы постоянного пользователя в рабочей базе.
  - `--port=<1–65535>` заменяет порт из настроек в любом режиме. Порт сервера выбирает отдельный провайдер-фабрика: значение параметра, если он передан, иначе порт из настроек.
