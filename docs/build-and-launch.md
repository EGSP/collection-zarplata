# Сборка и запуск

Раздел описывает запуск из исходников: разработку, сборку и ручную проверку на временной базе. Команды выполняются из корня рабочего каталога репозитория. Сборка и установка исполняемого файла для Windows описаны в разделе [«Поставка»](delivery.md).

## Подготовка рабочего каталога

Для работы нужны Node.js 24 и npm: служебные скрипты запускаются непосредственно из TypeScript благодаря удалению аннотаций типов в Node.js. Установите зависимости командой `npm install`. При установке скрипт `prepare` подключает `effect-tsgo` к команде `tsc`, поэтому последующая проверка охватывает типы и правила Effect.

Для разработки и обычного запуска подготовьте `collection-zarplata.settings.json` в корне рабочего каталога:

1. Скопируйте [образец настроек](https://github.com/EGSP/collection-zarplata/blob/main/collection-zarplata.settings.example.json).
2. Заполните `pinHmacSecret` случайным значением длиной не меньше 32 символов. Например, сгенерируйте 32 случайных байта в шестнадцатеричном виде:

   ```bash
   node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
   ```

3. Укажите адрес, порт и путь к базе по [справочнику настроек](#файл-настроек). Для режима разработки оставьте `host` равным `127.0.0.1` и `port` равным `3000`: на этот адрес направляет запросы Vite.
4. Если база новая, временно добавьте `initialUser` по инструкции [создания первого пользователя](authentication.md). Без пользователя войти в приложение нельзя.

Локальный файл настроек исключён из Git. Настоящий секрет хранится в нём, а не в образце. Для ручной проверки на базе в памяти файл настроек не требуется.

## Запуск для разработки

В подготовленном рабочем каталоге выполните:

```bash
npm run dev
```

Команда сначала генерирует реестры конфигурации, собирает сервер и документацию, затем запускает наблюдение за исходниками. Откройте `http://localhost:5173`: после входа должен появиться интерфейс приложения. Vite отдаёт клиент и направляет запросы `/api` и `/docs` на сервер `127.0.0.1:3000`.

Изменение серверного кода вызывает пересборку и перезапуск сервера. Vite обновляет клиент при правке его исходников. Генератор следит за добавлением, удалением и переименованием объектов, страниц и элементов формы. Описание соглашений о файлах находится в разделе [«Метаданные»](metadata.md).

Документация через `/docs/` показывает сборку, выполненную при запуске команды. Чтобы увидеть её правки, выполните `npm run build:docs`. Для редактирования с автоматическим обновлением страницы запустите отдельно `npm run docs:dev` и откройте `http://localhost:5174/docs/`.

## Сборка и обычный запуск

После установки зависимостей и подготовки файла настроек выполните:

```bash
npm run typecheck
npm run build
npm start
```

Проверка типов должна завершиться без ошибок и предупреждений Effect. Сборка создаёт сервер в `dist/server`, клиент в `dist/web` и сайт документации в `dist/docs`. Запуск использует готовые результаты сборки: изменение исходников само по себе их не обновляет.

Откройте адрес из `host` и `port` файла настроек, например `http://127.0.0.1:3000`. На одном порту сервер отдаёт API, интерфейс приложения и документацию по `/docs/`. Проверьте вход и действие, ради которого собирали приложение. Ошибка чтения или проверки настроек останавливает запуск с сообщением о причине.

## Ручная проверка на временной базе

Этот способ подходит для проверки изменений без рабочего файла базы и локальных настроек. После установки зависимостей выполните проверку типов, затем запустите приложение на свободном порту, отличном от `3000` и `5173`:

```bash
npm run typecheck
npm run start:check -- --test-pin=482915 --port=3101
```

Команда собирает приложение и открывает новую пустую базу в памяти. Синхронизация структуры создаёт таблицы; указанный PIN создаёт тестового пользователя со всеми ролями конфигурации. Откройте `http://127.0.0.1:3101`, войдите с PIN `482915` и выполните проверяемый сценарий в интерфейсе или через API. Формат запросов описан в разделе [«API данных»](single-endpoint.md).

Для проверки ограниченных прав добавьте второго пользователя. Имя роли должно существовать в конфигурации:

```bash
npm run start:check -- --test-pin=482915 --test-pin=111111:reader --port=3101
```

После остановки процесса данные, пользователи и токены исчезают. Следующий запуск начинает проверку с пустой базы. Сервер сообщает об этом режиме в журнале при запуске. Создавать файл базы или удалять данные после проверки не требуется.

При запуске через средство управления фоновыми задачами остановите свою задачу после проверки. На Windows убедитесь, что её дочерние процессы завершились и выбранный порт освободился: остановка фоновой задачи может оставить процессы `node`, Vite или компилятора работающими. Процессы других экземпляров приложения завершать не нужно.

## Команды npm

Команды определены в [package.json](https://github.com/EGSP/collection-zarplata/blob/main/package.json). Дополнительные аргументы запуска приложения передаются после `--`, например `npm start -- --port=3101`.

| Команда | Результат и условия |
|---|---|
| `npm install` | Устанавливает зависимости и выполняет `prepare`, который подключает `effect-tsgo` к TypeScript |
| `npm run dev` | Генерирует реестры, собирает сервер и документацию, затем запускает параллельно `dev:metadata`, `dev:build`, `dev:server` и `dev:web` |
| `npm run dev:metadata` | Следит за файлами конфигурации и обновляет реестры при изменениях |
| `npm run dev:build` | Компилирует сервер в режиме наблюдения |
| `npm run dev:server` | Запускает `dist/server/main.js` с картами исходников и перезапускает при изменении собранных файлов; требуется готовая сборка сервера |
| `npm run dev:web` | Запускает Vite для клиента на порту `5173`; проксирует `/api` и `/docs` на `127.0.0.1:3000` |
| `npm run build` | Генерирует реестры, затем собирает сервер, клиент и документацию |
| `npm run build:server` | Компилирует сервер и серверную часть конфигурации в `dist`; точка входа находится в `dist/server/main.js` |
| `npm run build:web` | Собирает клиент в `dist/web` |
| `npm run build:docs` | Собирает сайт документации в `dist/docs` |
| `npm run docs:dev` | Запускает сайт документации на порту `5174` с обновлением при правке исходников |
| `npm run build:executable` | На Windows x64 выполняет полную сборку и создаёт `dist/executable/collection-zarplata.exe`; требования и порядок поставки описаны в [отдельном разделе](delivery.md) |
| `npm start` | Запускает собранное приложение; по умолчанию читает настройки и использует файловую базу |
| `npm run start:check` | Выполняет полную сборку и запускает приложение с `--database=memory`; PIN и порт можно передать дополнительными аргументами |
| `npm run metadata:generate` | Генерирует серверный реестр конфигурации, ссылки на объекты для клиента, реестр страниц и реестр элементов формы |
| `npm run typecheck` | Генерирует реестры, проверяет границы импортов компонентов конфигурации, связь документации с кодом, типы и правила Effect для сервера, скриптов, настройки сайта и клиента |
| `npm run diagnostics` | Выводит подробные диагностики Effect для серверного проекта |
| `npm run docs:check` | Перечисляет разделы, код которых изменён относительно `main`, и проверяет шаблоны `covers`; [правила проверки](documentation.md#связь-разделов-с-кодом) описаны в разделе документации |

Отдельные команды `build:server` и `build:web` не запускают генератор реестров. Если изменился состав файлов конфигурации, сначала выполните `npm run metadata:generate` или используйте полную сборку. Сгенерированные файлы вручную не редактируются: следующая генерация заменит изменения.

## Файл настроек

В обычном файловом режиме сервер читает `collection-zarplata.settings.json`. При `npm start` и `npm run dev` файл ищется в текущем рабочем каталоге; команды из этого раздела выполняются из корня проекта. Исполняемый файл ищет настройки рядом с собой.

Корень файла должен быть объектом JSON. Обязательные поля и необязательное создание первого пользователя имеют следующий формат:

| Поле | Формат и назначение |
|---|---|
| `host` | Непустая строка с адресом интерфейса, на котором слушает сервер |
| `port` | Целое число от `1` до `65535`. Параметр `--port` заменяет его при запуске |
| `databasePath` | Непустая строка с путём к файлу базы. Относительный путь отсчитывается от каталога настроек; абсолютный путь также допустим |
| `pinHmacSecret` | Строка длиной не меньше 32 символов. Используется для HMAC PIN и подписи access-токенов |
| `initialUser` | Необязательный объект с непустым строковым `name`, строковым `pin` из 4–12 цифр и необязательным массивом строк `roles`. Без `roles` пользователь получает все роли конфигурации. Порядок создания и удаления этой настройки описан в [разделе о входе](authentication.md) |

Отсутствующий файл, ошибка JSON или неверное значение проверяемого поля останавливают запуск. Переданный `--port` не отменяет чтение и проверку файла в файловом режиме: `port` в JSON всё равно должен быть допустимым.

Чтение и проверка реализованы в [сервисе настроек](https://github.com/EGSP/collection-zarplata/blob/main/src/server/settings/settings.service.ts).

## Параметры командной строки

Параметры имеют только форму `--имя=значение` и идут после `main.js` или имени исполняемого файла. При запуске через npm перед ними ставится `--`. Неизвестный параметр или неверный формат значения останавливает запуск.

| Параметр | Значения | Поведение |
|---|---|---|
| `--database` | `file` или `memory` | По умолчанию `file`: используется файл настроек и файловая база. В режиме `memory` настройки из JSON не читаются, база пуста при каждом запуске, адрес равен `127.0.0.1`, порт по умолчанию `3100`, секрет HMAC создаётся случайным |
| `--port` | Цифры, представляющие число от `1` до `65535` | Заменяет порт из файла настроек или порт режима памяти |
| `--test-pin` | PIN из 4–12 цифр; необязательно `:<роль>` или `:<роль1>,<роль2>` | Только в режиме памяти создаёт тестового пользователя. Без списка ролей выдаёт все роли конфигурации. Имена ролей в аргументе состоят из латинских букв и цифр |

Параметр `--test-pin` можно повторять для разных PIN. Повтор PIN, неизвестная роль или попытка использовать параметр с файловой базой останавливают запуск. Несколько `--database` или `--port` допускаются; применяется последнее значение соответствующего параметра.

Разбор аргументов находится в [модуле параметров запуска](https://github.com/EGSP/collection-zarplata/blob/main/src/server/settings/launch-arguments.ts). Итоговый порт выбирается с приоритетом аргумента перед настройкой в [провайдере порта](https://github.com/EGSP/collection-zarplata/blob/main/src/server/settings/server-port.ts).

## Переменные окружения для сроков токенов

Эти переменные действуют в обоих режимах базы. Короткие сроки позволяют вручную проверить обновление токенов без ожидания штатного истечения.

| Переменная | Значение по умолчанию | Назначение |
|---|---|---|
| `ACCESS_TOKEN_LIFETIME_SECONDS` | `900` (15 минут) | Срок access-токена и его cookie |
| `REFRESH_TOKEN_LIFETIME_SECONDS` | `604800` (семь дней) | Срок refresh-токена и его cookie |

Значение задаётся положительным целым числом секунд, записанным цифрами без ведущих нулей и не превышающим безопасное целое число JavaScript. Отсутствующая или пустая переменная оставляет значение по умолчанию; другое неверное значение останавливает запуск. Поведение входа, обновления токенов и cookie описано в разделе [«Вход в приложение»](authentication.md).

## Устройство компиляции

Сервер компилируется командой `tsc` без Nest CLI. В проекте используется TypeScript 7 с `effect-tsgo`. Сервер работает как ES-модули (`"type": "module"`), поэтому относительные импорты серверного кода пишутся с расширением `.js`.

Серверная и клиентская части проверяются раздельно: серверу нужны модули Node.js и декораторы NestJS, клиенту нужны DOM и JSX. Служебные скрипты и настройка документации имеют собственные проекты для проверки типов.

| Конфигурация TypeScript | Область |
|---|---|
| [tsconfig.base.json](https://github.com/EGSP/collection-zarplata/blob/main/tsconfig.base.json) | Общие строгие правила типов и плагин Effect |
| [tsconfig.json](https://github.com/EGSP/collection-zarplata/blob/main/tsconfig.json) | Сервер и конфигурация без компонентов React и сгенерированных клиентских реестров |
| [scripts/tsconfig.json](https://github.com/EGSP/collection-zarplata/blob/main/scripts/tsconfig.json) | Служебные скрипты, только проверка типов |
| [docs/tsconfig.json](https://github.com/EGSP/collection-zarplata/blob/main/docs/tsconfig.json) | Настройка сайта документации, только проверка типов |
| [src/web/tsconfig.json](https://github.com/EGSP/collection-zarplata/blob/main/src/web/tsconfig.json) | Клиент, компоненты страниц и элементов формы конфигурации, сгенерированные клиентские реестры |

Прокси и выходной каталог клиента заданы в [vite.config.ts](https://github.com/EGSP/collection-zarplata/blob/main/vite.config.ts). Правила формирования реестров реализованы в [генераторе метаданных](https://github.com/EGSP/collection-zarplata/blob/main/scripts/metadata-generate.ts).
