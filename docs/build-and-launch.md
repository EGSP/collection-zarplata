# Сборка и запуск

Раздел описывает запуск из исходников: разработку, сборку и ручную проверку на временной базе. Команды выполняются из корня рабочего каталога. Сборка исполняемого файла для Windows описана в разделе [«Поставка»](delivery.md).

## Подготовка рабочего каталога

Нужны Node.js 24 и npm. Служебные скрипты запускаются прямо из TypeScript, потому что Node.js удаляет аннотации типов. Установите зависимости командой `npm install`: скрипт `prepare` подключает `effect-tsgo` к `tsc`, и проверка типов охватывает правила Effect.

Для разработки и обычного запуска подготовьте `collection-zarplata.settings.json` в корне. Он исключён из Git, а настоящий секрет хранится только в нём. Для проверки на базе в памяти файл не нужен.

1. Скопируйте [образец настроек](https://github.com/EGSP/collection-zarplata/blob/main/collection-zarplata.settings.example.json).
2. Заполните `pinHmacSecret` случайной строкой не короче 32 символов:

   ```bash
   node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
   ```

3. Задайте адрес, порт и путь к базе по [справочнику настроек](#файл-настроек). Для режима разработки оставьте `host` равным `127.0.0.1` и `port` равным `3000`: на этот адрес Vite направляет запросы.
4. Добавьте `initialUser` без `roles` по инструкции [создания первого пользователя](authentication.md). Без него нельзя войти в новую базу и применить первичные данные.
5. Соберите утилиту импорта по [её руководству](https://github.com/EGSP/collection-zarplata/blob/main/tools/1c-xml-import/README.md) и положите XML-выгрузки 1С в `tools/1c-xml-import/local-source`. При каждом запуске сервер загружает из них физических лиц и номенклатуру ([«Первичные данные»](initial-data.md)).

## Запуск для разработки

```bash
npm run dev
```

Команда генерирует реестры конфигурации, собирает сервер и документацию, затем следит за исходниками. Откройте `http://localhost:5173`: Vite отдаёт клиент и направляет `/api` и `/docs` на сервер `127.0.0.1:3000`.

Правка серверного кода пересобирает и перезапускает сервер, правка клиента обновляется в Vite. Генератор следит за добавлением, удалением и переименованием объектов, страниц и элементов формы ([«Метаданные»](metadata.md)).

`/docs/` показывает документацию, собранную при запуске команды. Чтобы увидеть правки, выполните `npm run build:docs` или запустите `npm run docs:dev` и откройте `http://localhost:5174/docs/`: там страница обновляется сама.

## Сборка и обычный запуск

```bash
npm run typecheck
npm run build
npm start
```

Проверка типов должна пройти без ошибок и предупреждений Effect. Сборка создаёт сервер в `dist/server`, клиент в `dist/web`, документацию в `dist/docs`. Запуск использует готовую сборку: правка исходников её не обновляет.

Откройте адрес из `host` и `port`, например `http://127.0.0.1:3000`. Один порт отдаёт API, интерфейс и документацию по `/docs/`. Ошибка чтения или проверки настроек останавливает запуск с сообщением о причине.

## Ручная проверка на временной базе

Способ подходит для проверки изменений без рабочей базы и локальных настроек. Выберите свободный порт, отличный от `3000` и `5173`:

```bash
npm run typecheck
npm run start:check -- --test-pin=482915 --port=3101
```

Команда собирает приложение и открывает пустую базу в памяти. Синхронизация структуры создаёт таблицы, а PIN создаёт тестового пользователя со всеми ролями. После открытия порта сервер загружает [первичные данные](initial-data.md) от имени этого пользователя, поэтому нужны собранная утилита импорта и выгрузки в `tools/1c-xml-import/local-source`. Загрузка занимает несколько секунд, её завершение сервер пишет в журнал.

Откройте `http://127.0.0.1:3101`, войдите с PIN `482915` и пройдите проверяемый сценарий в интерфейсе или через API ([«API данных»](single-endpoint.md)).

Для проверки ограниченных прав добавьте второго пользователя с ролью, которая существует в конфигурации. Пользователь без ролей остаётся обязательным: от его имени загружаются первичные данные.

```bash
npm run start:check -- --test-pin=482915 --test-pin=111111:reader --port=3101
```

После остановки процесса данные, пользователи и токены исчезают, удалять после проверки нечего. При запуске через средство фоновых задач остановите свою задачу сами. На Windows убедитесь, что дочерние процессы `node`, Vite и компилятора завершились и порт свободен: остановка задачи может их оставить. Процессы других экземпляров приложения не трогайте.

### Сохраняемая тестовая база

База в памяти пуста при каждом запуске. Чтобы данные проверки переживали перезапуск, укажите файл вместо `--database=memory`:

```bash
npm run start:check -- --test-database=C:/Temp/collection-zarplata-test/test.db --test-pin=482915 --port=3101
```

Режим во всём, кроме хранения, совпадает с режимом памяти: файл настроек не читается, адрес `127.0.0.1`, порт по умолчанию `3100`, допустимы `--test-pin` и автовход. Секрет HMAC лежит рядом с базой в файле `<база>.secret`. Он создаётся при первом запуске, поэтому после перезапуска пользователи входят с прежними PIN.

- Пользователи создаются только в пустой таблице. Роли и PIN из параметров последующих запусков на существующих пользователей не влияют.
- Первичные данные загружаются при каждом запуске, но импорт обновляет записи без дубликатов, а сотрудники создаются один раз.
- Чтобы начать с пустой базы, остановите сервер и удалите каталог с базой и секретом.

Журнал при запуске предупреждает, что используется тестовая файловая база.

### Автовход

Автовход избавляет от ввода PIN. Его PIN должен совпадать с одним из `--test-pin`:

```bash
npm run start:check -- --test-pin=482915 --test-pin=111111:reader --auto-login-pin=482915 --port=3101
```

Тот же PIN задаёт переменная окружения `AUTO_LOGIN_PIN`, тогда его не нужно повторять в командах. В PowerShell:

```powershell
$env:AUTO_LOGIN_PIN = '482915'
npm run start:check -- --test-pin=482915 --port=3101
```

Браузер без сессии сразу открывает приложение от имени этого пользователя: после первого отказа клиент обновляет токены, и сервер вместо отказа выдаёт новую сессию. Кнопка «Выйти» открывает экран входа, где можно войти другим тестовым пользователем. После перезагрузки страницы без сессии сервер снова входит по PIN автовхода. При запуске журнал предупреждает об автовходе.

Параметр `--auto-login-pin` важнее переменной. Пустая переменная автовход не включает, значение не из 4–12 цифр останавливает запуск. Автовход допустим только в режиме памяти и с `--test-database`. Если переменная задана в оболочке, а приложение запускается с файловой базой, запуск тоже остановится: удалите переменную командой `Remove-Item Env:AUTO_LOGIN_PIN`.

## Команды npm

Команды определены в [package.json](https://github.com/EGSP/collection-zarplata/blob/main/package.json). Аргументы приложения передаются после `--`: `npm start -- --port=3101`.

| Команда | Результат и условия |
|---|---|
| `npm install` | Устанавливает зависимости и выполняет `prepare` |
| `npm run dev` | Генерирует реестры, собирает сервер и документацию, затем параллельно запускает `dev:metadata`, `dev:build`, `dev:server` и `dev:web` |
| `npm run dev:metadata` | Следит за файлами конфигурации и обновляет реестры |
| `npm run dev:build` | Компилирует сервер в режиме наблюдения |
| `npm run dev:server` | Запускает `dist/server/main.js` с картами исходников и перезапускает при изменении сборки; нужна готовая сборка сервера |
| `npm run dev:web` | Запускает Vite на порту `5173`, проксирует `/api` и `/docs` на `127.0.0.1:3000` |
| `npm run build` | Генерирует реестры, собирает сервер, клиент и документацию |
| `npm run build:server` | Компилирует сервер и серверную часть конфигурации в `dist`; вход в `dist/server/main.js` |
| `npm run build:web` | Собирает клиент в `dist/web` |
| `npm run build:docs` | Собирает документацию в `dist/docs` |
| `npm run docs:dev` | Запускает сайт документации на порту `5174` с обновлением при правках |
| `npm run build:executable` | На Windows x64 выполняет полную сборку и создаёт `dist/executable/collection-zarplata.exe` ([«Поставка»](delivery.md)) |
| `npm start` | Запускает собранное приложение; по умолчанию читает настройки и использует файловую базу |
| `npm run start:check` | Выполняет полную сборку и запускает приложение с `--database=memory`; PIN и порт передаются аргументами |
| `npm run metadata:generate` | Генерирует серверный реестр конфигурации, ссылки на объекты для клиента, реестр страниц и реестр элементов формы |
| `npm run typecheck` | Генерирует реестры, проверяет границы импортов компонентов конфигурации, связь документации с кодом, типы и правила Effect для сервера, скриптов, настройки сайта и клиента |
| `npm run diagnostics` | Выводит подробные диагностики Effect для серверного проекта |
| `npm run docs:check` | Перечисляет разделы, код которых изменён относительно `main`, и проверяет шаблоны `covers` ([правила](documentation.md#связь-разделов-с-кодом)) |

`build:server` и `build:web` не запускают генератор реестров. Если изменился состав файлов конфигурации, сначала выполните `npm run metadata:generate` или полную сборку. Сгенерированные файлы вручную не правятся: следующая генерация их заменит.

## Файл настроек

В файловом режиме сервер читает `collection-zarplata.settings.json`. При `npm start` и `npm run dev` файл ищется в текущем каталоге, поэтому команды выполняются из корня проекта. Исполняемый файл ищет настройки рядом с собой.

Корень файла должен быть объектом JSON:

| Поле | Формат и назначение |
|---|---|
| `host` | Непустая строка с адресом интерфейса, на котором слушает сервер |
| `port` | Целое число от `1` до `65535`; параметр `--port` заменяет его |
| `databasePath` | Непустая строка с путём к файлу базы. Относительный путь отсчитывается от каталога настроек, абсолютный тоже допустим |
| `pinHmacSecret` | Строка не короче 32 символов: ключ HMAC для PIN и подписи access-токенов |
| `backup` | Необязательный объект [резервного копирования](backup.md#настройки): `schedule` (список строк cron) и `keep` (сколько копий хранить, по умолчанию 30). Копии лежат в каталоге `backups` рядом с файлом настроек |
| `initialUser` | Необязательный объект: непустая строка `name`, строка `pin` из 4–12 цифр, необязательный массив строк `roles` (без него пользователь получает все роли). Порядок создания и удаления описан в [разделе о входе](authentication.md) |
| `initialData` | Необязательный объект с логическим `createRandomEmployees`: при `true` первичная загрузка создаёт четырёх случайных сотрудников, если сотрудников ещё нет. По умолчанию `false`. В тестовых режимах без файла настроек генерация включена |

Отсутствующий файл, ошибка JSON или неверное значение останавливают запуск. `--port` не отменяет проверку файла: `port` в JSON всё равно должен быть допустимым.

Чтение и проверка реализованы в [сервисе настроек](https://github.com/EGSP/collection-zarplata/blob/main/src/server/settings/settings.service.ts).

## Параметры командной строки

Параметры имеют форму `--имя=значение` и идут после `main.js` или имени исполняемого файла; в npm перед ними ставится `--`. Неизвестный параметр или неверное значение останавливает запуск.

| Параметр | Значения | Поведение |
|---|---|---|
| `--database` | `file` или `memory` | По умолчанию `file`: файл настроек и файловая база. При `memory` настройки не читаются, база пуста при каждом запуске, адрес `127.0.0.1`, порт по умолчанию `3100`, секрет HMAC случайный |
| `--test-database` | Путь к файлу базы | Режим с [сохраняемой базой](#сохраняемая-тестовая-база): как `memory`, но база и секрет хранятся в файлах. Относительный путь отсчитывается от текущего каталога |
| `--port` | Число от `1` до `65535` цифрами | Заменяет порт из файла настроек или порт режима памяти |
| `--test-pin` | PIN из 4–12 цифр; необязательно `:<роль>` или `:<роль1>,<роль2>` | Создаёт тестового пользователя, только в режиме памяти и с `--test-database`. Без ролей выдаёт все роли конфигурации. Имена ролей состоят из латинских букв и цифр |
| `--auto-login-pin` | PIN из 4–12 цифр, совпадающий с одним из `--test-pin` | Включает [автовход](#автовход) от имени этого пользователя, только в режиме памяти и с `--test-database` |
| `--test-backup-schedule` | Строка cron | Задаёт [расписание копий](backup.md#настройки) тестовой базы. Повторяемый; только с `--test-database`, копии лежат в `backups` рядом с файлом базы |

Ограничения:

- `--test-pin` можно повторять, но PIN не должны совпадать. Неизвестная роль останавливает запуск.
- `--test-pin` с рабочей базой (`--database=file`) останавливает запуск.
- Автовход с рабочей базой или с PIN, которого нет среди `--test-pin`, останавливает запуск: в рабочей базе он пускал бы в приложение любого, кто откроет адрес.
- Повтор `--database`, `--test-database` или `--port` допустим, действует последний. Режим базы выбирает последний из `--database` и `--test-database`.

Разбор аргументов находится в [модуле параметров запуска](https://github.com/EGSP/collection-zarplata/blob/main/src/server/settings/launch-arguments.ts). Приоритет аргумента `--port` над настройкой задаёт [провайдер порта](https://github.com/EGSP/collection-zarplata/blob/main/src/server/settings/server-port.ts).

## Переменные окружения

`AUTO_LOGIN_PIN` задаёт PIN [автовхода](#автовход) наравне с `--auto-login-pin`.

Сроки токенов действуют в обоих режимах базы. Короткие сроки позволяют проверить обновление токенов, не дожидаясь штатного истечения.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `ACCESS_TOKEN_LIFETIME_SECONDS` | `900` (15 минут) | Срок access-токена и его cookie |
| `REFRESH_TOKEN_LIFETIME_SECONDS` | `604800` (семь дней) | Срок refresh-токена и его cookie |

Значение сроков: положительное целое число секунд цифрами, без ведущих нулей, в пределах безопасного целого JavaScript. Отсутствующая или пустая переменная оставляет значение по умолчанию, другое неверное значение останавливает запуск. Вход, обновление токенов и cookie описаны в разделе [«Вход в приложение»](authentication.md).

## Устройство компиляции

Сервер компилируется командой `tsc` без Nest CLI, на TypeScript 7 с `effect-tsgo`. Он работает как ES-модули (`"type": "module"`), поэтому относительные импорты серверного кода пишутся с расширением `.js`.

Серверная и клиентская части проверяются раздельно: серверу нужны модули Node.js и декораторы NestJS, клиенту DOM и JSX. Служебные скрипты и настройка документации имеют собственные проекты, только для проверки типов.

| Конфигурация TypeScript | Область |
|---|---|
| [tsconfig.base.json](https://github.com/EGSP/collection-zarplata/blob/main/tsconfig.base.json) | Общие строгие правила типов и плагин Effect |
| [tsconfig.json](https://github.com/EGSP/collection-zarplata/blob/main/tsconfig.json) | Сервер и конфигурация без компонентов React и сгенерированных клиентских реестров |
| [scripts/tsconfig.json](https://github.com/EGSP/collection-zarplata/blob/main/scripts/tsconfig.json) | Служебные скрипты |
| [docs/tsconfig.json](https://github.com/EGSP/collection-zarplata/blob/main/docs/tsconfig.json) | Настройка сайта документации |
| [src/web/tsconfig.json](https://github.com/EGSP/collection-zarplata/blob/main/src/web/tsconfig.json) | Клиент, компоненты страниц и элементов формы, сгенерированные клиентские реестры |

Прокси, выходной каталог и точки входа клиента заданы в [vite.config.ts](https://github.com/EGSP/collection-zarplata/blob/main/vite.config.ts). Кроме приложения (`index.html`), клиент собирает страницу [графа модулей](development-tools.md#граф-модулей-сервера) (`modules-graph.html`); в разработке Vite отдаёт её по `/modules-graph`. Реестры формирует [генератор метаданных](https://github.com/EGSP/collection-zarplata/blob/main/scripts/metadata-generate.ts).
