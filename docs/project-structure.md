# Структура проекта

Справочник отвечает на вопрос, где в репозитории искать код и какой раздел документации его описывает. Код платформы находится в `src/server` и `src/web`, прикладная конфигурация магазина в `src/configuration`, код общий для сервера и клиента в `src/common`.

```text
src/
  server/             сервер платформы
  web/                клиент платформы и web SDK
  configuration/      объекты, правила и экраны магазина
  common/             код, общий для сервера и клиента
docs/                 архитектура и сайт документации
scripts/              генерация, проверки и сборка приложения
tools/                самостоятельные инструменты
repos/                исходники внешних библиотек для изучения
```

### Генерируемые реестры

Пять файлов `*.generated.ts` в корне `src/configuration` формирует [генератор метаданных](https://github.com/EGSP/collection-zarplata/blob/main/scripts/metadata-generate.ts). Они исключены из git: вручную их не правят.

| Файл | Назначение |
|---|---|
| `configuration.generated.ts` | Серверный реестр объектов, объявлений страниц, элементов формы и форм объектов, объект прав `Rights` |
| `objects.generated.ts` | Ссылки `Objects` на объекты для клиентских компонентов; импорты объектов используются только как типы |
| `pages.generated.ts` | Клиентский реестр объявлений и компонентов страниц |
| `form-elements.generated.ts` | Клиентский реестр объявлений и компонентов элементов формы |
| `object-forms.generated.ts` | Клиентский реестр форм объектов |

Правила обнаружения файлов и проверки объявлений описаны в [метаданных](metadata.md), порядок генерации в [«Сборке и запуске»](build-and-launch.md).

### Устройство расчёта зарплаты

Расчёт разделён на данные, правила и исполнение, чтобы новое правило не затрагивало остальные.

| Файл | Роль |
|---|---|
| `payroll-context.ts` | Типы данных периода (у части продажи и строки начисления есть `installmentDate`, дата открытия рассрочки), сервис Effect `PayrollContext` и общие функции: `allocate` делит сумму между долями методом наибольших остатков, `percentOf` считает процент с округлением половины вверх |
| `payroll-rules.ts` | Правило задаётся объектом `PayrollRuleDefinition` с полями `name`, `title`, `description` и `calculate`. Эффект `calculate` читает данные из `PayrollContext` и возвращает строки начисления с текстом правила. Описания строятся из тех же констант, что и расчёт, например из границы ступени. Ступень ставки вынесена в чистую функцию `goodsRate` |
| `payroll.ts` | Читает документы периода из базы, кладёт их в контекст, выполняет правила `payrollRules.rules` через `Effect.forEach` и складывает строки по сотрудникам |

Новое правило добавляется объектом в список `payrollRules.rules`: расчёт и описание хранятся рядом. Расчёт возвращает описания правил в `ruleDescriptions`, их показывает окно «Правила» страницы «Зарплата». Название версии правил (`payrollRules.title`) сохраняется в закрытии периода и показывает, по каким правилам посчитан закрытый период.

## Клиент платформы

В `src/web/application` находятся точка входа клиента, провайдеры и оболочка приложения. Остальные каталоги содержат её части.

| Где искать | За что отвечает |
|---|---|
| `sdk/` | Публичные компоненты, хуки и иконки для экранов |
| `forms/`, `lists/` | Стандартные формы записей и списки объектов |
| `widgets/`, `references/` | Поля ввода, отображение значений, выбор связанных записей |
| `tabs/`, `window/` | Вкладки открытых страниц и область окна |
| `authentication/`, `data-provider/` | Клиентская сессия и обмен данными с сервером |
| `keyboard/`, `common/` | Фокус, горячие клавиши, общие клиентские средства |

Экран конфигурации использует платформу через [точку входа web SDK](https://github.com/EGSP/collection-zarplata/blob/main/src/web/sdk/index.ts), остальные модули клиента внутренние. Граница импортов и состав SDK описаны в [«Web SDK»](web-sdk.md).

В `src/common/formulas.ts` находится общий язык числовых формул: сервер и форма исполняют одно описание выражения. Правила вычисляемых полей описаны в [метаданных](metadata.md), расчёты магазина в [«Правилах учёта»](accounting-rules.md).
