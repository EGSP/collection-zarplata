# Структура проекта

Этот справочник помогает разработчику найти место для изменения и раздел с подробным описанием. Код платформы находится в `src/server` и `src/web`, прикладная конфигурация магазина в `src/configuration`. Общий для сервера и клиента код вынесен в `src/common`.

## Основные каталоги

```text
src/
  server/             сервер платформы
  web/                клиент платформы и web SDK
  configuration/      объекты, правила и экраны магазина
  common/             код, общий для сервера и клиента
docs/                 архитектура и сайт документации
scripts/              генерация, проверки и сборка приложения
tools/                самостоятельные инструменты
repos/                исходники внешних библиотек для изучения
```

## Конфигурация магазина

В `src/configuration` находятся прикладные объекты, действия, политики и компоненты интерфейса. Платформа предоставляет механизмы их описания и исполнения; конфигурация задаёт поведение магазина. Бизнес-правила собраны отдельно в [«Правилах учёта»](accounting-rules.md).

| Где искать | Содержимое | Подробное описание |
|---|---|---|
| `catalogs/`, `documents/`, `registers/`, `information-registers/` | Объекты в файлах `*.catalog.ts`, `*.document.ts`, `*.register.ts` и `*.information-register.ts` | [Метаданные](metadata.md) |
| `policies/` | Прикладные политики записи | [Политики записи](write-policies.md) |
| `payroll.ts`, `payroll-rules.ts`, `payroll-context.ts` | Расчёт зарплаты, правила начисления и данные периода для них; устройство описано [ниже](#устройство-расчёта-зарплаты) | [Расчёт зарплаты](accounting-rules.md#расчёт-зарплаты) |
| `period-summary.ts` | Отчёт «Сводка за период»: читает документы периода и возвращает продажи, взносы, отвесы и должников; его вызывает действие закрытия периода | [Сводка за период](accounting-rules.md#сводка-за-период) |
| `roles.ts` | Роли конфигурации | [Права](authorization.md) |
| `pages/` | Объявления `*.page.ts` и компоненты `*.page-component.tsx` собственных страниц | [Страницы конфигурации](metadata.md#страницы-конфигурации) |
| `form-elements/` | Объявления `*.form-element.ts` и компоненты `*.form-element-component.tsx` блоков стандартной формы | [Элементы формы](metadata.md#элементы-формы) |
| `shell.ts` | Подсистемы и группы навигации, включённые в них объекты и страницы | [Пользовательский интерфейс](interface.md) |
| `shell-groups.tsx`, `shell-components/` | Состав групп оболочки и их прикладные компоненты | [Пользовательский интерфейс](interface.md) |

Серверную навигацию объявляет [shell.ts](https://github.com/EGSP/collection-zarplata/blob/main/src/configuration/shell.ts); размещение клиентских компонентов в группах объявляет [shell-groups.tsx](https://github.com/EGSP/collection-zarplata/blob/main/src/configuration/shell-groups.tsx).

### Генерируемые реестры

Четыре файла в корне `src/configuration` формирует [генератор метаданных](https://github.com/EGSP/collection-zarplata/blob/main/scripts/metadata-generate.ts). Они исключены из git и обновляются генератором, а не вручную.

| Файл | Назначение |
|---|---|
| `configuration.generated.ts` | Серверный реестр объектов, объявлений страниц и элементов формы, объект прав `Rights` |
| `objects.generated.ts` | Ссылки `Objects` на объекты для клиентских компонентов; импорты объектов используются только как типы |
| `pages.generated.ts` | Клиентский реестр объявлений и компонентов страниц |
| `form-elements.generated.ts` | Клиентский реестр объявлений и компонентов элементов формы |

Правила обнаружения файлов и проверки объявлений описаны в [метаданных](metadata.md), порядок генерации при разработке и сборке в [«Сборке и запуске»](build-and-launch.md).


### Устройство расчёта зарплаты

Расчёт разделён на данные, правила и исполнение, чтобы новое правило начисления не меняло остальные:

| Файл | Роль |
|---|---|
| `payroll-context.ts` | Типы данных периода, сервис Effect `PayrollContext` и общие функции: `allocate` делит сумму между долями методом наибольших остатков, `percentOf` считает процент с округлением половины вверх |
| `payroll-rules.ts` | Каждое правило — объект `PayrollRuleDefinition` с `name`, `title`, `description` и `calculate`: эффект над `PayrollContext` читает данные периода и возвращает строки начисления с текстом правила. Описания строятся из тех же констант, что и расчёт, например из границы ступени. Ступень ставки вынесена в чистую функцию `goodsRate` |
| `payroll.ts` | Читает из базы документы периода, кладёт их в контекст и выполняет правила `payrollRules.rules` через `Effect.forEach`, затем складывает строки по сотрудникам |

Новое правило добавляется объектом в список правил `payroll-rules.ts`: расчёт и описание хранятся рядом. Описания правил расчёт возвращает в `ruleDescriptions`, их показывает окно «Правила» страницы «Зарплата». Название версии правил сохраняется в закрытии периода и показывает, по каким правилам посчитан закрытый период.

## Клиент платформы

В `src/web/application` находятся точка входа клиента, подключение провайдеров и оболочка приложения. Остальные каталоги содержат её части:

| Где искать | За что отвечает |
|---|---|
| `sdk/` | Публичные компоненты, хуки и иконки для экранов |
| `forms/`, `lists/` | Стандартные формы записей и списки объектов |
| `widgets/`, `references/` | Поля ввода, отображение значений и выбор связанных записей |
| `tabs/`, `window/` | Вкладки открытых страниц и область окна |
| `authentication/`, `data-provider/` | Клиентская сессия и обмен данными с сервером |
| `keyboard/`, `common/` | Фокус, горячие клавиши и общие клиентские средства |

Экран конфигурации использует платформу через [точку входа web SDK](https://github.com/EGSP/collection-zarplata/blob/main/src/web/sdk/index.ts). Остальные модули клиента являются внутренними. Граница импортов и состав SDK описаны в разделе [«Web SDK»](web-sdk.md).

В `src/common/formulas.ts` находится общий язык числовых формул и его исполнение: сервер и форма используют одно описание выражения. Правила вычисляемых полей описаны в [метаданных](metadata.md), конкретные расчёты магазина в [«Правилах учёта»](accounting-rules.md).
