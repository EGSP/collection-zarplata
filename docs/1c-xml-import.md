# Импорт из универсальной XML-выгрузки 1С

Стандартное действие `import` доступно справочникам и требует права записи. Тело `payload` содержит `externalSystem` и непустой список `items` (до 500 элементов). Каждый элемент содержит `sourceObject`, `externalIdentifier` и `fields`; ответ возвращает `externalIdentifier`, `guid` и `status` (`created` или `updated`) в исходном порядке.

В конфигурации регистр сведений `externalLinks` хранит уникальную тройку «внешняя система, вид объекта источника, внешний идентификатор» и ресурс «ссылка на запись». Импорт читает связь, записывает справочник и новую связь через вложенные действия диспетчера. Все действия используют одну транзакцию, права пользователя, политики записи и журнал. При повторной загрузке переданные пользовательские поля заменяются, пропущенные необязательные очищаются. Ошибка элемента отменяет всю порцию. Если связь ведёт в другой справочник, импорт останавливается. Несколько внешних адресов одной записи можно создать обычным действием записи регистра сведений.

Конфигурация может ограничить строковое поле вызовом `.choices(['Мужской', 'Женский'])`. Список копируется и становится неизменяемым; сборка метаданных отклоняет пустой список, пустые строки и повторы. Сервер проверяет принадлежность значения списку при записи и отборе, форма показывает выпадающий список с возможностью очистки необязательного поля. Тип хранения остаётся строковым. ФИО справочника `physicalPersons` хранится в стандартном `name`, подпись формы заменена на «ФИО». Справочник `nomenclature` собственных полей не имеет: название позиции хранится в стандартном `name`.

Инструмент импорта написан на Go и находится в `tools/1c-xml-import`, описание запуска и формата сопоставления в его README.md. Он использует стандартную библиотеку Go и собирается без cgo в исполняемый файл, не зависящий от системных библиотек. Сборка основного приложения Go не требует. Локальный инструмент передаёт PIN через скрытый ввод или переменную окружения, использует cookie и обновляет доступ при ответе 401. Для удалённого сервера требуется HTTPS. Файл читается потоком, в памяти находятся один выбранный объект XML и текущая порция. Ранее подтверждённые порции сохраняются при ошибке; повторный запуск безопасно обновляет их.

Полные ссылки хранятся в колонках TEXT как JSON в устойчивом порядке `kind`, `name`, `guid`; API возвращает объект, а не JSON-строку. Это правило действует также для табличных частей, измерений, ресурсов и условий отбора. Регистр внешних связей содержит ресурс `record` такого типа. Миграция `20261007_external_record_reference` переносит прежние `targetObject` и `recordGuid` в этот ресурс до удаления колонок, сохраняя внешние ключи. Пробный справочник содержит полную ссылку в реквизите и табличной части для проверки общего механизма.
