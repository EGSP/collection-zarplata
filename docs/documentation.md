# Документация

Архитектура описывается файлами Markdown в каталоге `docs`, а запущенное приложение показывает их сайтом по адресу `/docs/`. Тем же способом позже подключаются инструкции для пользователя.

## Файлы и оглавление

- Каждый раздел архитектуры — отдельный файл `docs/<имя>.md` с именем латиницей в kebab-case. Заголовок первого уровня называет раздел, заголовки второго уровня — его подразделы.
- Корневой ARCHITECTURE.md служит оглавлением: одна строка со ссылкой на каждый файл. Меню сайта строится из этого оглавления при сборке, а подразделы в нём берутся из заголовков файлов. Поэтому новый раздел добавляется файлом и строкой оглавления, без правки настроек сайта.
- Ссылка на другой раздел пишется относительным путём к файлу и якорем заголовка: `[«Web SDK»](interface.md#web-sdk)`. Такая ссылка работает и на сайте, и на GitHub.
- Якорь заголовка строится по правилу GitHub: строчные буквы, знаки препинания удалены, пробелы заменены дефисами. Собственное правило VitePress заменяет «й» на «и», и ссылка на подраздел работала бы только в одном из двух мест. Поэтому в настройке сайта оно заменено.
- В `docs` не кладутся секреты и данные магазина: сайт отдаётся без входа в приложение.

## Сборка сайта

- Сайт собирает VitePress: Vite уже используется для клиента, и в сборке не появляется второй сборщик. Настройка лежит в `docs/.vitepress/config.ts`, оформление сайта стандартное и под интерфейс приложения не подгоняется.
- `npm run build` собирает сайт в `dist/docs` вместе с сервером и клиентом. Сайт собирается заранее, а не отрисовывается клиентом из Markdown: навигация и поиск по тексту готовы без разработки экрана. Поиск работает в браузере по индексу, который входит в сборку.
- `npm run docs:dev` запускает сайт на порту 5174 с обновлением страницы при правке файлов. Команда нужна, пока документация пишется; серверу приложения она не требуется.
- Сборка останавливается, если ссылка ведёт на несуществующий файл документации.

## Раздача по адресу /docs

- Сайт отдаёт сервер приложения: из каталога `dist/docs` при запуске из исходников и из ресурсов исполняемого файла (раздел [«Поставка»](delivery.md)).
- Адреса внутри `/docs` обрабатывает отдельный маршрут. Клиент приложения отвечает своей страницей на любой неизвестный адрес, чтобы работали адреса вкладок; маршрут `/docs/*` точнее, поэтому неизвестный адрес документации показывает страницу «не найдено» самого сайта с кодом 404, а не клиент.
- Сайт доступен без входа. Cookie доступа действует только на `/api` (раздел [«Вход в приложение»](authentication.md)), и проверить её на `/docs` сервер не может.
- В режиме разработки Vite проксирует `/docs` на сервер так же, как `/api`. Сайт для этого собирается один раз при запуске `npm run dev`; чтобы увидеть правки, пересоберите его командой `npm run build:docs` или пользуйтесь `npm run docs:dev`.
- В левой панели приложения над кнопкой «Выйти» стоит кнопка «Документация». Она открывает `/docs/` в новой вкладке браузера и видна каждому вошедшему пользователю. Во вкладке приложения сайт не открывается: его меню и оформление повторяли бы каркас приложения.
