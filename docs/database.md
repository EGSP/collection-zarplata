# База данных

Используется **Turso** — SQLite-совместимая встраиваемая база, переписанная на Rust. Проект находится в статусе бета: часть возможностей SQLite ещё не реализована.

## Драйвер

Пакет `@tursodatabase/database` (версия 0.8 на сентябрь 2026). Основные вызовы:
- `connect(path)` открывает файл БД и создаёт его, если файла нет;
- `db.prepare(sql)` асинхронно готовит запрос; `run`, `get`, `all`, `iterate` выполняют его и возвращают промисы. Для разовых запросов есть `db.get(sql, ...parameters)`, `db.all(...)`, `db.run(...)`;
- `db.exec(sql)` выполняет SQL без результата, например DDL;
- `db.pragma(...)` выполняет PRAGMA.
- `db.transactionAsync(async (transaction) => { ... }).immediate()` удерживает соединение до подтверждения или отката и передаёт дескриптор для запросов внутри транзакции.

Драйвер использует нативные привязки для Node.js; есть и сборка на WebAssembly.

## Типизированные выборки объектов

Прикладной код вызывает `selectTyped` из `src/server/data/typed-select.ts`, передавая билдер объекта и настройки выборки. Имя таблицы определяется по виду и имени объекта. Имена колонок, отбора и сортировки проверяются по объявленным и стандартным полям; тип значения отбора связан с выбранным полем. Например:

```ts
const closing = yield* database.get(selectTyped(PeriodClosing, {
    columns: ['closedThrough'],
    where: [{ column: 'posted', operator: '=', value: true }],
    orderBy: [{ column: 'closedThrough', direction: 'DESC' }],
    limit: 1,
}));
```

Готовый запрос выполняют обычные `Database.get` и `Database.all`: тип строки выводится из выбранных колонок. Без `columns` возвращаются все поля таблицы объекта. Табличные части хранятся отдельно и в эту строку не входят. Регистратор не поддерживается в колонках, отборе и сортировке, поскольку занимает две колонки; без перечня колонок он тоже исключён из результата регистра.

Запрос сохраняет преобразование строки, которое методы чтения применяют внутри операции базы. Логические значения возвращаются как `boolean`, полные ссылки как объекты, деньги как целое число копеек. Те же преобразования используются при чтении обычных записей и табличных частей. Условия переводятся в хранимые значения до построения SQL, включая логические поля и полные ссылки. Ошибка преобразования возвращается как ошибка чтения базы. Конструктор SQL остаётся независимым от метаданных; обычные запросы продолжают возвращать хранимые строки.

## Работа с базой в приложении

- **Одно соединение на процесс.** Turso не поддерживает доступ к одному файлу из нескольких процессов, а нам это и не требуется: приложение работает одним процессом.
- **Соединение открывает провайдер-фабрика Nest.** Фабрика по настройкам запуска открывает файл базы, создав его каталог при необходимости, или пустую базу в памяти (`connect(':memory:')`). `DatabaseService` получает уже открытое соединение и закрывает его при остановке приложения; остальные сервисы работают с базой через него и о режиме не знают. Сам провайдер соединения из модуля базы не экспортируется.
- **Сервис `Database` на Effect** оборачивает драйвер: вызовы драйвера превращаются в `Effect`, ошибки — в `DatabaseError` (`Data.TaggedError`).
- **Транзакцией владеет драйвер.** Действие открывает `transactionAsync(...).immediate` и передаёт его дескриптор в окружение Effect. Все чтения и записи действия, включая вложенные вызовы, идут через этот дескриптор. Драйвер подтверждает транзакцию после успешного завершения действия и откатывает при ошибке или прерывании. Прерывание ждёт завершения отката, прежде чем соединение снова считается свободным.
- **Порядок запросов задаёт нативная блокировка соединения.** Драйвер удерживает её на всё время транзакции. Другая транзакция, отдельная запись или чтение вне неё ждёт завершения текущей транзакции и не видит промежуточные изменения. Запросы внутри транзакции выполняются на её дескрипторе. Отдельный семафор Effect для этого порядка не нужен.
- **Таблицы создаются как `STRICT`.** В таком режиме база проверяет типы колонок при записи, а не принимает любые значения, как обычная SQLite-таблица.
- **Конкурентная запись (MVCC, `BEGIN CONCURRENT`) не включается.** Она в статусе бета, а при двух пользователях очереди транзакций достаточно.

## Ограничения Turso, которые учитываем

- нет таблиц `WITHOUT ROWID`;
- нет `VACUUM`;
- только кодировка UTF-8;
- в JavaScript-драйвере нет `backup()`, поэтому резервная копия делается копированием файла.

## Структура БД

Для изменения стандартных полей во всех объектах миграция может предоставить `prepare(previous, desired)`. Чистая функция получает сохранённый и желаемый снимки структуры и возвращает план `changes` и `statements`, который заменяет одноимённые свойства миграции. Это позволяет обработать справочники конкретной базы, не перечисляя имена объектов вручную. План строится до транзакции, проверяется на покрытие разрушающих изменений и исполняется вместе с записью нового снимка. Повторно применённая миграция не выполняется.

- `SchemaService` после инициализации соединения и метаданных строит желаемую структуру и завершает синхронизацию до начала приёма запросов. `catalog_<имя>`, `document_<имя>` и `register_<имя>` содержат поля объектов; `<таблица объекта>_<имя части>` содержит строки табличной части с ключом `(ownerGuid, lineNumber)`. У справочников и документов первичный ключ — `guid`; у регистра — `(recorderDocument, recorderGuid, lineNumber)`. Значение `recorder` разложено на две колонки. Ссылки и даты хранятся как `TEXT`, деньги, целые числа и логические значения — как `INTEGER`, дробные числа — как `REAL`.
- Тем же описанием создаются служебные таблицы `platform_schema` (снимок), `platform_migrations` (применённые миграции), `platform_journal`, `platform_users`, `platform_user_roles` (связь пользователя с именами ролей) и `platform_tokens`. Все таблицы создаются в режиме `STRICT`. Индексы создаются для номера документа, пометки удаления, измерений и ссылок, периода регистра, а также для поиска по журналу и токенам.
- Применённая структура хранится JSON-снимком в `platform_schema`. При запуске платформа сравнивает с ним текущие метаданные. Новые таблицы, колонки и индексы добавляются автоматически. Новая колонка в существующей таблице допускает `NULL`, чтобы сохранить старые строки; обязательность нового реквизита проверяется при записи. Если нужна физическая обязательность с заполнением старых строк, используйте миграцию.
- Удаление таблицы или колонки, изменение типа, первичного ключа либо существующего индекса требует миграции. Переименование определяется как удаление старой и добавление новой колонки. Без подходящей миграции запуск останавливается с перечнем изменений. После выполнения SQL платформа проверяет фактические таблицы, типы колонок и индексы; ошибка откатывает транзакцию вместе с записью снимка и отметками миграций.

### Файлы миграций

Файл в `src/server/schema/migrations` экспортирует значение типа `SchemaMigration` с `id` вида `YYYYMMDD_имя`, массивом `changes` и массивом SQL-команд `statements`. Например, для переноса значения в колонку с новым именем миграция сначала добавляет колонку, переносит данные запросом `UPDATE`, затем удаляет старую колонку. Ключи `changes` следует брать из сообщения об остановке запуска. Файл импортируется в `migrations/index.ts`, где миграции перечислены в возрастающем порядке `id`: статический реестр попадает и в исполняемый файл.

```ts
import type { SchemaMigration } from './index.js';

export const renameComment: SchemaMigration = {
    id: '20260929_rename_comment',
    changes: ['catalog_sample.comment: удалить колонку'],
    statements: [
        'ALTER TABLE catalog_sample ADD COLUMN note TEXT',
        'UPDATE catalog_sample SET note = comment',
        'ALTER TABLE catalog_sample DROP COLUMN comment',
    ],
};
```

Платформа выполняет неприменённые миграции по порядку, затем добавляет недостающие безопасные элементы и записывает снимок в той же транзакции. `platform_migrations` фиксирует `id` только после успешного выполнения. При следующем запуске тот же файл повторно не выполняется. SQL миграции относится к конкретной установленной структуре; перед изменением рабочей базы сделайте резервную копию её файла.

## Хранение значений

- Деньги — целые числа в копейках.
- Дата и время — строки ISO 8601 с явным учётом часового пояса.
- `guid` — строка UUIDv7.
