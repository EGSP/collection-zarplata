# Интерфейс (SDUI)

Страница предназначена разработчикам конфигурации и платформы. Она объясняет, как серверные описания превращаются в формы, списки и оболочку приложения, и описывает контракт web SDK для собственных экранов.

Для настройки конфигурации используйте [«Переопределение формы»](#переопределение-формы), [«Выбор формы и место показа»](#выбор-формы-и-место-показа) и [«Схема оболочки»](#схема-оболочки). Для создания экрана начните с раздела [«Web SDK»](web-sdk.md). Формат ответа сервера приведён в [«Формат описаний»](#формат-описаний); поведение готовых экранов описано в [«Списки»](#списки), [«Формы»](#формы) и [«Работа с клавиатуры»](#работа-с-клавиатуры).

## Как сервер и клиент разделяют ответственность

Сервер отдаёт JSON-описания форм и списков: поля, виды значений, ссылки, табличные части, группы, порядок обхода и действия с учётом прав пользователя. Из тех же метаданных строятся таблицы базы и схемы проверки данных. Поэтому форма предлагает те же поля и ограничения, которые проверяет сервер. Клиент проверяет ввод до отправки; окончательное решение принимает сервер.

Конфигурация задаёт раскладку формы и состав меню. Клиент выбирает поле ввода и отображение значения через реестр виджетов Ant Design. Экран, который не сводится к стандартному списку или форме, объявляется [страницей конфигурации](metadata.md#страницы-конфигурации): её компонент входит в сборку клиента, а сервер отдаёт имя и заголовок. Сам список или форму записи можно заменить [формой объекта](metadata.md#формы-объекта).

Стандартные и собственные экраны используют web SDK. Ядро Refine отвечает за ресурсы, маршрутизацию и хуки данных; собственный data provider переводит операции в `/api/perform`. Лёгкие вычисления клиент выполняет сам, сложные оформляются собственным действием на сервере.

## Формат описаний

`GET /api/metadata` требует входа и возвращает `{ "objects": [...], "pages": [...], "shell": {...} }`. В ответе остаются объекты, которые пользователь вправе читать, и страницы, которые он вправе открывать, в порядке файлов реестра. Страница содержит `{ "name", "title" }`; формат `shell` описан в [«Схема оболочки»](#схема-оболочки).

Полные описания строятся при первом запросе и переиспользуются, а отбор по правам выполняется при каждом запросе. Типы опубликованы в `src/server/ui/descriptions.ts`: файл не зависит от Nest и Effect и доступен клиентской сборке. Построение описаний выполняет `src/server/ui/views.ts`.

### Объект и форма

Описание объекта (`ObjectView`): `kind`, `name`, `title`, `presentation`, `form`, `list` и `tableParts`. Последнее содержит описания всех частей для просмотра, независимо от раскладки формы. `presentation` описывает представление по ссылке, `null` означает собственное представление. У регистров `form` равен `null`: их строки записывают только документы.

Описание формы (`FormView`):

| Свойство | Содержимое |
|---|---|
| `fields` | Поля на форме в порядке объявления: `name`, `title`, `kind`, `target`, `readOnly`, `rules`, `inputElement`, а также `choices` (перечень значений строки), `initial` (начальное значение строки), `computed` (формула), `suggestions` (источник числовых подсказок), `expandedTablePart` (часть объекта ссылки для просмотра), `variants` (варианты составного поля, каждый в формате поля своего вида), `inputMode` ([способ ввода](metadata.md#способ-ввода) `fluent` или `solid`) |
| `tableParts` | Табличные части: `name`, `title`, `inputElement` (имя замены либо `null`), `columns` (поля строки в том же формате) |
| `groups` | Раскладка: `{ title, elements }`. Строка в `elements` обозначает поле или табличную часть, объект `{ element }` обозначает собственный элемент конфигурации. Каждое поле и каждая табличная часть входят ровно в одну группу |
| `traversal` | Порядок обхода с клавиатуры: имена редактируемых полей и табличных частей. Собственных элементов групп в нём нет |
| `actions` | Действия формы: `name`, `title`, `standard`, `input` и `tableParts` входных данных собственного действия |
| `calculations` | Полный набор полей и частей для расчётов, включая скрытые раскладкой формы |
| `creationMode` | Режим, в котором форма новой записи открывается по умолчанию: `tab` открывает вкладку, `dialog` открывает модальное окно |

- `rules` содержит правила проверки: `required`, `minimumLength`, `maximumLength`, `minimum`, `maximum`, `integer`. Обязательная строка не может быть пустой; длина считается в символах UTF-16, как `String.length`. Значение денег и их границы указаны в копейках.
- `readOnly` получают поля, которые заполняет платформа: `number` и `posted` документа, а также вычисляемые числовые поля. Они показываются на форме, но не входят в порядок обхода. `guid` и `deletedAt` на форму не выводятся.
- Стандартные действия справочника: `save`, `markDeleted`, `unmarkDeleted`; у документа к ним добавляются `post` и `unpost`. За ними идут собственные действия объекта. В описание попадают только действия, на которые у пользователя есть право; форму без `save` клиент показывает только для просмотра.

### Список

Описание списка (`ListView`):

| Свойство | Содержимое |
|---|---|
| `columns` | Поля записи, кроме стандартных `guid` и `deletedAt`; `role` различает измерения (`dimension`) и ресурсы (`resource`). У составного поля `variants` перечисляет варианты: `kind`, `target`, `choices`, `rules` |
| `filters` | Отборы: поле и допустимые способы сравнения `operators`; у составного поля те же `variants`, что у колонки, и `inputMode` поля |
| `sortable` | Поля, по которым можно сортировать; регистратор не сортируется |
| `defaultSort` | Сортировка при открытии: справочник по наименованию, документ по дате и номеру от новых к старым, движения по периоду от новых к старым, сведения по измерениям в порядке объявления |
| `deletionMark` | У записей есть пометка удаления; клиент показывает её признаком строки, а не колонкой |
| `tableParts` | Имена частей для раскрытия строки списка только для чтения |

Для строк доступны `contains`, `equals` и `notEquals`. Числа, деньги, даты и даты со временем поддерживают `equals`, `notEquals`, `greater`, `greaterOrEqual`, `less`, `lessOrEqual` и `contains`. Логические значения, ссылки и регистратор поддерживают `equals` и `notEquals`. Составное поле поддерживает все способы: значение отбора содержит тип варианта, а упорядоченные сравнения действуют внутри простого типа ([«Отбор по полю»](single-endpoint.md#отбор-по-полю)). `contains` ищет подстроку без учёта регистра, а `%` и `_` считает обычными символами. Общий модуль формата значений рядом с форматом описаний используется клиентом для отображения и сервером для поиска: правило перевода копеек в рубли, десятичная запятая и вид даты задаются один раз. Для `contains` интерфейс предлагает свободный текстовый ввод, в том числе части даты или суммы; при переходе к точному сравнению или обратно прежнее значение очищается. Соответствие видов полей и способов сравнения задано в формате описаний (`filterOperators`), и действие `list` принимает те же способы, поэтому отбор из описания всегда можно передать в `list` без перевода.

## Переопределение формы

По умолчанию форма состоит из одной группы без заголовка: поля в порядке объявления, затем табличные части. `.form(...)` в описании объекта меняет раскладку:

```ts
.form((form) => form
    .group('Основное', ['item', 'date', 'number'])
    .group('Строки документа', ['lines'])
    .hide('posted')
    .title('comment', 'Примечание')
    .creation('dialog'))
```

- `group(title, elements)` выводит поля и табличные части группой с заголовком. Группы идут в порядке объявления, элементы внутри группы идут в указанном порядке. Элементы, не попавшие ни в одну группу, собираются после групп в группу без заголовка.
- `hide(name)` убирает поле или табличную часть с формы и из порядка обхода.
- `title(name, title)` меняет подпись на форме; в списке остаётся подпись из описания поля.
- Порядок обхода следует за раскладкой групп, поэтому перестановка групп и элементов меняет и его.
- Собственные компоненты объявляют подключения через `defineFormComponent` рядом с реализацией (подраздел [«Элементы формы»](metadata.md#элементы-формы)). `insert` добавляет блок в группу, `override` заменяет ввод поля или табличной части. Схема объекта компоненты не импортирует и не назначает.
- Сервер применяет подключения до проверки формы: замена сохраняет имя, подпись, место в раскладке и обходе. Скрытое место, несуществующая группа и две замены одного места останавливают запуск с `MetadataError`. В списке и отборе представление остаётся стандартным.
- `creation(mode)` задаёт режим создания записи: `tab` открывает форму новой записи во вкладке, `dialog` открывает её в модальном окне поверх списка. Без вызова запись создаётся во вкладке. Это умолчание, а не запрет: место вызова может указать режим само (команда [`useOpenRecord`](web-sdk/hooks.md#область-окна-и-открытие-записи)), а адрес `/<вид>/<имя>/new` всегда открывает вкладку. На существующие записи режим не действует. Режим задаётся один раз. В окне создаются записи справочников «Номенклатура» и «Физические лица»: полей на их формах немного.

Переопределение действует только на форму. Ошибки переопределения обнаруживает `commit()` при запуске (раздел [«Проверки при сборке»](metadata.md#проверки-при-сборке)).

## Схема оболочки

Оболочка состоит из подсистем, подсистема из групп, группа из ссылок на объекты и страницы конфигурации. Схема описывается билдером в `src/configuration/shell.ts`:

```ts
import { shell } from '../server/ui/shell.js';
import { Employees } from './catalogs/employees.catalog.js';
import { Shift } from './documents/shift.document.js';
import { ShiftWorkplace } from './pages/shift-workplace.page.js';

export const applicationShell = shell()
    .subsystem('masterData', (subsystem) => subsystem
        .title('НСИ')
        .group('Справочники', [Employees])
        .group('Документы', [Shift])
        .group('Рабочие места', [ShiftWorkplace]));
```

- Подсистемы, группы и пункты группы показываются в порядке описания. Объекты и страницы стоят в группе в общем порядке. Имя подсистемы отличает её от остальных, пользователь видит заголовок.
- Объект и страница указываются импортированными билдерами, а не строками. Один объект или страницу можно указать в нескольких группах и подсистемах, поскольку содержимое подсистемы представляет собой список ссылок.
- Вся проверка выполняется типами при `npm run typecheck`: значение, которое не является билдером объекта или страницы, и повтор имени подсистемы не компилируются. Имена подсистем накапливаются в параметре типа билдера оболочки. При запуске сервера схема не проверяется.
- Объект, не указанный в схеме, в окнах подсистем не показывается, но его список открывается по адресу, а форма записи открывается по ссылке из другой записи. Страница, не указанная в схеме, открывается по адресу. Предупреждений об этом нет: объект или страница могли быть скрыты намеренно.
- Файл схемы один, путь к нему постоянный, поэтому генератор реестра его не ищет: сервер импортирует его напрямую, как файл ролей.

В ответе `GET /api/metadata` схема лежит в свойстве `shell`: `{ "subsystems": [{ "name", "title", "groups": [{ "title", "items": [{ "kind", "name" }] }] }] }`. У пункта-страницы `kind` равен `page`, у объекта это его вид. Сервер оставляет в схеме только объекты, которые пользователь вправе читать, и страницы, которые он вправе открывать. Группа без таких пунктов, в том числе пустая в конфигурации, и подсистема без групп в ответ не попадают. Заголовок объекта клиент берёт из его описания в `objects`, заголовок страницы берёт из `pages`.

## Каркас клиента

Клиент предоставляет именованные группы для компонентов конфигурации: `ShellGroups.home` на главном экране и `ShellGroups.list(Objects.<вид>.<имя>)` над поиском и отбором стандартного списка. Группы существуют только в клиенте и не входят в `GET /api/metadata`. У каждого списка своя группа, а пустая группа не занимает места. Главный экран показывает «Нет доступных объектов», только если нет ни подсистем, ни фактически выведенных компонентов, в том числе когда компоненты возвращают `null`.

Состав групп описывается в `src/configuration/shell-groups.tsx` вызовом `defineShellGroups`. Каждая запись массива добавляет `content` в `parent`: компонент с `component` и необязательным перечнем `requiredObjects` либо вложенную группу. `shellGroup(name, orientation)` объявляет собственную группу с уникальным именем и ориентацией `vertical` (по умолчанию), `horizontal` или `grid`. Группа `grid` раскладывает компоненты по сетке Ant Design (`Row` и `Col`): на телефоне ячейка занимает всю строку, на широком экране в строке четыре ячейки. Ячейку компонента, вернувшего `null`, сетка скрывает, чтобы в строке не было пропуска; вложенная группа в сетке занимает всю строку. Вложенная группа стоит наравне с компонентами; порядок массива задаёт порядок показа. Объявления известны до отрисовки всех вкладок, поэтому порядок монтирования на состав не влияет. Циклы вложенности, повторное назначение родителя и разные ориентации одного имени завершаются ошибкой при загрузке конфигурации.

Один компонент можно добавить в несколько групп. У компонента нет отдельного права: доступ определяется правами объектов. Если хотя бы одного объекта из `requiredObjects` нет среди доступных описаний, компонент не монтируется и не отправляет запросов. При самостоятельной проверке компонент сначала получает описание через `useObjectView` и только после этого монтирует часть, которая читает данные. Он импортирует из платформы только web SDK, а из серверных модулей только типы, как компонент страницы; границу всех файлов `.tsx` конфигурации проверяет `npm run typecheck`.

Все модальные окна сохраняют открытое состояние и введённые значения при нажатии на затемнённую область вокруг окна. Это правило задано один раз в общем провайдере Ant Design и действует также на новые окна. Окно закрывается крестиком, клавишей Esc или переходом из самого окна; кнопки «Отмена» и «Выполнить» сохраняют своё назначение. Пока собственное действие выполняется, окно его входных данных не закрывается: Esc отключён, крестик и «Отмена» недоступны. После отказа сервера окно остаётся открытым с ошибками полей и снова допускает закрытие.

Каркас объединяет сессию, data provider, ресурсы Refine, список подсистем и вкладки открытых окон. Формы и списки объектов работают поверх него и описаны в разделе [«Web SDK»](web-sdk.md) и подразделах [«Реестр виджетов»](#реестр-виджетов), [«Ссылки»](#ссылки), [«Списки»](#списки) и [«Формы»](#формы).

### Сессия и запросы к API

- Все запросы приложения идут через один экземпляр axios (`src/web/common/api.ts`). Ошибка запроса приводится к `ApiError`: статус HTTP, текст сервера, а для единого эндпоинта ещё пути полей с ошибками проверки (`fields`) и ключ недостающего права (`right`). Если ответ не получен, статус равен 0.
- Токены лежат в `HttpOnly`-cookie, поэтому клиент не видит ни их, ни срок их действия и судит о сессии по ответам сервера. Ответ 401 принимает перехватчик axios (`src/web/authentication/session.ts`): он обновляет токены запросом `POST /api/authentication/refresh` и повторяет исходный запрос. Вызывающий код получает ответ повтора, поэтому истёкший access-токен не виден ни TanStack Query, ни интерфейсу.
- Обновление токенов одно на всю страницу. Refresh-токен одноразовый: если бы каждый запрос, получивший 401, обновлял токены сам, сервер принял бы только первое обновление. Одновременные запросы ждут общего обновления. Запрос запоминает номер пары токенов, с которой отправлен; если к приходу ответа 401 пара уже заменена, запрос только повторяется.
- Сессия считается завершённой, когда 401 вернул и повтор запроса. Отказ в самом обновлении её ещё не завершает: токены могла заменить соседняя вкладка, у которой общие cookie.
- Состояние сессии хранится в TanStack Store: `unknown` означает, что приложение только открыто; `active` означает, что сервер принял запрос пользователя; `ended` означает отказ после обновления токенов или выход пользователя. По состоянию auth provider Refine отвечает на проверку входа. Отдельного запроса «кто я» у сервера нет, поэтому при открытии приложения состояние выясняет загрузка описаний объектов.
- При завершении сессии данные и описания объектов удаляются из кеша TanStack Query: следующий вошедший пользователь не увидит данных предыдущего.

### Data provider

Refine называет ресурс одной строкой, а сервер различает объекты по виду и имени. Имя ресурса состоит из вида и имени объекта через точку: `catalog.sample`. Методы data provider (`src/web/data-provider/data-provider.ts`) переводятся в действия единого эндпоинта:

| Метод Refine | Действие | Входные данные |
|---|---|---|
| `getList` | `list` | Отбор, сортировка и страница; условие отбора с текстом поиска передаётся параметром `search`, условие поиска по представлению записи параметром `presentation` |
| `getOne` | `get` | `id`: `guid` записи |
| `getMany` | пакет действий `get` | `ids`: перечень `guid`; одновременные вызовы уходят одним запросом |
| `create` | `save` без `guid` | `variables`: значения полей и табличные части, как в `payload.fields` |
| `update` | `save` с `guid` | `id` и `variables`; запись заменяется целиком |
| `deleteOne` | `markDeleted` | `id`: `guid` записи |
| `custom` | любое, в том числе собственное | `url`: ресурс и действие через косую черту: `document.sample/post`, `platform.journal/history`; `payload`: входные данные действия |

- Запись возвращается в том виде, в каком её отдал сервер. Её идентификатором служит `guid`; поля `id`, принятого в Refine, у записей нет.
- Операторы отбора Refine переводятся в способы сравнения сервера: `eq` становится `equals`, `ne` становится `notEquals`, `gt` становится `greater`, `gte` становится `greaterOrEqual`, `lt` становится `less`, `lte` становится `lessOrEqual`, `contains` становится `contains`. Операторы `null` и `nnull` становятся сравнением с `null`. Группа `and` раскрывается в общий список условий. Группа `or` и остальные операторы завершаются ошибкой: молча пропущенное условие показало бы лишние записи.
- В режиме страниц `server` запрашивается одна страница. В режимах `client` и `off` Refine ждёт все записи сразу, и data provider читает их страницами по 500 записей, пока не получит все.
- Метод HTTP в `custom` значения не имеет: единый эндпоинт принимает только `POST`.

### Ресурсы, подсистемы и адреса

- Ресурсы Refine строятся из ответа `GET /api/metadata`: один ресурс на объект конфигурации. Ресурсы плоские, без ресурсов-групп: один объект может стоять в нескольких группах схемы оболочки, поэтому меню строится из схемы, а не из ресурсов.
- Слева показан список подсистем из схемы оболочки. Нажатие на подсистему открывает модальное окно с её группами. Пункт группы содержит ссылку на список объекта или на страницу конфигурации; переход по ней закрывает окно. Слева от названия пункта стоит иконка: у объекта по его виду (справочник, документ, регистр оборотов, регистр сведений), у страницы собственная. Иконку выбирает клиент по виду пункта.
- Под списком подсистем стоят кнопки «Документация», «Граф модулей» и «Выйти». Первые две открывают в новой вкладке браузера сайт документации (раздел [«Документация»](documentation.md)) и [граф модулей сервера](development-tools.md#граф-модулей-сервера).
- Подсистема не подсвечивается по открытой странице: страница объекта не принадлежит одной подсистеме.
- Адреса: `/<вид>/<имя>` открывает список объекта, например `/catalog/sample`; `/<вид>/<имя>/new` и `/<вид>/<имя>/<guid>` открывают форму записи; `/page/<имя>` открывает страницу конфигурации; `/` открывает главный экран. Главный экран выводит настроенные клиентские группы; объекты пользователь открывает из окон подсистем. Список, форма и страница конфигурации открываются во вкладках, см. «Вкладки открытых окон».
- Страница конфигурации открывается, если её имя есть и в ответе сервера, и в реестре страниц клиента (`pages.generated.ts`). Неизвестное имя и страница без права показывают «не найдено»: для клиента они неразличимы. Пока страница не задала заголовок сама, вкладка показывает заголовок из объявления.
- Всё приложение закрыто проверкой входа. Без сессии на его месте показывается экран входа, а адрес не меняется: отдельного адреса у экрана входа нет. Поэтому после входа открывается та же страница, в том числе когда сессия истекла посреди работы. После явного выхода открывается главный экран: следующим может войти другой пользователь.
- Раскладка показывает страницы вкладок только после загрузки описаний объектов. Пока они загружаются, виден признак ожидания; при ошибке показано сообщение с кнопкой повтора.
- Refine получает общий с приложением клиент TanStack Query. Запросы не повторяются сами ни при возврате в окно или восстановлении сети, ни после отказа сервера. Проверка входа Refine на время своего запроса убирает приложение с экрана, и её повтор закрыл бы все вкладки. Отказ в праве или в проверке данных от повтора не изменится.
- Уведомления Refine выводятся компонентом уведомлений Ant Design, их встроенные заголовки переведены на русский язык. Описанием ошибки служит текст сервера. Отправка сведений об использовании на сервер Refine отключена.

### Вкладки открытых окон

Открытые списки, формы и страницы конфигурации остаются вкладками, как окна в 1С (`src/web/tabs/`). Над страницей стоит полоса вкладок. Первая вкладка показывает главный экран. На ней иконка без заголовка, закрыть её нельзя.

- Вкладку определяет путь адреса. Поэтому отдельной команды «открыть вкладку» нет: ссылка из окна подсистемы, из списка или из другой записи, прямой адрес и кнопки браузера «Назад» и «Вперёд» меняют адрес, а набор вкладок выводится из него. Адрес с новым путём открывает вкладку, адрес с путём открытой вкладки делает её активной. Новая вкладка встаёт сразу за активной.
- Строка запроса принадлежит вкладке: в ней список хранит сортировку, отбор и страницу. Скрытая вкладка помнит свою строку запроса. При возврате на вкладку, в том числе по ссылке без строки запроса, адрес браузера приводится к запомненному.
- Страницы всех вкладок и главный экран остаются смонтированными, неактивные скрыты. Так вкладка сохраняет несохранённые значения формы, отбор, текст поиска и страницу списка. Если бы страница пересоздавалась при переключении, ввод терялся бы.
- Общих маршрутов у приложения нет: каждая вкладка раскладывает страницы по своему адресу, а не по адресу браузера. Поэтому скрытый список не реагирует на адрес активной вкладки и не меняет его.
- Всё, что действует на приложение в целом, страница включает только на активной вкладке. Так устроены сочетания клавиш формы: иначе Esc закрыл бы все открытые формы сразу.
- Страница обращается не к вкладке, а к ближайшей области окна (`src/web/window/`): области она сообщает заголовок, несохранённые изменения, изменённую и созданную запись (форма записи делает это через [контракт](#выбор-формы-и-место-показа)), у неё узнаёт, видна ли пользователю, и её просит закрыться. Реализаций области три: вкладка, главный экран и модальное окно с формой записи. Каждая сама решает, что значит обращение. Область главного экрана нужна компонентам конфигурации на нём, чтобы открыть форму записи в окне; закрыть её нельзя, а заголовок и сообщение о созданной записи она не использует. Поэтому страница, в том числе форма записи, не зависит от того, в чём показана.
- У области может быть рамка: собственные места для заголовка и кнопок действий. У вкладки рамки нет, и каркас страницы выводит заголовок и кнопки над содержимым. У модального окна рамка есть: заголовок с отметками состояния стоит в шапке окна, кнопки в его нижней части.
- Модальное окно с формой записи (`src/web/forms/record-dialog.tsx`) открывает команда открытия записи SDK в режиме окна; форма в нём получает `presentation: 'dialog'`. Адреса у окна нет: вкладки выводятся из адреса, и адрес окна открыл бы вкладку. Поэтому окно после перезагрузки страницы не восстанавливается. После создания записи окно закрывается и отдаёт её `guid` коду, который его открыл.
- Окно принадлежит области, со страницы которой открыто, и регистрируется в ней вложенной областью: закрытие вкладки, выход и закрытие страницы браузера учитывают несохранённые изменения в окне. Окно выводится в слой страницы вкладки: затемнение закрывает только страницу, а полоса вкладок и список подсистем остаются доступны. Окно видно, только пока активна его вкладка; при возврате на вкладку оно показано снова с введёнными значениями. Форма в окне может открыть следующее окно, оно вкладывается в первое.
- Крестик окна, Esc и кнопка «Закрыть» спрашивают то же подтверждение, что и вкладка. Esc обрабатывает форма, а не окно Ant Design: она отличает закрытие списка выбора от закрытия окна.
- Несохранённые изменения область узнаёт через проверки: функции, которые читают признак в момент вызова. Форма сбрасывает признак сразу после записи и тут же закрывает область, а признак в состоянии React к этому моменту ещё не обновился бы. Проверок в области может быть несколько; область изменена, если изменён хотя бы один участник. Вложенная область регистрируется в родительской одной проверкой. Так же области вкладок регистрируются в общем наборе приложения, по которому спрашивается подтверждение перед выходом и перед закрытием вкладки браузера.
- Подтверждение перед закрытием спрашивает область. Крестик в полосе вкладок стоит вне области, поэтому вызывает команду закрытия, которую область вкладки передала набору вкладок.
- Страница сообщает области заголовок, и он становится заголовком вкладки. У списка это заголовок объекта. У формы это представление записи, у новой записи заголовок объекта с пометкой «(новый)»; после записи заголовок меняется на представление. Представление по ссылке форма читает по записанному состоянию: несохранённый выбор ссылки запись ещё не называет. У страницы конфигурации это заголовок из объявления, пока она не задала свой.
- Вкладка закрывается крестиком, форма также кнопкой «Закрыть» и клавишей Esc. Активной становится соседняя слева вкладка, а если её нет, главный экран. В истории браузера адрес закрытой вкладки заменяется адресом новой активной.
- Набор вкладок хранится в памяти страницы. После перезагрузки открыты главный экран и вкладка текущего адреса. Вкладки стоят под проверкой входа и при завершении сессии закрываются: следующий вошедший пользователь не увидит вкладок и данных предыдущего.

## Реестр виджетов

Формы и списки о видах полей сами ничего не знают: компонент для поля они берут из реестра виджетов (`src/web/widgets/registry.tsx`). Реестр сопоставляет каждому виду поля (`FieldKind`) два компонента. Поле ввода служит для ввода или выбора значения. Компонент отображения выводит значение текстом там, где его нельзя изменить: в ячейке списка и на форме у полей только для чтения.

| Вид поля | Поле ввода | Отображение |
|---|---|---|
| `string` | Текстовое поле; пустое поле отдаёт `null`, а не пустую строку | Текст |
| `number` | Поле для числа; при правиле `integer` дробную часть ввести нельзя | Число с разделителями разрядов |
| `money` | Поле для суммы в рублях с двумя знаками после запятой | Рубли с двумя знаками после запятой |
| `date` | Выбор даты в календаре | `ДД.ММ.ГГГГ` |
| `dateTime` | Выбор даты и времени | `ДД.ММ.ГГГГ ЧЧ:ММ` по часовому поясу браузера |
| `boolean` | Флажок | «Да» или «Нет» |
| `reference` | Выбор записи другого объекта с поиском и кнопка перехода к выбранной записи | Представление записи со ссылкой на её форму |
| `composite` | По способу ввода поля: одно текстовое поле с подсказками (`fluent`) либо выбор типа и поле ввода выбранного варианта (`solid`) | Отображение варианта и подпись типа значения |
| `guid` | Нет: значение заполняет платформа | Текст |
| `recorder` | Нет: значение заполняет платформа | Представление документа со ссылкой на его форму |

- Реестр обязан перечислить все виды полей, и это проверяется типами. Если на сервере появится новый вид поля, клиент не соберётся, пока для него не добавлена пара компонентов.
- Значение остаётся в формате сервера на всём пути: деньги в копейках, даты строками ISO, ссылка в виде `guid`, отсутствие значения в виде `null`. В привычный человеку вид значение переводит само поле ввода, и оно же переводит введённое обратно. Поэтому значения формы уходят в `save`, а значение отбора в `list` без преобразования, и общего слоя преобразования нет.
- Все поля ввода принимают один набор свойств, принятый для элементов формы Ant Design: значение, обработчик изменения, признак недоступности, а также описание поля. Поэтому одно и то же поле ввода стоит в шапке формы, в ячейке табличной части, в условии отбора списка и в окне входных данных собственного действия.
- Каждое поле ввода умеет принять фокус по команде извне. Этим пользуется форма, когда ставит фокус в первое поле новой записи; этим же контрактом пользуется обход с клавиатуры.
- Правила проверки Ant Design строятся из `rules` описания поля в одном месте (`src/web/widgets/validation.ts`): обязательность, длина строки, границы числа, целочисленность. Значение проверяется в формате сервера, поэтому граница суммы сравнивается в копейках, а в сообщении называется в рублях.

### Составное поле

Виджет [составного поля](metadata.md#составное-поле) вводит значение одним из двух способов. Способ определяет платформа и передаёт в описании поля свойством `inputMode`: `fluent`, если каждый вариант можно написать текстом, иначе `solid` ([правила](metadata.md#способ-ввода)). Значение в форме и в отборе остаётся в формате сервера: `{ type, value }` либо `{ type: 'reference', kind, name, guid }`.

Оба способа решают одну задачу: дать пользователю работать с данными одного смысла, которые физически имеют разный тип. Поэтому тип значения всегда показан явно. При способе `fluent` он подписан под полем, при способе `solid` виден в выборе типа, а в списке и в поле только для чтения стоит рядом со значением: «100 · Число». Без подписи строка «100» и число 100 неразличимы, хотя сравниваются и суммируются по-разному.

#### Текстовый ввод (`fluent`)

Пользователь печатает в одном поле, а поле предлагает, чем введённое может быть:

| Источник подсказок | Что предлагается |
|---|---|
| Ссылочные варианты | Записи каждого целевого объекта, найденные по представлению; читаются общим хуком подсказок |
| Строка с перечнем значений | Значения перечня, содержащие введённый текст |
| Простые варианты | Толкования текста, когда их несколько: «Строка: 100», «Число: 100», «Сумма: 100,00» |

Выбор подсказки задаёт значение явно. Без выбора действуют правила:

- Текст становится значением простого варианта: строкой, а если строкового варианта нет, числом или суммой. Строка всегда приоритетнее числа. Имя человека, которого нет в справочнике, сохраняется строкой и проверяется правилами строки.
- Число и сумма принимают только текст, который читается как число: десятичная запятая или точка, пробелы между разрядами допустимы, у целого числа нет дробной части, у суммы не больше двух знаков копеек.
- Пока текст подходит типу текущего значения, тип сохраняется: правка числа 100 в 1005 оставляет его числом.
- Текст, который не подходит ни одному простому варианту, служит только запросом подсказок и прежнее значение не меняет. Так ведёт себя поле из одних ссылок. При потере фокуса поле снова показывает значение.
- Enter не выбирает первую подсказку: запись выбирается стрелками или мышью, иначе значением остаётся набранный текст.
- Очистка поля отдаёт `null`. Ограничения варианта, включая перечень значений строки, проверяются так же, как у поля его вида.

Рядом с выбранной ссылкой стоит кнопка перехода к записи. Объекты без права чтения подсказок не дают, а ссылка на запись такого объекта показана текстом «Нет доступа».

#### Выбор типа (`solid`)

Пользователь сначала выбирает тип значения, затем вводит его в поле этого вида: число, сумму, дату, флажок или ссылку на конкретный объект. Смена типа очищает значение. Так вводится поле, у которого есть вариант с собственным элементом ввода, и любое поле, которому текстовый ввод отключён.

#### Как отключить текстовый ввод

Текстовый ввод отключается в двух местах: в конфигурации вызовом `.inputMode('solid')` у составного поля и на экране свойством `inputMode="solid"` поля ввода, например `<FieldInput field={field} inputMode="solid" />`. Включить его свойством нельзя: возможность определяет платформа по вариантам.

#### Контракт компонента

Компоненты обоих способов принимают одни свойства `CompositeInputProperties` и зарегистрированы в `compositeInputs` (`src/web/widgets/registry.tsx`). Тип `CompositeInputModes` требует компонент на каждый способ: способ выбирает описание поля, поэтому виджет без одного из них оставил бы часть полей без ввода. Собственный компонент конфигурации, который заменяет ввод составного поля, получает способ в `field.inputMode` и обязан поддержать оба; проще всего передать значение в `FieldInput` или взять компонент из `compositeInputs`.

#### Запрос подсказок

Какие записи предлагать и каким запросом их читать, задаёт один хук `useRecordSuggestions` (`src/web/references/record-suggestions.ts`). Им пользуются поле ссылки и составное поле; компонент передаёт только объекты и введённый текст.

- Подсказки всех объектов читаются одним запросом к `/api/perform`: пакетом действий `list`, по одному на объект. У поля ссылки объект один, у составного поля их столько, сколько ссылочных вариантов доступно пользователю.
- Помеченные на удаление записи не предлагаются. Порядок задаёт сортировка объекта по умолчанию, текст ищется в представлении записи параметром `presentation`, от каждого объекта берутся первые 20 записей.
- Запрос уходит через 300 мс после последнего изменения текста и только пока список открыт. При каждом открытии подсказки читаются заново.
- Пакет выполняется целиком, поэтому в него входят только объекты, которые пользователь вправе читать.

### Подсказки и вычисляемые поля

Числовое поле с `suggestions` использует ввод с подсказками вместо обычного числового виджета. При открытом выборе читаются первые 50 подходящих записей справочника; поиск учитывает представление и числовые значения. Подсказка показывает название и число. Выбор сохраняет только число, которое остаётся редактируемым. Помеченные записи и пустые значения источника исключаются.

Вычисляемые поля показывают текущий результат только для чтения. Поставщик данных формы пересчитывает строки, затем шапку по общим с сервером формулам. Поэтому изменение ячейки, добавление строки через элемент конфигурации и удаление строки сразу меняют итог. Сервер повторяет расчёт перед проверкой и сохранением.

## Ссылки

Поле вида `reference` хранит `guid` записи другого объекта. Пользователю `guid` ничего не говорит, поэтому вместо него всегда выводится представление записи: текст, по которому человек её узнаёт. У записи справочника это наименование, у документа: «<заголовок объекта> № <номер> от <дата>». Общий модуль представлений (`src/server/ui/reference-presentation.ts`) используется сервером и клиентом, поэтому в поле ссылки, в ячейке списка, в колонке регистратора и в заголовке формы запись называется одинаково. Список получает готовые представления со своей страницей, а вне списка клиент читает записи по ссылкам.

Справочник может объявить представление по ссылке: `.presentation('<поле>')`. Тогда его запись везде показывается представлением записи, на которую ссылается это поле: в ячейке списка, в поле выбора, в ссылке на форму, в колонке табличной части, в заголовке формы и вкладки. Наименование у такого справочника остаётся обычным обязательным полем.

- Представление берётся по ссылке при каждом показе и в наименование не копируется. Копия устаревала бы при изменении целевой записи, в том числе импортом из 1С.
- Поле представления по ссылке должно быть обязательной ссылкой с заданной целью. Представление также может состоять из текста, полей шапки и значений колонок частей (раздел [«Представление из частей»](metadata.md#представление-из-частей)). Циклы ссылок с заданными целями отклоняет сборка метаданных.
- Сервер читает целевые записи пакетом вместе со страницей списка: сначала записи, на которые ссылаются колонки, затем одним запросом на целевой объект записи, по которым они называются. Число запросов зависит от числа объектов, а не строк.
- Вне списка клиент читает запись по ссылке и использует готовое служебное поле `$presentation` ответа `get`. Целевые записи и используемые колонки частей читает сервер пакетами. Заголовок формы и вкладки, ссылки и поля выбора используют этот же текст; представление не хранится в отдельной колонке.
- Вне списка клиенту нужны записи по списку `guid`. Чтения, начатые за один проход отрисовки, уходят на сервер одним пакетом действий `get`, общим для всех объектов страницы. Это делает метод `getMany` data provider. В ячейках списка отдельное чтение не выполняется: представления страницы имеют приоритет перед кешем записей.
- Прочитанная запись хранится в общем кеше запросов и в течение минуты повторно не запрашивается. Изменение записи самим пользователем сбрасывает сохранённые ответы раньше.
- Пакет выполняется целиком или не выполняется вовсе. Для ссылок это допустимо: записи физически не удаляются, поэтому чтение по сохранённой ссылке всегда находит запись, а объекты без права чтения клиент не запрашивает.
- Поле ввода ссылки представляет собой выпадающий список с поиском по представлению записи (параметр `presentation` действия `list`), включая части составного представления. Предлагаются первые 20 записей в порядке сортировки объекта по умолчанию; помеченные на удаление не предлагаются. Запрос уходит, только когда список открыт. Правила заданы общим [хуком подсказок](#запрос-подсказок).
- Уже сделанная ссылка на помеченную запись остаётся в силе: поле показывает её представление, хотя выбрать её заново нельзя.
Если целевого объекта нет в описаниях, у пользователя нет права его читать. Записи не запрашиваются, вместо представления написано «Нет доступа», а выбрать другую запись нельзя. Сервер не отдаёт представление недоступных записей, и поиск их не находит.

## Списки

Страница `/<вид>/<имя>` показывает стандартный список по серверному описанию, если конфигурация не заменила его [формой объекта](#выбор-формы-и-место-показа). Новый объект конфигурации получает список без изменений клиента. Хук SDK читает страницу, а поиск, отбор и таблица управляют её состоянием.

### Поиск, отбор и сортировка

Над списком есть поле «Поиск» с очисткой, отдельно от условий отбора. Поиск ищет фрагмент в любой видимой колонке и действует вместе с отбором. Введённый текст применяется через 300 мс после последнего изменения; очистка убирает только поиск без задержки. Изменение поиска возвращает список на первую страницу, сохраняя отборы и сортировку. Число строк и страницы относятся к найденному набору.

Пользователь составляет отбор из условий: поле из `filters`, способ сравнения из `operators` и значение. Ввод использует реестр виджетов; условия соединяются через «и», условие без значения не применяется. Колонки берутся из `columns`, при открытии действует `defaultSort`. Щелчок по заголовку колонки из `sortable` заменяет сортировку, повторный щелчок меняет направление. Под таблицей выбираются страница и её размер: 20, 50 или 100 записей, по умолчанию 50.

Сортировка, отбор, поиск и номер страницы хранятся в адресе вкладки: его можно сохранить в закладки и восстановить после перезагрузки. Пока вкладка открыта, её состояние сохраняется при переключении. Refine не хранит поиск отдельно, поэтому SDK записывает его условием `$search`, а data provider передаёт серверу параметром `search`. Значения отбора после разбора адреса приводятся к виду поля по описанию списка: строка запроса сама не различает типы. Значение составного поля лежит в адресе вместе с типом варианта, и по нему восстанавливается тип самого значения: число 100 не превращается в строку «100».

### Открытие записи и действия строки

Помеченная на удаление запись остаётся в списке: в первой колонке стоит значок пометки, текст строки бледнее обычного. Проведённый документ отмечается значком проведения.

Двойной щелчок по строке или ссылка в первой колонке открывает форму записи. Если первая колонка сама содержит ссылку, она открывает целевую запись; двойной щелчок открывает владельца строки. Кнопка «Создать» доступна при наличии `save` в описании формы, если её не скрыл компонент клиентской группы. Она открывает новую запись в режиме из конфигурации: вкладка или окно поверх списка. Созданная в окне запись появляется в списке без изменения адреса и набора вкладок. Меню строки ставит или снимает пометку удаления при наличии соответствующего действия.

Списки обоих видов регистров доступны только для просмотра: кнопки создания, меню строк и формы регистра нет. У движений представление регистратора открывает форму документа; у сведений показаны измерения и ресурсы.

### Просмотр табличных частей

Если объект объявил части для списка, строка раскрывает таблицы только для чтения. Просмотр монтируется при раскрытии и запрашивает запись через `get`; закрытые строки дополнительных запросов не отправляют, а `list` не возвращает массивы частей. Колонки, используемые для составного представления, сервер читает отдельно без включения массивов в ответ. Переключатель «Раскрыть строки страницы» раскрывает все записи текущей страницы. Параметр `expandTableParts=true` сохраняется вместе с состоянием списка и восстанавливается после перезагрузки.

### Ограничения кнопок от компонентов конфигурации

Над поиском и отбором выводится клиентская группа списка. Её компонент вызывает `useListControls({ hideCreate: true, hiddenRowActions: ['markDeleted', 'unmarkDeleted'] })`, чтобы скрыть создание и действия пометки удаления. Настройки принадлежат экземпляру списка: соседние вкладки на них не влияют. Ограничения нескольких компонентов объединяются; при изменении настроек или удалении компонента снимаются только его ограничения. Вне стандартного списка хук ничего не меняет, поэтому компонент можно поставить и на главный экран.

Ограничения касаются показа кнопок. Права сервера, `useOpenRecord` и адрес `/<вид>/<имя>/new` продолжают работать. Собственная таблица передаёт `hiddenRowActions` непосредственно в `RecordTable`; вложенные таблицы ограничений стандартного списка автоматически не получают.

## Формы

У записи есть собственный адрес: `/<вид>/<имя>/new` открывает форму новой записи, `/<вид>/<имя>/<guid>` открывает форму существующей (`src/web/forms/`). Какую форму показать, собственную или стандартную, выбирает [модуль выбора форм](#выбор-формы-и-место-показа). По адресу форма открывается в отдельной вкладке: на запись ведут ссылки из списков, из строк регистров и из других форм. Ту же форму команда открытия записи SDK показывает в модальном окне поверх страницы; так создаётся запись объекта, у которого в конфигурации задан режим создания в окне (подразделы [«Переопределение формы»](#переопределение-формы) и [«Вкладки открытых окон»](#вкладки-открытых-окон)). У обоих видов регистров формы нет, и их адреса форм показывают страницу «не найдено». Если сервер запись не отдал, на месте формы показывается его сообщение и кнопка возврата в список.

Страница вкладки только разбирает адрес. Чтение существующей записи с признаком ожидания и сообщением об отказе сервера вынесено в отдельный компонент, который от адреса не зависит: что предложить пользователю при отказе, ему передаёт вызывающий код. Поэтому форму существующей записи показывает и модальное окно: при отказе оно предлагает закрыться.

### Выбор формы и место показа

Конфигурация может заменить [формой объекта](metadata.md#формы-объекта) список, форму существующей записи и форму новой записи. Модуль выбора форм (`src/web/forms/object-forms.tsx`) решает, какую из них показать:

| Экран | Что показывается | Свойства формы |
|---|---|---|
| Список `/<вид>/<имя>` | Собственный список или стандартный `ObjectList` | `{ object }`; список показывается только во вкладке |
| Запись `/<вид>/<имя>/<guid>` | Собственная форма записи или `StandardRecordForm` | `object`, `view`, `record`, `reload`, `presentation` |
| Новая запись `/<вид>/<имя>/new` или окно создания | Собственная форма новой записи или `StandardRecordForm` | `object`, `view`, `presentation` |

Форма новой записи отличается от формы записи отсутствием записи при открытии. Каждый вид выбирается отдельно: собственная форма записи не заменяет форму новой записи, и наоборот. Объект без объявления остаётся со стандартной формой.

Место показа форма получает свойством `presentation`: `page` для вкладки с собственным адресом, `dialog` для модального окна. Модальность видом формы не является, форма сама решает, менять ли раскладку в окне. Где откроется новая запись, как и раньше, определяют `.form(...).creation(...)` и место вызова `useOpenRecord`. Место показа за время жизни формы не меняется.

#### Контракт с областью окна

Форме записи и форме новой записи нужно сообщать области окна о несохранённых изменениях, о записанной и созданной записи, а область после действия может закрыться. Добровольные вызовы такого рода форма легко забыла бы, поэтому контракт принудительный:

- Форма вызывает `useRecordFormContract` (напрямую или через `useRecordForm`) и передаёт обязательные обработчики `changed`, `save`, `perform` и `show`. Пропущенный обработчик не проходит проверку типов.
- Хук сам записывает несохранённые изменения перед действием, сообщает области о записанной и созданной записи, закрывает область после действия с признаком `close` и регистрирует проверку несохранённых изменений для подтверждения при закрытии.
- Сочетания клавиш форма обрабатывает сама: `useRecordForm` подключает Ctrl+S, Ctrl+Enter и Esc, а `useRecordFormContract` их не подключает.

Область окна ставит вокруг формы контекст и после её монтирования проверяет, что контракт подключён ровно один раз. Если форма не подключила контракт или подключила его дважды, вместо формы показывается ошибка «Форма «<заголовок объекта>» не может быть показана» с причиной: форма без контракта молча не сообщала бы области о записи, а двойное подключение сообщило бы о ней дважды. Хук, обработчики и параметры описаны в разделе [«Хуки»](web-sdk/hooks.md#контракт-формы-записи), готовые части формы в разделе [«Компоненты»](web-sdk/components.md#стандартная-форма-и-её-части).

### Значения и раскладка

Стандартная форма `StandardRecordForm` лежит в SDK и собрана из хука `useRecordForm` и частей раскладки ([«Компоненты»](web-sdk/components.md#стандартная-форма-и-её-части)). Значения и ошибки полей хранит форма Ant Design, а загрузку, запись и действия выполняют хуки данных SDK. Отдельно форма помнит записанное состояние: запись в том виде, в каком её последним вернул сервер. По нему выводятся заголовок, отметки «Помечен на удаление» и «Проведён» и поля только для чтения, к нему применяются действия.

Группы выводятся в порядке описания: группа с заголовком блоком с заголовком, группа без заголовка без рамки. Табличная часть занимает всю ширину формы.

На форме новой записи служебные поля не выводятся: только для чтения и не вычисляемые, например номер документа и «Проведён». Их значение назначает запись. Группа, в которой не осталось элементов, не выводится.

Собственный элемент конфигурации в группе занимает всю её ширину и свойств не получает. Элемент, назначенный полю, стоит на месте поля ввода: значение и обработчик изменения ему передаёт элемент формы Ant Design, как и виджету, поэтому подпись, ошибку проверки и отметку «Сервер отклонил значение» показывает форма. Значения и записанное состояние элементы читают из данных формы SDK, а изменение значения элементом форма считает несохранённым так же, как ввод пользователя. На форме только для просмотра поля ввода и кнопки Ant Design внутри элемента недоступны: недоступность им передаёт форма.

В новой записи обязательный флажок снят, обязательное поле `dateTime` равно текущему моменту. Поле `date` остаётся пустым. Дата нового документа имеет вид `dateTime` и заполняется автоматически. Строка с начальным значением из описания получает его; так же заполняется новая строка табличной части. Остальные поля пусты, в том числе поля только для чтения: номер документа сервер назначает при записи.

### Доступность и ограничения

Форма без действия `save` в описании открывается только для просмотра.

Состоянием формы может управлять собственный элемент конфигурации (подраздел [«Элементы формы»](metadata.md#элементы-формы)): он объявляет ограничения, а форма применяет их объединение. Форма, недоступная целиком, выглядит как форма только для просмотра: поля и табличные части не редактируются, действие «Записать» скрыто само, обход с клавиатуры отключён, а остальные элементы узнают о недоступности по признаку «только просмотр» данных формы. Отдельное недоступное поле или табличная часть не редактируется и не входит в обход, остальные части формы работают как обычно. Значение недоступного поля остаётся в значениях формы и уходит в `save`, поэтому запись его не обнуляет.

Скрытое действие не выводится кнопкой, а его сочетание клавиш запрос не отправляет: кнопки и сочетания проверяют видимость действия одной функцией.

Пока элементы не сообщили ограничения, форма недоступна целиком и показывает только кнопку «Закрыть». Фокус в первое поле новой записи ставится после того, как ограничения собраны.

### Проверка и сохранение

До отправки форма проверяет значения по правилам из описания. Сообщение показывается под полем, а в табличной части у ячейки; пока есть ошибки, запрос не отправляется. Если сервер ответил 400, поля из его перечня `fields` отмечаются ошибкой «Сервер отклонил значение», а текст сервера показывается уведомлением: отдельного текста на каждое поле сервер не присылает. Ответы 403 и 409 показываются уведомлением с текстом сервера. При любой ошибке введённые значения остаются на форме.

Для части с заменой форма дополнительно проверяет все строки по описаниям колонок, даже когда таблица не смонтирована. Ошибка серверной проверки отмечает исходный путь ячейки; если ячейка не выведена, сообщение показывается также у части.\n\nЗначение ячейки табличной части лежит в форме по пути «табличная часть, номер строки, поле». Сервер называет поле с ошибкой таким же путём (`payload.fields.lines.0.text`), поэтому его ошибки сопоставляются с полями напрямую.

Действие `save` заменяет запись целиком, а на форме есть не все её поля: переопределение `.hide(...)` убирает поле из описания формы. Поэтому в `save` отправляется загруженная запись, в которой значения полей формы заменены введёнными. Иначе запись обнулила бы скрытые поля. Поля, которые заполняет платформа, сервер во входных данных пропускает.

### Действия и результат записи

Кнопки действий строятся из `actions` описания, поэтому действие без права на форме не появляется. Из пары «Пометить на удаление» и «Снять пометку удаления» показывается применимое, «Отменить проведение» показывается только у проведённого документа. В форме новой записи доступны запись и проведение.

Если проведение доступно, главной кнопкой служит «Провести и закрыть» (Ctrl+Enter). Она записывает изменения, проводит документ и закрывает область окна только после успеха. Рядом расположены кнопки-иконки «Провести» и «Записать»: первая проводит без закрытия, вторая только записывает (Ctrl+S). У каждой есть название для чтения с экрана и подсказка. Во вкладке кнопки стоят над формой, в модальном окне те же кнопки находятся внизу. Если проведение недоступно по правам или скрыто элементом формы, «Записать» остаётся главной кнопкой с подписью; так же выглядит форма справочника.

Элемент состояния закрытой рассрочки делает форму недоступной для изменения и скрывает проведение и его отмену. На такой форме нет ни одной из трёх кнопок записи и проведения; соответствующие сочетания клавиш действия не запускают.

Все действия, кроме «Записать», применяются к записанному состоянию. При несохранённых изменениях форма сначала записывает их и только затем выполняет действие, двумя последовательными запросами: у новой записи до ответа на запись нет `guid`, который нужен действию. Если действие после успешной записи отклонено, запись остаётся сохранённой, форма показывает причину и не закрывается. После исправления значений повторное нажатие «Провести и закрыть» записывает изменения и повторяет проведение.

После каждого изменения записи на сервере области окна сообщается её `guid`, а после создания записи об этом сообщается отдельно. Сообщает хук контракта формы (`useRecordFormContract`), а не код формы ([«Выбор формы и место показа»](#выбор-формы-и-место-показа)). Что делать дальше, решает область. Вкладка формы новой записи получает адрес существующей записи, форма остаётся открытой, и повторное открытие этой записи находит ту же вкладку. Модальное окно после создания записи закрывается. В истории браузера адрес новой записи заменяется, поэтому кнопка «Назад» к пустой форме не возвращает. Форма новой записи у объекта одна: кнопка «Создать» при уже открытой новой форме возвращает к ней.

Собственное действие доступно для записанной записи. Если у него есть входные данные, кнопка действия открывает окно с полями из того же реестра виджетов. Поля окна заполняются так же, как поля новой записи: обязательное поле `dateTime` равно текущему моменту, а поле `date` остаётся пустым. После выполнения запись читается с сервера заново: действие могло её изменить.

После любого изменяющего действия сохранённые ответы сервера о данных помечаются устаревшими: открытые списки и ссылки перечитываются сразу, остальные при следующем открытии. Сбрасываются ответы обо всех объектах, потому что проведение меняет строки регистров, а собственное действие может изменить любые записи.

### Несохранённые изменения

Переключение вкладок данные формы не теряет, поэтому подтверждение спрашивается только при закрытии вкладки формы с несохранёнными изменениями: крестиком, кнопкой «Закрыть» или клавишей Esc. Отказ оставляет вкладку открытой. Выход из приложения закрывает все вкладки и спрашивает подтверждение, если несохранённые изменения есть хотя бы на одной. При закрытии вкладки или окна браузера подтверждение показывает сам браузер; оно тоже учитывает все вкладки приложения, потому что изменения могут быть на скрытой форме.

### Просмотр частей и ввод данных действия

Табличная часть сделана отдельным компонентом, который получает только её описание и не зависит от остальной формы. Форма знает свои поля ввода и табличные части по именам и может перевести фокус на любое имя из порядка обхода `traversal`.

В колонке-ссылке с `expandedTablePart` строка раскрывает часть целевой записи компонентом SDK `RecordTablePart`. Этот же компонент работает в списке и в элементе конфигурации; `onRowClick` передаёт прочитанную строку вызывающему экрану. Сам просмотр запись не меняет. Например, элемент формы может добавить выбранную строку в текущую часть через `useFormData`.

Входные табличные части собственного действия выводятся в его окне тем же компонентом `TablePart`, с теми же проверками ячеек, вычислениями и обходом Enter. Серверный путь ошибки начинается с `payload.lines.0.field`, без промежуточного `fields`. Экран может передать входные строки через `ActionButton.input` или `useAction`, тогда окно не открывается.

## Работа с клавиатуры

Форма обходит редактируемые поля по порядку `traversal` из описания: Enter переводит фокус вперёд, Shift+Enter назад. Поля только для чтения и поля, которые элемент формы сделал недоступными для изменения, в обход не входят. На границе шапки обратный обход останавливается в первом поле.

Собственный элемент, назначенный полю, участвует в обходе на месте этого поля и получает фокус в новой записи, если поле первое в порядке: для этого он принимает фокус по контракту поля ввода. Кнопка внутри элемента по Enter срабатывает сама, как и остальные кнопки формы. Собственный элемент в группе без назначенного поля в порядок обхода не входит: контракта поля ввода он соблюдать не обязан.

При переходе в пустую табличную часть форма добавляет первую строку и ставит фокус в её первую ячейку. Внутри строки обход идёт по колонкам описания. После последней ячейки Enter переходит в первую ячейку следующей строки, а если её ещё нет, добавляет строку. Shift+Enter из первой ячейки возвращает в последнюю ячейку предыдущей строки, а из первой строки в предыдущее поле формы. Ссылки на поля ячеек учитываются по устойчивым ключам строк, поэтому удаление строки не меняет адреса полей остальных строк.

Открытый список выбора или календарь обрабатывает Enter и Esc сам: Enter выбирает значение, Esc закрывает выбор. Следующее нажатие работает с формой. Во время составного ввода текста переходы не выполняются.

Сочетания TanStack Hotkeys действуют на форме активной вкладки: Ctrl+S записывает её, Ctrl+Enter проводит документ и закрывает вкладку только после успеха, Esc закрывает вкладку с обычным подтверждением при несохранённых изменениях. В форме, показанной в модальном окне, сочетания действуют так же и закрывают окно, а в формах под окном не действуют. Esc, которую обработала форма, до обработчика Ant Design не доходит: иначе то же нажатие закрыло бы только что открытое окно подтверждения. Сочетания вызывают те же действия, что кнопки, и доступны только при наличии действия в описании формы. Поэтому пользователь без права записи не может записать форму сочетанием клавиш. Окна подтверждения и входных данных собственных действий получают клавиши сами; действия записи за ними не запускаются. Повторное нажатие во время запроса не запускает второе действие.

Обход полей и учёт фокуса входят в SDK (`useFieldTraversal`), поэтому собственный экран с формой получает тот же обход; значения хранятся в форме Ant Design, серверные данные в TanStack Query. Табличная часть использует таблицу Ant Design с собственным обходом ячеек, без замены остальных частей формы.
